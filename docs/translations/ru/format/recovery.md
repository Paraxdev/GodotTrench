# Повреждённые файлы { #damaged-files }

Повреждённая бинарная карта теряет только повреждённые чанки, всё остальное по-прежнему открывается. Если вы пишете
читатель формата, эта страница описывает, что он должен делать, чтобы вести себя так же.

Читатель проходит по [чанкам](container.md#chunks), начиная с байта 12. Корректный заголовок чанка содержит маркер
синхронизации, совпадающую проверку заголовка, исходный размер не более 1 GiB и печатаемый тег. Если корректного заголовка
нет, читатель ищет вперёд следующий маркер синхронизации и продолжает с него.

Чанк `HEAD`, `NODE` или `END` отбрасывается, если его данные не распаковываются, не сходятся по контрольной сумме, имеют
неверный размер или не декодируются.

| Повреждение | Результат |
| --- | --- |
| Чанк `NODE` | Узлы, хранившиеся в нём, теряются |
| Потерян родитель узла | Узел вместе со всем, что под ним, переносится в слой с именем `Recovered` в конце карты. При загрузке слой получает новый идентификатор |
| Вложенность глубже 60 уровней | Тоже переносится в `Recovered`, чтобы чтение не исчерпало стек. Такое бывает только в специально созданном файле |
| Чанк `HEAD` | Свойства worldspawn и состояние редактора теряются, а версия карты берётся из `END` |
| И `HEAD`, и `END` | Файл отклоняется |
| Нет чанка `END` | Файл обрезан. Загружается всё до последнего полного чанка |
| Счётчики в `END` больше прочитанного | Сообщается как число отсутствующих узлов или чанков |

Каждый читатель сообщает о каждой потере:

| Читатель | Сообщение |
| --- | --- |
| Редактор | Открывает то, что смог прочитать, перечисляет потери в строке состояния и помечает карту как несохранённую. О повреждённых префабах тоже сообщает строка состояния |
| Аддон Godot | Собирает то, что смог прочитать, и печатает предупреждение о каждой потере с префиксом `[TDM]` и путём к файлу |
| `trenchdot --dump` | Печатает то, что смог прочитать, а потери пишет в stderr |

Перед каждым сохранением редактор копирует старый файл в `<map>.tdm.bak`, поэтому после сохранения восстановленной карты
повреждённый оригинал остаётся рядом. Новый файл сначала записывается в `<map>.tdm.tmp`, а затем переименовывается поверх
карты, так что сбой посреди сохранения никогда не оставит наполовину записанную карту.
