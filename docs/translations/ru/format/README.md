# Формат карт .tdm { #the-tdm-map-format }

Эти страницы для вас, если вы пишете инструмент, который читает или записывает файлы `.tdm`, например импортёр,
конвертер или проверку в CI. Для создания уровней всё это знать не нужно.

Файл `.tdm` хранит три вещи: свойства worldspawn, немного состояния редактора и дерево узлов с самим содержимым.

Редактор сохраняет его как бинарный контейнер из чанков, сжатых zstd, поэтому файлы получаются небольшими, а
повреждённый файл всё равно открывается. Старые редакторы сохраняли вместо этого один документ JSON в UTF-8, и каждый
читатель загружает обе формы. В обеих формах хранится одно и то же дерево, поэтому на этих страницах оно показано в виде
JSON, который печатает `trenchdot --dump`.

| Страница | Читайте её, когда вы |
| --- | --- |
| [Устройство контейнера](container.md) | Разбираете или записываете бинарный файл. Здесь заголовок файла, чанки и то, как каждое значение кодируется в байты |
| [Повреждённые файлы](recovery.md) | Хотите знать, что ещё загружается из испорченного файла и где каждый читатель сообщает о потерях |
| [Узлы](nodes.md) | Обходите дерево. Здесь общая форма каждого узла, как работают идентификаторы и узлы слоёв, групп, сущностей и экземпляров |
| [Геометрия](geometry.md) | Читаете или создаёте браши и меши, включая их грани, проекцию текстур и дисплейсменты |
| [Ландшафт и разброс](terrain-scatter.md) | Работаете с ландшафтами по карте высот и наборами разбросанных моделей |
| [Формат JSON](json.md) | Работаете с читаемой формой, преобразуете одну форму в другую или читаете то, что редактор кладёт в буфер обмена |

Хотите увидеть работающий код? Эталонная реализация находится в
[`format.rs`](https://github.com/Paraxdev/TrenchDot/blob/main/crates/td_doc/src/format.rs), контейнер в
[`binary.rs`](https://github.com/Paraxdev/TrenchDot/blob/main/crates/td_doc/src/binary.rs) и
[`variant.rs`](https://github.com/Paraxdev/TrenchDot/blob/main/crates/td_doc/src/variant.rs). Со стороны Godot файл
читает [`tdm_file.gd`](https://github.com/Paraxdev/trenchdot_func/blob/main/src/trenchdot/tdm_file.gd), а строит карту
[`tdm_parser.gd`](https://github.com/Paraxdev/trenchdot_func/blob/main/src/trenchdot/tdm_parser.gd).

## Верхний уровень { #top-level }

| Ключ | Тип | Когда записывается | Значение |
| --- | --- | --- | --- |
| `format` | строка | всегда | Всегда `"trenchdot-map"`. По нему карта отличается от другого JSON |
| `version` | целое число | всегда | Версия карты, сейчас 1 |
| `properties` | объект из строки в строку | если не пуст | Ключи worldspawn, отсортированные по имени |
| `editor` | объект | если не всё по умолчанию | Состояние вида в редакторе. В Godot никогда не экспортируется |
| `textures` | объект | если у какой-то текстуры есть настройки | [Настройки текстур](geometry.md#texture-settings) по имени материала |
| `layers` | массив узлов | всегда | [Узлы слоёв](nodes.md#layer) карты по порядку. Всё остальное подвешено под ними |
| `lightmap` | объект | карты JSON с запеканием | Запечённое освещение, которое бинарная карта хранит в [чанке LMAP](container.md#lmap) |

Из `layers` читаются только узлы `layer`, а карта без них при загрузке получает слой `Default`.

Значения worldspawn всегда строки, как в файле `.map`. Когда Godot строит карту, `TrenchDotEnvironment` превращает эти
ключи в небо, туман и солнце:

| Ключи | Что они задают |
| --- | --- |
| `sun_angles`, `sun_color`, `sun_energy` | Направленный солнечный свет: куда он направлен, его цвет и яркость |
| `ambient_color`, `ambient_energy` | Свет, который доходит до поверхностей, куда не попадает солнце, чтобы тени не были абсолютно чёрными |
| `sky_top_color`, `sky_horizon_color`, `sky_ground_color`, `sky_energy` | Градиент процедурного неба и его яркость |
| `sky_panorama` | Изображение `res://`, которое заменяет процедурное небо в Godot. Предпросмотр в редакторе и запекание продолжают использовать цвета неба |
| `fog_color`, `fog_density` | Туман на расстоянии |
| `glow_intensity`, `ssr` | Блум на ярких поверхностях и отражения в экранном пространстве, когда `ssr` равно `1` |

Если ваша игра приносит собственный `WorldEnvironment`, задайте `environment` равным `sun_only`, и будет построено только
солнце. `0` или `none` не строит ничего, см. [окружение и солнце](../godot/building.md#environment-and-sun).
`sky_source` запоминает, какая текстура была у граней неба импортированной карты.

Объект `editor` это состояние вида, важное только внутри редактора:

| Ключ | Тип | По умолчанию | Значение |
| --- | --- | --- | --- |
| `cameras` | объект, ключи от `"1"` до `"9"` | пусто | Сохранённые положения камеры, каждое `{"position": [x, y, z], "yaw": r, "pitch": r}` с углами в радианах |
| `cordon` | `{"min": [x, y, z], "max": [x, y, z]}` | нет | Коробка кордона в единицах карты, для работы над одной частью большой карты |
| `cordon_enabled` | bool | `false` | Скрывать объекты вне кордона и не включать их в экспорт с кордоном |
| `bake` | `{"quality", "texel_size", "softness", "backend"}` | нет | Параметры, с которыми карта [запекалась](../editor/light-baking.md) в последний раз, чтобы следующее запекание начиналось с них |
| `graph_frames` | массив | пусто | Рамки [графа логики](../gameplay/logic-graph.md#frames), каждая `{"title", "rect": [x, y, width, height], "color"}` в точках графа. Повреждённая рамка при загрузке отбрасывается |

## Версии и совместимость { #versions-and-compatibility }

`format` и `version` описывают данные. Версия контейнера в заголовке файла отдельная, она меняется только тогда, когда
меняется расположение чанков.

Вот что делает каждый читатель с файлом, который понимает не полностью:

| Ситуация | Редактор | Аддон Godot |
| --- | --- | --- |
| Другой `format` | Отклоняет файл | Ошибка сборки |
| Более новая `version` | Отклоняет файл | Ошибка сборки с просьбой обновить аддон |
| Нет `version` | Читает как самую старую версию | То же |
| Неизвестный ключ | Игнорирует, а после следующего сохранения он пропадает | Игнорирует |
| Неизвестный чанк | Сохраняет и записывает обратно при сохранении | Пропускает |
| Индекс грани вне диапазона | Отклоняет карту, называя узел | Пропускает этот браш |
| `heights` дисплейсмента неверного размера | Отклоняет карту, называя узел | Строит грань плоской |

Редактор отбрасывает неизвестные ключи при сохранении. Поэтому, если вы добавляете данные, которые старый редактор не
должен потерять, нужно либо поднять версию карты, и тогда старые редакторы откажутся её открывать, либо завести для них
отдельный чанк, который они сохранят нетронутым. См. [Другие чанки](container.md#other-chunks).

## Координаты и единицы { #coordinates-and-units }

Позиции используют оси Godot: Y вверх, X вправо, Z к зрителю. При сборке значения делятся на `inverse_scale_factor` из
настроек карты, по умолчанию 32, поэтому 32 единицы карты составляют один метр.

| Величина | Единица |
| --- | --- |
| Позиции, размеры, высоты, шаг, размер ячейки | Единицы карты |
| Углы сущностей, экземпляров и разброса | Градусы: тангаж вокруг X, рыскание вокруг Y, крен вокруг Z, применяются в порядке YXZ, как `rotation_degrees` в Godot |
| Рыскание и тангаж закладки камеры | Радианы |
| Смещение UV | Тексели |
| Масштаб UV | Единицы карты на тексел |
| `uvs` меша | Ширины текстуры, так что 1 это одно полное повторение текстуры |
