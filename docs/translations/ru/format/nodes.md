# Узлы { #nodes }

Содержимое карты это дерево узлов. У каждого узла одна и та же внешняя форма, ключи идут в таком порядке:

| Ключ | Тип | Когда записывается | Значение |
| --- | --- | --- | --- |
| `id` | целое число | всегда | Уникален в пределах карты |
| `type` | строка | всегда | `layer`, `group`, `entity`, `brush`, `mesh`, `terrain`, `scatter` или `instance` |
| поля типа | | | Ключи этого типа узла, см. ниже, [Геометрию](geometry.md) и [Ландшафт и разброс](terrain-scatter.md) |
| `label` | строка | если задан | Имя, данное через *Переименовать*, см. ниже |
| `graph` | массив из 2 чисел | если задан | Где узел сущности стоит в [графе логики](../gameplay/logic-graph.md) |
| `hidden` | bool | когда `true` | Скрыт в редакторе |
| `locked` | bool | когда `true` | Нельзя выделить или править в редакторе |
| `children` | массив узлов | если не пуст | Дочерние узлы по порядку |

`hidden` и `locked` это только состояние редактора, поэтому Godot всё равно строит скрытый узел. Чтобы исключить что-то
из сборки, поместите это в слой с `omit_from_export`.

`label` это имя, которое вы дали брашу, мешу, сущности, экземпляру или ландшафту в редакторе, оно показывается вместо
имени по умолчанию вроде `brush12`. У слоёв, групп и наборов разброса его никогда нет, они хранят своё имя в `name`.

Godot использует `label` только для ландшафтов, он называет узел `terrain_<id>_<label>`. Браши и меши сливаются со своей
сущностью, а сущность берёт имя узла из `targetname`. Редакторы, более старые, чем этот ключ, всё равно читают файлы с
ним, но при сохранении его отбрасывают.

`graph` тоже состояние редактора. Это место узла сущности в графе логики, в точках графа, и он есть только у узлов,
которые кто-то передвинул. Godot его игнорирует, а значение, не являющееся двумя числами, при загрузке отбрасывается.

## Идентификаторы { #ids }

Идентификаторы это положительные целые числа, которые остаются теми же между сохранениями, чтобы другие данные могли
указывать на узел. Live link отправляет правки по идентификатору, наборы разброса называют свои поверхности по
идентификатору, а Godot хранит идентификатор каждого созданного узла в его метаданных `_td_id`. Идентификатор `0` или
дубликат, которые бывают только в файле, правленном вручную, при загрузке получает новый идентификатор.

Префаб это отдельный файл `.tdm` со своими идентификаторами, поэтому две его копии конфликтовали бы. Чтобы этого не
случилось, сборка Godot прибавляет к идентификатору каждого узла, который приносит [экземпляр](#instance), миллион,
умноженный на номер вхождения. Две копии одного префаба никогда не делят идентификаторы, как бы глубоко они ни были
вложены.

## Где размещаются узлы { #where-nodes-go }

| Узел | Допустимый родитель |
| --- | --- |
| Слой | Только верхний уровень |
| Группа | Слой или группа |
| Браш, меш, ландшафт, набор разброса, точечная сущность, экземпляр | Слой или группа |
| Браш или меш браш-сущности | Эта сущность |

Сущность с дочерними узлами это браш-сущность, например дверь из брашей. Браши и меши вне какой-либо сущности
принадлежат worldspawn.

## Слой { #layer }

Часть карты верхнего уровня, показывается в Структуре редактора.

| Ключ | Тип | По умолчанию | Значение |
| --- | --- | --- | --- |
| `name` | строка | обязателен | Имя, показываемое в Структуре |
| `color` | строка | обязателен | `#rrggbbaa`. При чтении принимается и `#rrggbb` |
| `omit_from_export` | bool | `false` | Записывается всегда. Когда true, сборка пропускает весь слой, для опорной геометрии, которая никогда не должна попадать в Godot |

## Группа { #group }

Узлы, собранные вместе, чтобы выделять и двигать их разом.

| Ключ | Тип | По умолчанию | Значение |
| --- | --- | --- | --- |
| `name` | строка | обязателен | Имя, показываемое в Структуре |
| `link_id` | целое число | опускается | Группы с общим идентификатором связи это связанные копии, созданные через *Дублировать со связью* |
| `transform` | 16 чисел | единичная, опускается | Размещение этой копии относительно остальных, матрица 4x4 в порядке по столбцам |

Содержимое группы хранится в мировом пространстве, уже на своём месте. [Связанная копия](../editor/organizing.md#groups)
повторяет правку, сделанную в одной копии, во всех остальных, а `transform` это лишь то, чем редактор переносит правку
от одной копии к следующей. Сборка Godot игнорирует и `transform`, и `link_id`.

## Сущность { #entity }

| Ключ | Тип | По умолчанию | Значение |
| --- | --- | --- | --- |
| `classname` | строка | обязателен | Класс сущности из конфигурации игры, например `prop_physics` |
| `origin` | `[x, y, z]` | `[0, 0, 0]` | Записывается всегда. Позиция точечной сущности |
| `angles` | `[pitch, yaw, roll]` | `[0, 0, 0]` | Записывается всегда. Градусы, порядок YXZ, как `rotation_degrees` |
| `properties` | объект из строки в строку | опускается | Ключи сущности, отсортированные по имени |
| `outputs` | массив | опускается | Соединения I/O, см. ниже |

Значения свойств всегда строки, каким бы ни был их тип в FGD, например `"travel": "0 168 0"`.

Свойство `angles`, `angle` или `mangle` главнее `angles` узла и читается как в Quake: тангаж и крен меняют знак,
рыскание поворачивается на 180 градусов. У классов, имена которых начинаются с `light`, `mangle` вместо этого задаёт
рыскание, тангаж и крен. `angle` равный -1 или -2 смотрит строго вверх или вниз. Редактор рисует сущность, повёрнутую
так же, а поворот её там переносит свойство в `angles` узла.

Сборка игнорирует `origin` и `angles` браш-сущности, так как её браши уже стоят там, где нужно.

Каждый выход это одно [соединение I/O](../gameplay/io.md): когда эта сущность подаёт сигнал, вызвать метод у цели.

| Ключ | Тип | По умолчанию | Значение |
| --- | --- | --- | --- |
| `output` | строка | обязателен | Сигнал этой сущности, запускающий соединение |
| `target` | строка | обязателен | Кто получает вызов, см. [Цели](../gameplay/parameters.md#targets) |
| `input` | строка | обязателен | Метод, вызываемый у цели |
| `parameter` | строка | `""`, опускается | Значение, передаваемое входу |
| `delay` | число | `0`, опускается | Сколько секунд ждать перед вызовом |
| `times` | целое число | `-1`, опускается | Сколько раз оно может сработать, `-1` значит каждый раз |

## Экземпляр { #instance }

Ссылка на другой файл `.tdm`, размещаемая с позицией и поворотом, как `func_instance` в Hammer. Так размещаются
префабы: содержимое лежит один раз в собственном файле, а каждый экземпляр его показывает.

| Ключ | Тип | По умолчанию | Значение |
| --- | --- | --- | --- |
| `path` | строка | обязателен | Указанная карта: относительно ссылающейся карты, абсолютный путь или `res://` |
| `origin` | `[x, y, z]` | обязателен | Где размещён экземпляр |
| `angles` | `[pitch, yaw, roll]` | обязателен | Градусы, порядок YXZ |
| `fixup` | строка | `""`, опускается | Префикс имён для содержимого экземпляра, см. ниже |

Сборка берёт потомков каждого слоя указанной карты, не исключённого из экспорта, и сдвигает их на `origin` и `angles`.
Проекции текстур двигаются вместе с геометрией. Worldspawn указанной карты не используется. Экземпляры вкладываются до
восьми уровней в глубину.

Сборка Godot читает каждую указанную карту один раз, и все экземпляры одной карты вместе могут добавить 2 097 152
значений, где значение это элемент массива или запись словаря указанной карты, а каждые 8 символов текста считаются
ещё за одно. Сверх этого сборка оставляет остальные экземпляры в стороне и сообщает об ошибке. Обычные карты остаются
намного ниже этого предела, достигают его только экземпляры экземпляров, умноженные многократно.

При fixup `p1` значение `door` становится `p1-door` в `targetname`, `target`, `destination`, `call_target`, в каждом
свойстве, которое FGD объявляет как `target_source` или `target_destination`, и в `target` каждого выхода. Значения,
начинающиеся с `!`, `@` или `/`, остаются нетронутыми. Вложенные fixup складываются снаружи внутрь, так что `b` внутри
`a` даёт `a-b-door`, и *Разобрать экземпляр* в редакторе даёт те же имена.
