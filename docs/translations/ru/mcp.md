# MCP-сервер { #mcp-server }

В редактор встроен сервер [MCP](https://modelcontextprotocol.io). Агент вроде Claude Code или обычный скрипт на Python
может с его помощью просматривать и править карты, делать скриншоты и подавать ввод в интерфейс.

Он пригодится, чтобы ИИ-ассистент построил или проверил уровень, чтобы автоматизировать повторяющиеся правки или
чтобы автоматически тестировать сам редактор. Пока вы его не запустите, сервер выключен, и слушает он только вашу
собственную машину.

## Запуск { #starting-it }

| Транспорт | Как запустить |
| --- | --- |
| HTTP | Запустите редактор с `--mcp-http` для порта 7841 или с `--mcp-http=PORT` для другого порта. Чтобы он стартовал каждый раз, откройте *Файл > Настройки*, перейдите в *Дополнительно*, поставьте галочку *включать при запуске* рядом с *Сервер MCP (HTTP, localhost)*, задайте порт рядом и перезапустите |
| stdio | Запустите с `--mcp`. Клиент сам запускает редактор для каждого сеанса и общается с ним через стандартный ввод и вывод |

Выбирайте HTTP, когда вы держите редактор открытым и работаете в нём сами, а агент помогает. Выбирайте stdio, когда
клиент должен владеть своим редактором или когда за этим компьютером работают другие люди. Чтобы подключить Claude Code
к любому из них:

```sh
claude mcp add --transport http trenchdot http://127.0.0.1:7841/mcp   # HTTP
claude mcp add trenchdot -- /path/to/trenchdot --mcp                 # stdio
```

`.mcp.json` в репозитории уже направляет Claude Code на HTTP-сервер. В *Файл > Настройки* показана команда для
запущенного сервера, а *Копировать команду* кладёт её в буфер обмена.

Запустили редактор на другом порту? Задайте `TRENCHDOT_MCP_URL`, и
[tools/mcp_client.py](https://github.com/Paraxdev/TrenchDot/blob/main/tools/mcp_client.py) и
[tools/mcp_script.py](https://github.com/Paraxdev/TrenchDot/blob/main/tools/mcp_script.py) будут подключаться туда.

### HTTP-токен { #the-http-token }

До HTTP-сервера может достучаться любая программа на вашем компьютере, а также другие люди, вошедшие в него. Чтобы их
не пускать, поставьте галочку *Требовать токен* в разделе *Дополнительно* в *Файл > Настройки*. Со следующего запроса
сервер отвечает только на те, что присылают его токен как `Authorization: Bearer <token>`. Тогда команда в настройках
включает токен, пользуйтесь ею вместо `.mcp.json`. Для stdio токен не нужен, говорить с ним может только клиент,
запустивший редактор.

Редактор создаёт случайный токен, когда вы просите его впервые, и хранит в `mcp-token`, файле, который читаете только
вы, рядом со своими настройками: `%APPDATA%\TrenchDot\data` в Windows, `~/.local/share/trenchdot` в Linux и
`~/Library/Application Support/TrenchDot` в macOS. Запуск с `--default-prefs` держит свой токен в
`trenchdot-default-prefs.mcp-token` во временной папке.

Чтобы выбрать токен самому на один запуск, задайте `TRENCHDOT_MCP_TOKEN` или запустите с `--mcp-token=<token>`, этот
параметр главнее переменной. Любой из них включает токен, что бы ни говорили настройки, и *Требовать токен* показывается
с галочкой и неактивным. `tools/mcp_client.py` и `tools/mcp_script.py` присылают токен, только если вы его им дадите,
через `--token` или `TRENCHDOT_MCP_TOKEN`.

## Отключение MCP { #turning-mcp-off }

Чтобы вообще не пускать агентов и скрипты в редактор, снимите галочку *MCP* в верхней части раздела MCP в
*Файл > Настройки*. HTTP-сервер сразу закрывается и разрывает открытые соединения, клиент по stdio получает ошибку на
каждый запрос, а остальные настройки MCP становятся неактивными. Настройка сохраняется сразу, поэтому каждый редактор,
который вы запустите без `--default-prefs`, остаётся с выключенным MCP, пока вы снова не поставите галочку, и тогда
HTTP-сервер возвращается на свой порт.

![Раздел MCP в настройках: MCP с галочкой, строка HTTP-сервера с портом и «Требовать токен»](assets/mcp/prefs-mcp.png)

Чтобы выключить MCP на один запуск, что бы ни говорили настройки, задайте `TRENCHDOT_DISABLE_MCP` любым значением,
кроме пустого и `0`. Тогда *MCP* показывается без галочки и неактивным. Пока MCP выключен, `--mcp` и `--mcp-http` не
запускают сервер. Редактор всё равно открывается, а его строка состояния сообщает, что MCP выключен, и клиент по stdio
получает ошибку с этим сообщением, а не ждёт.

Агент тоже может выключить MCP через `set_editor` с `"mcp": false`. Включить его обратно можете только вы.

## Инструменты { #tools }

| Область | Для чего | Инструменты |
| --- | --- | --- |
| Просмотр | Прочитать карту, состояние редактора, определения сущностей и способ использования сущности из кода игры, ничего не меняя | `get_state`, `summarize_map`, `list_nodes`, `get_node`, `changes_since`, `validate_map`, `get_game_config`, `code_reference` |
| Создание | Добавить брашы, меши, ландшафты, сущности и импортированные модели, а также обрезать вдоль рёбер граней | `create_brush`, `create_mesh`, `create_terrain`, `create_entity`, `import_model`, `trim` |
| Правка | Изменить то, что есть: ключи сущностей, выделение, размещение, грани, текстуры, ландшафт, слои и группы, а также worldspawn | `update_entity`, `select`, `transform`, `duplicate`, `set_face`, `mesh_edit`, `texture`, `terrain_edit`, `hierarchy`, `set_map_properties`, `bake_lighting` |
| Рисование и геймплей | Разбросать модели, смешать материалы, вставить части из библиотеки префабов и превратить брашы в двери, платформы и кнопки | `scatter`, `blend`, `prefab_library`, `random_fill`, `gameplay` |
| Редактор | Запускать действия меню, открывать и сохранять файлы, менять настройки редактора, двигать камеру, делать скриншоты, подавать ввод и проверять, где может пройти игрок | `run_action`, `map_file`, `open_project`, `set_editor`, `set_camera`, `screenshot`, `simulate_input`, `walkability` |
| Проект | Добавить в открытый проект Godot пакет сущностей геймплея, модели природы или демо | `project_content` |
| Скрипты | Воспроизвести сохранённый список вызовов инструментов, см. [MCP-скрипты](mcp-scripts.md) | `run_script` |

Описание каждого инструмента перечисляет его операции и аргументы, поэтому агент узнаёт их прямо с сервера.
[tools/mcp_client.py](https://github.com/Paraxdev/TrenchDot/blob/main/tools/mcp_client.py) выводит их командой `list` и
вызывает инструмент из оболочки:

```sh
python tools/mcp_client.py call screenshot '{"target":"3d","width":1280,"height":720}' --out shot.png
```

## Скриншоты { #screenshots }

`screenshot` возвращает PNG всего окна редактора или одного вида, когда `target` равен `3d`, `top`, `front` или `side`.
Для вида остальные аргументы определяют, что вы получите:

| Аргументы | Результат |
| --- | --- |
| Никаких | Всё окно редактора |
| Только `target` | Этот закреплённый вид как он есть, вместе с оверлеями |
| `width` и `height` | Отрисовка вне экрана до 4096 пикселей, без сетки, рамок сущностей, гизмо и выделения |
| `width`, `height` и `"overlays": true` | Вне экрана, с оверлеями редактора |
| `"overlays": false` | Чистый снимок в размере закреплённого вида |

### Что рисует Godot { #what-godot-renders }

`"source": "godot"` просит редактор Godot отрисовать карту с настоящими источниками света, окружением, туманом и
постобработкой. Вы получаете этот PNG, а также все ошибки и предупреждения, которые Godot записал при сборке. Удобно,
чтобы оценить освещение и материалы, не запуская игру.

```sh
python tools/mcp_client.py call screenshot '{"source":"godot","position":[0,256,512],"look_at":[0,64,0]}' --out godot.png
```

1. Сохраните карту внутри проекта, который открыт в TrenchDot.
2. Откройте этот проект в редакторе Godot, со сценой, где `FuncGodotMap` собирает карту.
3. Вызовите `screenshot` с `"source": "godot"`. Без `position` и `look_at` берётся камера 3D-вида.

Без [живого режима](godot/live.md) Godot сначала собирает карту такой, как она показана в TrenchDot, как *Собрать в
Godot*. `"build": false` снимает сцену такой, какая она сейчас в Godot. `width` и `height` по умолчанию 1280 на 720, а
`fov` как у 3D-вида.

> [!NOTE]
> Godot нужно окно для отрисовки, а Godot без окна возвращает ошибку вместо изображения. Окно может быть
> в фоне или свёрнуто.

## Чтение и проверка карты { #reading-and-reviewing-a-map }

| Шаг | Инструмент |
| --- | --- |
| Получить обзор | `summarize_map` перечисляет слои, классы сущностей, связи I/O и материалы, а также недостающие ассеты |
| Найти узлы | `list_nodes` фильтрует по `layer`, `material`, `property` (`{"model": "*crate*"}`) или `box` на карте |
| Посмотреть один | `get_node` возвращает один узел. `compact: true` опускает вершины и грани |
| Показать, что вы изменили | `changes_since` сравнивает с последним сохранением, с состоянием `undo_steps` шагов назад или с `file` карты |
| Откатить | Каждый вызов и каждый `run_script` это один шаг отмены с именем `MCP: ...`. `run_action undo` с `steps` отменяет несколько |

О хранении карт в git см. [Просмотр изменений](editor/reviewing.md).

## Поведение, которое стоит знать { #behavior-worth-knowing }

| Тема | Поведение |
| --- | --- |
| Браузеры | HTTP-сервер отклоняет любой запрос с заголовком `Origin` и любой POST, который не `application/json`, поэтому веб-страницы до него не достучатся, даже отданные с localhost |
| Ошибки | Инструмент, который не смог сделать своё дело, возвращает `isError`, в том числе неудавшийся `run_action` |
| Диалоги файлов | Действия, открывающие их, отклоняются, используйте `map_file` с путём. `run_action save` требует карту, у которой уже есть файл |
| Несохранённые вкладки | `run_action close_tab` отказывает при несохранённых изменениях, если `args.discard` не равен true. `args.close_others` вместо этого закрывает все вкладки, кроме активной |
| Пути к файлам | `res://` и относительные пути в `map_file`, `run_script`, `import_model`, `changes_since` и `validate_map` отсчитываются от открытого проекта или от рабочей папки редактора, если проекта нет. `map_file open` и `open_tab` перед открытием превращают путь в абсолютный, чтобы более поздний `save` не попал в другое место |
| Настройки редактора | `transform`, а также `run_action rotate` и `flip` вращаются вокруг центра выделения, привязанного к сетке только при включённой привязке, и сохраняют текстуры блокированными, пока включена блокировка UV. `transform` принимает `snap` и `uv_lock`, чтобы переопределить это на один вызов, `duplicate` принимает `uv_lock`. `run_action sculpt` и `blend` используют настройки инструмента, которые может менять человек, а `terrain_edit` использует фиксированные значения по умолчанию |
| Выделение | `select` отклоняет неизвестные id и пропускает скрытые или заблокированные узлы, перечисляя их в `skipped` |
| CSG | `csg_subtract`, `csg_merge`, `csg_intersect`, `csg_hollow` и `clip_apply` возвращают `replaced`, старые id, сопоставленные новым |
| Тайм-ауты | Вызовы прерываются по тайм-ауту через 120 с, кроме `run_script`, `project_content` и `bake_lighting` |
| Вопрос о контенте | Вопрос о готовом контенте, который получает новый проект, закрывается первым вызовом, кроме `get_state`, `screenshot` и `simulate_input`, и в этом сеансе больше не открывается |
| Переменные скриптов | `$name/rest` (без фигурных скобок) является ошибкой, когда `name` это известная переменная, ведь подставляются только `$name` отдельно или `${name}/rest`. Пишите `${project}/maps` |

## Заметки об инструментах { #tool-notes }

| Инструмент | Заметка |
| --- | --- |
| `run_action` `copy`, `cut`, `paste` | Copy и cut возвращают текст буфера обмена, paste принимает его как `args.text` с необязательными `offset` или `origin` |
| `run_action` `clip_apply` | Принимает плоскость (`point` и `normal` или три `points`) и `keep`: `front`, `back` или `both` |
| `run_action` `create_decal` | Размещает [декаль](editor/decals.md), используйте его вместо тонких брашей |
| `create_brush` | `openings` вырезает двери и окна, `{min, max, count, step, rows, row_step}` повторяет одно как сетку |
| `create_mesh` `rotate` | `[x, y, z]` в градусах в порядке YXZ Godot, поэтому `[0, 0, 90]` кладёт цилиндр вдоль X |
| `transform` | Применяет translate, rotate, flip и scale_to в таком порядке, одним шагом отмены. `rotate` поворачивает на 90 градусов вокруг Y, если не сказано иначе |
| `create_terrain` | `origin` это минимальный угол ландшафта, в отличие от других инструментов. `center` вместо этого размещает его вокруг точки |
| `create_brush`, `create_mesh` | Коньковый гребень фронтона идёт вдоль Z у брашей и вдоль X у мешей. Оба инструмента принимают `ridge_x` и `ridge_z` |
| Экспорт `map_file` | `path` это записанный файл, оставленный для старых вызывающих, `exported` тоже называет его, а `map_path` это открытая карта |
| `terrain_edit` | `probe [x, z]` без `op` только читает высоту. `clear_layer` требует `layer` |
| `validate_map` | Принимает в качестве входа любой метод или свойство класса или скрипта Godot у цели. `coplanar_faces` отмечает грани, которые будут мерцать. У каждой проблемы есть `bounds`. `path` проверяет сохранённую карту, не открывая её, `project: true` проверяет все карты проекта |
| `run_action` `place_entities` | Принимает `args.classnames`, а также `at` и `normal`, чтобы поставить сущности на поверхность так, как это делает перетаскивание из вкладки «Сущности». Отсутствие classnames это ошибка |
| Перетаскивания `simulate_input` | Перетаскивание с `"release": false` держит кнопку и её модификаторы нажатыми после возврата вызова, поэтому скриншот показывает перетаскивание в процессе, например карточку рядом с курсором. Событие `release` в более позднем вызове отпускает её там, где указатель, или в его `x` и `y`, или `world`, а отпускание только с одним из `x` и `y` это ошибка. Перетаскивание и его модификаторы остаются зажатыми, в том числе на настоящей клавиатуре, до этого отпускания, действия `new_map` или успешного `close_tab`, либо до выключения MCP, так что не забывайте про release. Щелчки и перетаскивания отклоняются до этого момента |
| `run_action` `reload_materials` | Сразу пересканирует папку текстур, хотя новые файлы и так находятся сами |
| `set_editor` `live_link_port` | Говорит с редактором Godot, проект которого задаёт другой `trenchdot/live_link_port` |
| `scatter` `preset` | Добавляет встроенные модели Blockbench, нужные пресету. Пресет glTF в проекте без пакета природы это ошибка, называющая `project_content` |
| `bake_lighting` | Запекает как [Запечь освещение](editor/light-baking.md) и ждёт. Пропущенные параметры сохраняют то, с чем карта была запечена в последний раз. `bake: false` только переключает `view`, `remove: true` убирает запекание. `out_of_date` говорит, менялась ли карта с тех пор |
| `project_content` | `install: "nature"` или `"demo"` скачивает из релиза и отвечает, когда файлы на месте. `install: "gameplay"` копирует пакет сущностей геймплея из аддона проекта, в том числе внутри скриптов. Без аргументов сообщает, что есть в проекте |
