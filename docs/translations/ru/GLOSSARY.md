# Глоссарий { #glossary }

## 3D-курсор { #3d-cursor data-forms="3D-курсора|3D-курсору|3D-курсором|3D-курсоре" }
Точка в мире под вашей мышью, в том виде, над которым вы побывали последним. Всё, что вы размещаете у курсора, попадает именно туда, например сущность по кнопке «Разместить» на панели «Сущности» или новый ландшафт.

## активатор { #activator data-forms="активатора|активатору|активатором|активаторе" }
Игрок или тело, которое запустило цепочку entity I/O, обычно тот, кто нажал кнопку или вошёл в триггер. Следующие шаги цепочки могут указать целью !activator и подействуют ровно на него.

## альбедо { #albedo }
Основной цвет материала, обычная текстура до добавления освещения, карт нормалей или свечения. Godot называет цветовую текстуру материала его текстурой альбедо.

## alpha scissor { #alpha-scissor }
Режим прозрачности Godot, который резко обрезает текстуру по порогу альфы, так что каждый пиксель либо виден полностью, либо скрыт полностью. Он подходит для решёток, листвы и декалей с чёткими краями, и в отличие от альфа-смешивания такой материал всё ещё отбрасывает тени.

## автозагрузка { #autoload data-forms="автозагрузки|автозагрузке|автозагрузку|автозагрузкой|автозагрузок" }
Скрипт или сцена, которую Godot один раз загружает при запуске и держит живой всю игру, настраивается в Project Settings > Globals > Autoload. В ней живёт код на всю игру, например счётчик очков или слушатель горячей перезагрузки.

## запечённое освещение { #baked-lighting data-forms="запечённого освещения|запечённому освещению|запечённым освещением|запечённом освещении" }
Свет, который один раз считается заранее и сохраняется, а не вычисляется в каждом кадре. Пункт Godot > Запечь освещение запекает солнце, небо, лампы и светящиеся материалы в лайтмап, а Godot рисует его через LightmapGI.

## блум { #bloom data-forms="блума|блуму|блумом|блуме" }
Мягкое сияние, которое яркие лампы и светящиеся материалы растекают по окружающим пикселям. Включается ключом worldspawn glow_intensity.

## булево значение { #boolean data-forms="булева значения|булеву значению|булевым значением|булевом значении|булевы значения|булевых значений|булевым значениям|булевыми значениями|булевых значениях" }
Значение, которое либо истинно, либо ложно, например включено ли питание. Сущности logic_branch, logic_gate и logic_flipflop хранят и объединяют булевы значения.

## браш { #brush data-forms="браша|брашу|брашем|браше|браши|брашей|брашам|брашами|брашах" }
Выпуклое тело, например коробка или клин, основной строительный блок уровня. Вы рисуете браши в видах и объединяете их с помощью CSG, а Godot превращает каждый в меш с подходящей коллизией.

## браш-сущность { #brush-entity data-forms="браш-сущности|браш-сущностью|браш-сущностей|браш-сущностям|браш-сущностями|браш-сущностях" }
Сущность, которая берёт свою форму у построенных вами брашей, например дверь, кнопка или триггер. Сначала вы рисуете браши, а затем превращаете их в сущность, в отличие от точечной сущности, которая находится в одной точке.

## выпуклая { #convex data-forms="выпуклый|выпуклое|выпуклые|выпуклой|выпуклую|выпуклых|выпуклым|выпуклыми" }
Выпирающая наружу везде, без вмятин и впадин, как коробка, клин или цилиндр. Каждый браш обязан быть выпуклым, поэтому редактор отклоняет перемещения вершин, которые продавили бы его. Для вогнутых форм преобразуйте браш в меш.

## кордон { #cordon data-forms="кордона|кордону|кордоном|кордоне|кордоны|кордонов" }
Рамка, которая ограничивает карту одной областью, пока вы работаете. Когда кордон включён, объекты за рамкой скрыты и не попадают в экспорт по кордону.

## CSG { #csg }
Constructive solid geometry, построение форм сочетанием тел, например вычитание одного браша из другого, чтобы прорезать дверной проём. Команды CSG в редакторе: Вычесть, Сделать полым, Выпуклое слияние и Пересечение.

## декаль { #decal data-forms="декали|декаль|декалью|декалей|декалям|декалями|декалях" }
Текстура, наложенная на поверхность, например пятно, трещина или плакат. В TrenchDot декаль это тонкий меш, который лежит на грани без мерцания, и ставится она при зажатом Alt, когда вы бросаете материал на грань. Проецируемая декаль, напротив, это сущность, которая проецирует материал на всё внутри своей рамки.

## антитайл { #detile data-forms="антитайла|антитайлу|антитайлом|антитайле" }
Настройка слоя ландшафта от 0 до 1, которая случайно поворачивает и сдвигает каждый повтор текстуры, чтобы на большом поле не было заметной сетки. Она требует дополнительных чтений текстуры, поэтому оставьте 0 там, где повтор не заметен.

## дисплейсмент { #displacement data-forms="дисплейсмента|дисплейсменту|дисплейсментом|дисплейсменте|дисплейсменты|дисплейсментов|дисплейсментам|дисплейсментами|дисплейсментах" }
Четырёхугольная грань браша, разбитая на сетку вершин, каждую из которых можно поднять или опустить, как в Hammer. Он даёт неровную землю внутри браша, построенного ровно. Большие открытые пространства лучше строить как ландшафт.

## определение сущности { #entity-definition data-forms="определения сущности|определению сущности|определением сущности|определении сущности|определений сущностей|определения сущностей|определениях сущностей" }
Описание одного класса сущности в FGD: его classname, ключи, входы и выходы и то, что Godot строит для него, например класс узла и скрипт. В Godot это ресурс FuncGodotFGDPointClass или FuncGodotFGDSolidClass, перечисленный в Entity Definitions файла FGD.

## спад { #falloff data-forms="спада|спаду|спадом|спаде" }
Как кисть для рисования, например кисть инструмента «Смешивание», затухает от центра к краю. Плавный спад даёт мягкие границы, постоянный закрашивает весь круг с одинаковой силой.

## FGD { #fgd }
Описание классов сущностей игры с их именами, ключами, входами и выходами. Название идёт от файлов Forge Game Data в Hammer. В Godot это ресурс FuncGodotFGDFile, а конфигурация игры передаёт его дальше в редактор.

## fixup { #fixup }
Префикс имени, заданный экземпляру префаба. При fixup p1 сущность door внутри него становится p1-door, так что несколько копий одного префаба хранят свои связи раздельно.

## func_detail { #func_detail }
Браш-сущность FuncGodot для статичной геометрии с коллизией, которая строится отдельным узлом, в стороне от брашей мира. Она не добавляет окклюдер, поэтому никогда не скрывает от отрисовки объекты за собой.

## func_illusionary { #func_illusionary }
Браш-сущность FuncGodot, которая видна, но без коллизии, так что игроки проходят сквозь неё. В уроке про остров в море из неё сделана вода.

## FuncGodot { #funcgodot }
Плагин Godot для построения уровней из map-файлов в стиле Quake. Аддон TrenchDot является его форком, поэтому его узел называется FuncGodotMap, а ресурсы начинаются с FuncGodot.

## конфигурация игры { #game-config data-forms="конфигурации игры|конфигурацию игры|конфигурацией игры" }
Файл trenchdot_game.json в корне проекта Godot, который пишет аддон. Он сообщает редактору, какие сущности, папки текстур и масштаб единиц использует ваш проект, и редактор перечитывает его всякий раз, когда аддон записывает его заново.

## пакет сущностей геймплея { #gameplay-entities-pack data-forms="пакета сущностей геймплея|пакету сущностей геймплея|пакетом сущностей геймплея|пакете сущностей геймплея" }
Двери, кнопки, лифты, триггеры, логика, спавнеры, пропсы и эффекты из справочника сущностей. Они не входят в сам аддон. Установка пакета копирует их определения и скрипты в res://trenchdot/entities, где они становятся частью вашего проекта, и вы можете свободно их менять.

## glTF { #gltf }
Открытый формат файлов для 3D-моделей и сцен, который читают Blender, Godot и большинство 3D-инструментов. Файл .glb это его двоичная форма, где геометрия и текстуры лежат в одном файле.

## группа Godot { #godot-group data-forms="группы Godot|группе Godot|группу Godot|группой Godot|групп Godot|группах Godot" }
Именованная метка на узлах в Godot, которую задают в Node > Groups или из кода и по которой код и entity I/O находят сразу все такие узлы. Цель вроде @enemies достаёт каждый узел группы enemies.

## Hammer { #hammer }
Редактор уровней от Valve для игр на движке Source, например Half-Life 2. TrenchDot заимствует у него модель входов и выходов сущностей и умеет импортировать его карты .vmf.

## горячая перезагрузка { #hot-reload data-forms="горячей перезагрузки|горячей перезагрузке|горячую перезагрузку|горячей перезагрузкой" }
Пересборка карт уже запущенной игры при каждом сохранении в TrenchDot, чтобы вам не приходилось перезапускать её, чтобы увидеть изменение. Для неё в игре нужен автозагрузочный скрипт trenchdot_hot_reload.gd.

## хотспот { #hotspot data-forms="хотспота|хотспоту|хотспотом|хотспоте|хотспоты|хотспотов|хотспотам|хотспотами|хотспотах" }
Прямоугольник, отмеченный на трим-листе и сохранённый в файле .hotspots.json рядом с текстурой. Подгонка к хотспоту притягивает выбранные грани к прямоугольнику, который подходит им лучше всего, так что трим-лист позволяет быстро текстурировать комнату.

## лайтмап { #light-map data-forms="лайтмапа|лайтмапу|лайтмапом|лайтмапе|лайтмапы|лайтмапов|лайтмапам|лайтмапами|лайтмапах|карта освещения|карты освещения|карте освещения|карту освещения|картой освещения|карт освещения" }
Текстура, которая хранит свет, доходящий до каждой точки статичной геометрии, вместе с переотражениями. Каждой грани достаётся в ней своя область.

## световой зонд { #light-probe data-forms="светового зонда|световому зонду|световым зондом|световом зонде|световые зонды|световых зондов|световым зондам|световыми зондами|световых зондах" }
Точка в открытом пространстве, которая хранит свет, приходящий со всех сторон. Движущиеся объекты берут свет у окружающих зондов, поэтому совпадают с запечённым освещением статичной геометрии.

## LightmapGI { #lightmapgi }
Узел Godot, который рисует лайтмап и его световые зонды. Карта, собранная из запечённого .tdm, получает такой узел с именем baked_lighting.

## освещённый просмотр { #lit-preview data-forms="освещённого просмотра|освещённому просмотру|освещённым просмотром|освещённом просмотре" }
Режим затенения 3D-вида редактора, включается клавишей F3, который показывает освещение карты, тени от солнца, небо и туман. Хорош, чтобы оценить свет до сборки в Godot, но рисует только 64 самых сильных точечных и прожекторных источника.

## live link { #live-link }
Соединение между TrenchDot и редактором Godot, локальный сервер, который аддон запускает на порту 7842. Через него идут пересборка при сохранении, живой режим и состояние Godot на панели инструментов.

## живой режим { #live-mode data-forms="живого режима|живому режиму|живым режимом|живом режиме" }
Отправляет ваши правки в сцену, открытую в редакторе Godot, по мере того как вы их делаете, ещё до сохранения, так что вы можете оценить свет и масштаб в собственном рендерере Godot. Включается кнопкой-ссылкой на панели инструментов или через Godot > Живой режим.

## логический вентиль { #logic-gate data-forms="логического вентиля|логическому вентилю|логическим вентилем|логическом вентиле|логические вентили|логических вентилей|логическим вентилям|логическими вентилями|логических вентилях" }
Правило, которое превращает два входа со значениями «истина» или «ложь» в один ответ, например and (истинны оба) или xor (истинен ровно один). Сущность logic_gate предлагает самые распространённые.

## главная сцена { #main-scene data-forms="главной сцены|главной сцене|главную сцену|главной сценой" }
Сцена, которую Godot проигрывает при запуске проекта, задаётся в Project > Project Settings > Application > Run. Её запускают и «Запустить проект» в TrenchDot, и кнопка Play в Godot.

## настройки карты { #map-settings data-forms="настроек карты|настройкам карты|настройками карты|настройках карты" }
Ресурс FuncGodotMapSettings, который говорит, откуда берутся текстуры, материалы и определения сущностей и сколько единиц карты составляют метр. У FuncGodotMap могут быть свои, иначе используются настройки проекта по умолчанию.

## MCP { #mcp }
Model Context Protocol, стандартный способ, которым ИИ-агенты и скрипты вызывают инструменты программы. Редактор может запускать MCP-сервер, чтобы агент мог просматривать и править карты. Для построения уровней он не нужен, и эта документация скрывает части про MCP, пока вы не включите переключатель MCP в шапке.

## MultiMesh { #multimeshes }
Способ Godot рисовать много копий одного меша за один проход. Разбросанные деревья, камни и трава строятся как MultiMesh, и тысячи экземпляров отрисовываются дёшево.

## навигационный меш { #navigation-mesh data-forms="навигационного меша|навигационному мешу|навигационным мешем|навигационном меше|навигационные меши|навигационных мешей|навигационным мешам|навигационными мешами|навигационных мешах" }
Упрощённый контур полов, по которым могут ходить ИИ-агенты, и по нему Godot ищет пути. TrenchDotNav запекает его из коллизии собранной карты.

## карта нормалей { #normal-map data-forms="карты нормалей|карте нормалей|карту нормалей|картой нормалей|карт нормалей|картам нормалей|картами нормалей|картах нормалей" }
Текстура, которая хранит, в какую сторону смотрит каждый пиксель поверхности, так что плоские грани ловят свет, как будто на них есть бугры и канавки. Она добавляет мелкие детали без лишней геометрии.

## операнд { #operand data-forms="операнда|операнду|операндом|операнде|операнды|операндов" }
Число, с которым работает вычисление, кроме полученного. В math_calc, который прибавляет 5, операнд равен 5.

## ORM { #orm }
Текстура, которая упаковывает три карты в градациях серого в свои цветовые каналы: ambient occlusion в красный, roughness в зелёный и metallic в синий. Материалы Godot и слои ландшафта TrenchDot читают её как один файл.

## точечная сущность { #point-entity data-forms="точечной сущности|точечную сущность|точечной сущностью|точечные сущности|точечных сущностей|точечным сущностям|точечными сущностями|точечных сущностях" }
Сущность, которая находится в одной точке, а не берёт форму у брашей, например свет, звук или точка появления. Разместите её, перетащив с панели «Сущности» в вид.

## префаб { #prefab data-forms="префаба|префабу|префабом|префабе|префабы|префабов|префабам|префабами|префабах" }
Повторно используемый кусок карты, сохранённый как отдельный файл .tdm и размещаемый в других картах как экземпляры. Правка файла префаба обновляет каждый его экземпляр.

## res:// { #res }
Способ Godot записывать путь внутри папки проекта, как бы эта папка ни называлась на диске. res://maps/room.tdm это room.tdm в папке maps вашего проекта Godot. Поэтому карты и модели нужно сохранять внутри проекта, чтобы аддон их нашёл.

## ограниченный режим { #restricted-mode data-forms="ограниченного режима|ограниченному режиму|ограниченным режимом|ограниченном режиме" }
Как TrenchDot открывает проект Godot, в котором есть код и которому вы ещё не доверяете. Вы можете просматривать и править его карты, но редактор не запускает на нём Godot, не собирает в Godot и не отправляет живые правки, потому что Godot выполняет скрипты проекта, когда открывает, запускает или собирает его. Нажмите «Ограниченный режим» в строке состояния, чтобы довериться проекту.

## набор разброса { #scatter-set data-forms="набора разброса|набору разброса|набором разброса|наборе разброса|наборы разброса|наборов разброса|наборам разброса|наборами разброса|наборах разброса" }
Группа моделей, которые рисуют вместе инструментом разброса, например лес или луг с травой, со своим слоем, плотностью и целевыми поверхностями. Godot строит каждый набор как MultiMesh.

## отражения в экранном пространстве { #screen-space-reflections data-forms="отражений в экранном пространстве|отражениям в экранном пространстве|отражениями в экранном пространстве|отражениях в экранном пространстве" }
Эффект Godot, который зеркалит в блестящих поверхностях то, что уже есть на экране, так что мокрые улицы отражают лампы. Включается ключом worldspawn ssr, равным 1.

## сигнал { #signal data-forms="сигнала|сигналу|сигналом|сигнале|сигналы|сигналов|сигналам|сигналами|сигналах" }
Так Godot называет событие, о котором узел оповещает, например нажатие кнопки. Каждый выход сущности это сигнал, а связывание выхода подключает этот сигнал к методу входа на цели.

## targetname { #targetname }
Имя, которое вы даёте сущности, чтобы другие сущности могли до неё добраться, например main_door. По нему сущности находят выходы, fixup префабов и ключи вроде fixture.

## тексел { #texel data-forms="тексела|текселу|текселом|текселе|тексели|текселей|текселям|текселями|текселях" }
Один пиксель текстуры в том виде, как он ложится на поверхность. По умолчанию один тексел покрывает одну единицу карты, а плотность текселей, то есть сколько текселей помещается на площади, определяет чёткость текстуры. У лайтмапа тоже есть тексели, и его размер тексела говорит, сколько единиц карты покрывает один.

## размер текстуры { #texture-size data-forms="размера текстуры|размеру текстуры|размером текстуры|размере текстуры" }
Размер в мире, который покрывает один повтор текстуры, задаётся как metadata/texture_size у материала Godot. Без него один пиксель покрывает одну единицу карты, и фотография высокого разрешения растягивается на огромную площадь.

## служебные текстуры { #tool-textures data-forms="служебных текстур|служебным текстурам|служебными текстурами|служебных текстурах" }
Особые текстуры, которые говорят сборке, для чего нужна грань браша, а не рисуются сами. Грани clip только сталкиваются, грани skip ничего не строят, а грани origin задают, где находится начало браш-сущности. Любая текстура из папки special/, tools/ или td/ ничего не рисует в Godot, как и nodraw, hint, trigger и остальные служебные имена в любой папке.

## TrenchBroom { #trenchbroom }
Бесплатный редактор уровней для игр в стиле Quake. TrenchDot во многом вдохновлён им и умеет импортировать его файлы .map.

## триггерный объём { #trigger-volume data-forms="триггерного объёма|триггерному объёму|триггерным объёмом|триггерном объёме|триггерные объёмы|триггерных объёмов|триггерным объёмам|триггерными объёмами|триггерных объёмах" }
Невидимая браш-сущность, которая запускает выходы, когда в неё входит тело или выходит из неё, например чтобы начать кат-сцену, когда игрок входит в комнату. Нарисуйте её инструментом «Объём» (Shift+E).

## трим-лист { #trim-sheet data-forms="трим-листа|трим-листу|трим-листом|трим-листе|трим-листы|трим-листов|трим-листам|трим-листами|трим-листах" }
Текстура, которая упаковывает в одно изображение полосы деталей, например кромки, трубы и панели. Грани подгоняются к её частям хотспотами, так что нескольких трим-листов хватает, чтобы текстурировать целое здание.

## трипланарная проекция { #triplanar data-forms="трипланарной проекции|трипланарную проекцию|трипланарной проекцией|трипланарные проекции|трипланарных проекций|трипланарное|трипланарный" }
Способ проецировать текстуру на поверхность с трёх сторон, сверху и с двух боков, смешивая по углу поверхности. Слои ландшафта используют её, чтобы на скалах была порода, а не растянутая клякса.

## блокировка UV { #uv-lock data-forms="блокировки UV|блокировке UV|блокировку UV|блокировкой UV" }
Настройка, по умолчанию включённая и переключаемая сочетанием Ctrl+Shift+U, которая удерживает текстуры приклеенными к брашу, пока вы его двигаете. При выключенной текстура остаётся на месте в мире и скользит по сдвинутым граням.

## UV { #uv }
Координаты, которые говорят, какая часть текстуры ложится на каждую точку грани, U поперёк текстуры, V вдоль неё вниз. Грани брашей обычно получают их из проекции, а меши и некоторые грани хранят свои для каждого угла.

## worldspawn { #worldspawn }
Корневая сущность карты, которая хранит браши мира. Её ключи содержат настройки всей карты, такие как небо, туман, солнце и стриминг, и Инспектор показывает её, когда ничего не выбрано.

## рыскание { #yaw data-forms="рыскания|рысканию|рысканием|рыскании" }
Вращение вокруг вертикальной оси, направление, в котором что-то смотрит, если глядеть сверху. Рыскание точки назначения телепорта определяет, куда повёрнуты тела после прибытия.

## z-fighting { #z-fighting }
Мерцающие полосы там, где две поверхности лежат в одной плоскости или очень близко к ней. GPU не может понять, какая из них спереди, поэтому каждый пиксель показывает то одну, то другую, а узор смещается при движении камеры. Декали его избегают, тонкие браши, наложенные на стену, нет.
