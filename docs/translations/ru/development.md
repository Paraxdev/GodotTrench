# Разработка { #development }

Эта страница для вас, если вы хотите собрать редактор из исходников, изменить аддон или писать документацию.

## Сборка { #building }

Клонируйте вместе с подмодулями, аддон Godot в `godot/addons/func_godot` один из них:

```sh
git clone --recursive https://github.com/Paraxdev/TrenchDot.git
```

Уже склонировали без этого? Выполните `git submodule update --init`. Редактор собирается и без аддона, но тестам и
проекту Godot он нужен.

```sh
cargo run -p td_editor --release            # start the editor
cargo run -p td_editor --release -- map.tdm # open a map
```

Нужен GPU с Vulkan, DX12 или Metal, а в Linux сеанс X11 или Wayland.

Минимум это Rust 1.95, его требует egui 0.36.
[rust-toolchain.toml](https://github.com/Paraxdev/TrenchDot/blob/main/rust-toolchain.toml) закрепляет 1.98.1, версию, которую
использует CI, поэтому rustup установит её при вашей первой сборке.

## Проверки { #checks }

Один раз на клон выполните `./tools/fmt --install`. Он включает pre-commit-хук, который форматирует добавленный в индекс
Rust.

```sh
./tools/fmt --check
python tools/gen_licenses.py --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo test -p td_editor --test e2e -- --ignored --test-threads=1
godot --headless --path godot --import                            # twice on a fresh checkout
godot --headless --path godot --script res://tests/run_tests.gd
godot --headless --path godot --script res://tests/build_showcase.gd
```

CI выполняет всё это, так что прогоните перед отправкой.

E2e-тесты запускают настоящий редактор и управляют им симулированным вводом. Для этого нужны GPU и сеанс рабочего стола,
поэтому `cargo test` пропускает их, если не передать `--ignored`. CI запускает их в Linux с программным Vulkan. Чтобы
проверить live link без окна, см. [Протокол live link](godot/live-link.md#testing-without-a-window).

> [!NOTE]
> `godot --headless --script` ничего не рисует (скриншоты и проверки отрисовки получаются чёрными) и не запускает
> автозагрузки проекта, только сам скрипт. Пишите тесты на данные и узлы, а не на пиксели или состояние автозагрузок.

Чтобы замерить время сборки карт, выполните `godot --headless --path godot --script res://tests/bench_build.gd -- runs=5 threaded=1`.
Не используйте для этого `build_showcase.gd`, он перезаписывает закоммиченные сцены витрины.

## Файлы карт в git { #map-files-in-git }

Карты `.tdm` двоичные, см. [формат карт .tdm](format/README.md). `.gitattributes` в репозитории уже помечает их. Для
читаемых диффов вам нужна только строка `git config` из раздела
[Просмотр изменений](editor/reviewing.md#maps-in-git), один раз на клон.

## Сгенерированный контент { #generated-content }

Некоторые файлы создаются скриптом, а не вручную. Когда вы меняете то, что скрипт читает, запустите его снова.

| Команда | Что перегенерирует |
| --- | --- |
| `cargo run -p td_formats --example demo_maps` | Тестовые карты в `godot/tests/maps` и маленькие демо-карты в `godot/demo/maps` |
| `python tools/fetch_demo_textures.py` | Фототекстуры CC0 для демо, см. [размер текстуры](godot/materials.md#texture-size) |
| `python tools/fetch_demo_props.py` | Пропсы CC0 с Poly Haven в `godot/models/polyhaven` с восстановленными альфа-картами стекла и пламени. `--fix-alpha` только восстанавливает их |
| `cargo run -p td_samples --bin showcase --release` | Демо-модели Blockbench |
| `cargo run -p td_editor --example export_addon_fgd` | Основные файлы FGD аддона и шаблон пакета сущностей геймплея из `builtin_entities.json` и `gameplay_entities.json`, записанные в подмодуль аддона, затем установленную копию пакета в демо-проекте |
| `python tools/gen_licenses.py` | Таблицу крейтов Rust в [LICENSES.md](https://github.com/Paraxdev/TrenchDot/blob/main/LICENSES.md) |

## Аддон Godot { #the-godot-addon }

У аддона свой репозиторий, [trenchdot_func](https://github.com/Paraxdev/trenchdot_func), он выгружен в
`godot/addons/func_godot`. Его тесты лежат здесь, в `godot/tests`, потому что им нужен демо-проект. Чтобы изменить аддон:

1. Закоммитьте изменение внутри `godot/addons/func_godot` и отправьте его в trenchdot_func.
2. Добавьте новый коммит подмодуля в индекс здесь командой `git add godot/addons/func_godot` и закоммитьте его вместе с
    изменениями TrenchDot, которым он нужен.

Сначала отправляйте аддон. Коммит TrenchDot, указывающий на коммит аддона, которого нет на GitHub, не выгрузится в CI.

`version` в `plugin.cfg` совпадает с версией воркспейса в [Cargo.toml](https://github.com/Paraxdev/TrenchDot/blob/main/Cargo.toml).
Повышайте обе вместе, редактор предупреждает, когда аддон проекта с ней не совпадает.

## Переводы { #translations }

Интерфейс редактора есть на английском, немецком, французском, испанском, португальском, русском, упрощённом китайском и
японском, см. [Язык](editor/interface.md#language). Английский это исходный язык, а остальные семь лежат в
[crates/td_editor/locales](https://github.com/Paraxdev/TrenchDot/tree/main/crates/td_editor/locales), по одному
JSON-файлу, и встраиваются при сборке редактора. В README там описаны формат, формы множественного числа и глоссарий.

В коде ключом служит английский текст. Оберните литерал в `en!("...")` там, где он хранится, и в `tr(...)`,
`trf!("... {n} ...", n = count)` или `tr_n!(count, "{n} brush", "{n} brushes")` там, где он рисуется, и добавьте тот же
ключ в каждый файл. Текст без записи показывается по-английски. Код в `crates/td_editor/src/mcp`, строки журнала и
содержимое карт никогда через них не проходят, ответы и ошибки MCP остаются английскими. `Msg` хранит английский текст
рядом с переводом, так что строка состояния может показать один, а MCP прочитать другой.

```sh
TD_L10N_TODO=/tmp/l10n cargo test -p td_editor --lib i18n
```

Этот запуск падает, пока в файле нет ключа, который использует код, или пока в нём остался ключ, которого код уже не
использует. Если `TD_L10N_TODO` указывает на существующую папку, он ещё и пишет по файлу на язык с недостающими
ключами. Другой тест сканирует исходники на тексты интерфейса, которые обходят поиск, поэтому необработанный литерал,
переданный подписи, его проваливает. Переводы написаны ИИ и не проверены, правка от носителя языка затрагивает только
файл этого языка. Редактор, запущенный с `--default-prefs`, как в e2e-тестах, всегда на английском.

У руководства тоже есть переводы, см. [Перевод руководства](#translating-the-manual). Его страницы называют пункты меню и
кнопки так, как их показывает редактор, поэтому после изменения значения в каталоге выполните
`python3 tools/translations.py check`. Он перечислит страницы, которые всё ещё используют старую формулировку.

## Документация { #documentation }

Документация это страницы Markdown в `docs/`, а сайт из них делает [Zensical](https://zensical.org).
Его настраивает `zensical.toml` в корне репозитория, а оглавление это `docs/SUMMARY.md`. Страница, которой там нет, всё
равно собирается, просто не получает места в навигации. `docs/requirements.txt` закрепляет Zensical,
`docs/stylesheets/td.css` хранит цвета, `docs/javascripts/td.js` переключатель MCP и карточки глоссария, а
`docs/overrides` заменяет несколько шаблонов темы.

Выполняйте это из корня репозитория:

```sh
python3 -m venv .venv                  # once
. .venv/bin/activate                   # .venv\Scripts\activate on Windows
pip install -r docs/requirements.txt   # once, and again when the pin changes
zensical serve                         # live preview of the English site on http://localhost:8000/TrenchDot/
python3 tools/translations.py check    # the translated pages against their English source
python3 tools/build_site.py            # the build CI runs, English at the root of _site and a folder per language
python3 tools/test_docs.py             # tests of the three tools and of the built site
python3 tools/check_site.py            # the link check CI runs on _site
```

`build_site.py` запускает `zensical build --clean --strict` один раз для английского и по разу для каждого языка, поэтому
он падает на ссылке на страницу или заголовок, которых нет ни в одном из них. Опечатка в записи `SUMMARY.md`, пропавшая
картинка или страница, забытая в навигации, через него проходят, их ловит `tools/check_site.py` в каждом языке. Чтобы
собрать только некоторые языки, назовите их: `python3 tools/build_site.py de ja`.

Идентификатор заголовка это его текст в нижнем регистре, пробелы становятся дефисами, а остальная пунктуация
отбрасывается, так что `## path_corner` это `#path_corner`. Ссылки на справку из редактора в
[help.rs](https://github.com/Paraxdev/TrenchDot/blob/main/crates/td_editor/src/help.rs) указывают на эти идентификаторы,
и тест их проверяет, поэтому переименовывайте заголовок только вместе с его ссылками.

Врезки это алерты в стиле GitHub: `> [!NOTE]`, `> [!TIP]` или `> [!WARNING]` в отдельной строке, а текст в цитируемых
строках ниже. Так они отображаются и на GitHub. Всё, что относится к пронумерованному шагу, второй абзац, картинка или
блок кода, отступается на 4 пробела, иначе оно выпадет из списка.

Картинки для страницы лежат в `docs/assets/<page>/`.

Если новичок не знал бы термина, заведите для него запись в `GLOSSARY.md`: заголовок `## term` и определение в один
абзац. Тогда первое употребление на каждой странице ссылается на него и показывает определение при наведении. Код,
ссылки и заголовки остаются нетронутыми.

`.github/workflows/pages.yml` собирает сайт для запросов на слияние, которые затрагивают `docs/`, `zensical.toml`,
инструменты документации или каталоги редактора, и публикует его на GitHub Pages, когда они попадают в `main`.

### Перевод руководства { #translating-the-manual }

Сайт также собирается на немецком, французском, испанском, португальском, русском, упрощённом китайском и японском, то
есть на языках редактора. Английский это исходный язык, а остальные называются как коды редактора: `de`, `fr`, `es`,
`pt`, `ru`, `zh-Hans` и `ja`. Сайт языка живёт по адресу `/TrenchDot/<code>/`, и редактор открывает руководство там,
когда работает на этом языке. Переводы написаны ИИ, и носитель языка их не проверял, поэтому каждый переведённый сайт
сообщает об этом в баннере, который читатель может закрыть. Правка от человека, свободно владеющего языком, приветствуется.

**Где что лежит.** Переведённая страница лежит в `docs/translations/<code>/` под именем английской,
`docs/translations/de/editor/brushes.md` для `docs/editor/brushes.md`. Рядом со страницами `site.toml` хранит тексты, которые
не являются страницами: язык темы, описание сайта, названия кнопки цветовой схемы и переключателя MCP, баннер,
пометку для непереведённых страниц, названия врезок и таблицу `[nav]`. Таблица `[nav]` сопоставляет каждому
английскому названию в `SUMMARY.md` его перевод, а название, которого в ней нет, показывается по-английски. Список
языков это `[[project.extra.alternate]]` в `zensical.toml`.

**Строка source.** Переведённая страница начинается с front matter, называющего английскую страницу, за которой она
следует:

```yaml
---
source: 0123456789abcdef0123456789abcdef01234567
---
```

`source` это то, что печатает `git hash-object docs/<page>` для английской страницы. Пока он совпадает, перевод
актуален, и сборка использует его. Когда английская страница меняется, он больше не совпадает, перевод устарел, и
сборка вместо него показывает английскую страницу с короткой пометкой после заголовка. Поэтому правка английской
страницы никогда не ломает CI и не требует правки перевода, страница лишь становится английской на остальных сайтах,
пока кто-нибудь её не обновит. Отсутствующая страница откатывается так же, поэтому каждая страница есть в каждом языке, а
кнопка языка всегда попадает на ту же страницу.

**Команды.** Все они выполняются из корня репозитория.

| Команда | Что делает |
| --- | --- |
| `python3 tools/translations.py status` | Перечисляет устаревшие, отсутствующие и осиротевшие страницы и названия навигации без записи. Никогда не падает. Добавьте `--lang de` для одного языка и `--diff`, чтобы увидеть, что изменилось в английском с момента перевода каждой страницы. |
| `python3 tools/translations.py prep --lang de editor/brushes.md` | Печатает то, что нужно переводчику для одной страницы: front matter, идентификаторы заголовков, подписи с их переводом, слова глоссария и английский текст. |
| `python3 tools/translations.py check [--lang de] [page ...]` | Падает на актуальном переводе, нарушающем одно из правил ниже. Названные вами страницы проверяются независимо от состояния, так что можно проверить страницу до того, как она станет актуальной. |
| `python3 tools/translations.py stamp --lang de editor/brushes.md` | Задаёт `source` как английскую страницу в её нынешнем виде и больше ничего не трогает. |

**Перевод или обновление страницы.** Четыре шага:

1. Выполните `prep` для страницы. Для устаревшей страницы он ещё показывает английский дифф с прежнего `source`.
2. Напишите страницу в `docs/translations/<code>/`, начав с front matter, который напечатал `prep`. Сохраните английскую
    структуру строка в строку: те же заголовки, списки, картинки, ссылки, врезки и блоки `td-mcp`. Переводите текст,
    альтернативный текст картинок и текст ссылок, и ничего больше, в манере языка, см. ниже.
3. Выполните `check` для страницы и исправляйте то, о чём он сообщает, пока он не станет чистым.
4. Выполните `python3 tools/build_site.py`, `python3 tools/check_site.py` и `python3 tools/translations.py check`, затем
    закоммитьте страницы одного языка вместе.

Используйте `stamp` только тогда, когда английская правка ничего не требует от перевода, например опечатка, изменённая
цель ссылки или переформулировка с тем же смыслом. Он не смотрит на страницу, так что сначала прочитайте английский
дифф. Изменение того, что страница говорит, требует правки перевода, и новый `source` идёт вместе с ней.

**Манера.** Каждый язык сохраняет непринуждённую манеру [getting-started.md](getting-started.md) в форме, которую там
используют документации к программам:

| Язык | Обращение |
| --- | --- |
| de | du, со строчной буквы |
| fr | vous |
| es | tú, в нейтральном испанском, ustedes во множественном числе, как сказано в README каталога |
| pt | você, бразильский португальский |
| ru | вы, со строчной буквы |
| zh-Hans | 你 |
| ja | форма です/ます, без местоимения |

**Что проверяет `check`.** Правила действуют для каждого актуального перевода, и `check` запускается в CI перед сборкой.

* Идентификаторы заголовков остаются английскими. Каждый заголовок, включая название, несёт идентификатор своего
    английского заголовка, `## Größe ändern { #reshape }`, в том же порядке и с теми же суффиксами повторов
    (`{ #inputs_1 }`). Zensical отбрасывает буквы вне ASCII, когда строит идентификатор, а на английские опираются ссылки
    справки F1 из редактора, ссылки между страницами, глоссарий и кнопка языка.
* Код остаётся английским и побайтно тем же. Блоки кода копируются вместе с комментариями, а каждый встроенный фрагмент
    кода английской страницы присутствует в переводе. Имена классов сущностей, ключи, входы и выходы, имена
    инструментов MCP, JSON, имена файлов, названия клавиш (`Ctrl`, `F1`) и названия продуктов (TrenchDot, Godot, MCP,
    Live Link) тоже не переводятся.
* Ссылки и картинки сохраняют свои цели, меняются только текст ссылки и альтернативный текст. Скриншоты английские,
    переведённая страница указывает на те же файлы, так что на развёрнутом сайте лежит по одной копии каждого.
* Подписи берутся из редактора. Жирный фрагмент, или курсивный со словами ` > `, все части которого являются ключами
    каталога `crates/td_editor/locales/<code>.json`, должен встречаться в переведённой странице так, как пишет каталог,
    а части соединены через ` > `. Пишите подпись так, как её показывает редактор, не склоняя, и стройте предложение
    вокруг неё. Подпись, которой нет в каталоге, например кнопка Godot или аддона, остаётся английской.
* Врезки, блоки `td-mcp` и их заголовок `## MCP` остаются на месте. Пишите маркер врезки отдельно в строке,
    `> [!NOTE]`, сборка поставит переведённое название после него. Блоки GDScript сохраняют тег `gdscript`.
* Никаких длинных тире, средних тире, дефисов с пробелами и эмодзи, правила английских страниц действуют в каждом языке.
* В китайском и японском каждый абзац, пункт списка и ячейка таблицы это одна исходная строка. Перенос строки между
    двумя иероглифами в браузере отображается как пробел, поэтому `check` его отмечает. Полноширинная пунктуация
    допустима, но двойные тире U+2014 и U+2015 считаются тире и не разрешены.

**Глоссарий.** `GLOSSARY.md` переводится как любая страница, и каждый термин сохраняет свой английский идентификатор,
`## Aktivator { #activator }`. Язык, который склоняет термин, перечисляет другие формы в `data-forms`,
`{ #baked-lighting data-forms="gebackenen Beleuchtung|gebackener Beleuchtung" }`, так что карточка при наведении находит и
их. Термин, который является названием в интерфейсе, использует слово из каталога, и `check` их сравнивает. Переведённая
страница использует термин в собственной форме глоссария там, где он встречается впервые, именно это связывает её с
карточкой. Когда вы добавляете термин в английский глоссарий, добавьте его и в переведённые, если можете, а пока
глоссарий каждого языка остаётся английским.

## CI { #ci }

CI пропускает отправки в `main`, которые меняют только документацию или Markdown. Каждая другая зелёная отправка в `main`
заменяет [скользящую бету](https://github.com/Paraxdev/TrenchDot/releases/tag/beta) свежими загрузками редактора,
аддона, демо и контента.

Редактор скачивает аддон и контент только из релизов GitHub. itch.io это витрина, которая получает те же файлы на своих
каналах, `addon`, `nature-pack`, `demo-content` и так далее. Скользящая бета это единственная сборка, поэтому она
заполняет эти простые каналы.

| Архив в релизе | Чем устанавливается |
| --- | --- |
| `func_godot-trenchdot-addon.zip` | *Godot > Установить или обновить аддон…* |
| `trenchdot-nature-pack.zip` | *Godot > Добавить контент в проект…* |
| `trenchdot-demo-content.zip` | *Godot > Добавить контент в проект…* |

Папки, которые содержит каждый архив, перечислены в
[content.rs](https://github.com/Paraxdev/TrenchDot/blob/main/crates/td_editor/src/content.rs) и
[addon_install.rs](https://github.com/Paraxdev/TrenchDot/blob/main/crates/td_editor/src/addon_install.rs), а тесты
сверяют команды zip в `ci.yml` с ними.

Редактор находит архивы через GitHub API. CI собирает его с `TRENCHDOT_CHANNEL=beta`, поэтому он сначала смотрит в
скользящую бету. Локальная сборка сначала пробует релиз с именем её собственной версии, затем откатывается к бете. Чтобы
попробовать архив до публикации, направьте редактор на другой сервер переменной окружения `TRENCHDOT_RELEASES_API`.

CI также ставит метку на каждую бету, в `TRENCHDOT_BUILD` для редактора и в `plugin.cfg` упакованного аддона, вроде
`0.1.0-beta.202611041532.d194b57`: номер релиза, время коммита по UTC и коммит. Так редактор отличает аддон от более
старой беты и предлагает обновление. Локальная сборка сохраняет простую версию.

## MCP { #mcp }

Участвуете с помощью ИИ-агента? [AGENTS.md](https://github.com/Paraxdev/TrenchDot/blob/main/AGENTS.md) перечисляет правила
и проверки, которые должен пройти запрос на слияние.

E2e-тесты управляют редактором через [MCP-сервер](mcp.md), а `example_mcp_scripts_replay` воспроизводит каждый скрипт в
`examples/mcp`.

Чтобы управлять собственным редактором из оболочки:

```sh
trenchdot --mcp-http=7850 --default-prefs &
TRENCHDOT_MCP_URL=http://127.0.0.1:7850/mcp python3 tools/mcp_client.py call get_state
```

Задайте `TRENCHDOT_MCP_TOKEN` одинаковым для обоих, чтобы попробовать с [токеном](mcp.md#the-http-token).

### MCP в документации { #mcp-in-the-docs }

Переключатель **MCP** в заголовке, по умолчанию выключенный, скрывает всё о MCP, чтобы страницы оставались читаемыми для
тех, кто с ним никогда не работает. На странице помещайте весь текст о MCP в один раздел `## MCP` в самом конце, внутри
блока `td-mcp`:

```html
<div class="td-mcp" markdown>

## MCP

What only MCP users need.

</div>
```

Оставляйте пустые строки вокруг содержимого, GitHub читает Markdown внутри только с ними. Страницы только о MCP
относятся к части **MCP** в `SUMMARY.md`, которую переключатель тоже скрывает.
