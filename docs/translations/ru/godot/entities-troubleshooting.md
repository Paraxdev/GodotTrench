# Сущности, которые ничего не делают { #entities-that-do-nothing }

Когда Godot собирает сущность без её определения, сущность остаётся лишь оболочкой. Браш-сущность вроде двери сохраняет меш, но становится обычным `Node3D` без скрипта и коллизии, а точечная сущность становится пустым `Marker3D`. То же случается, когда определение не подходит своей сущности, например у браш-сущности определение не строит физическое тело. TrenchDot и Godot оба сообщают, когда так происходит, а эта страница объясняет каждое сообщение.

## Где это видно { #where-you-see-it }

1. Строка состояния

    Сохраните карту в TrenchDot, пока её сцена открыта в Godot. Если Godot собрал классы, для которых у него нет определения, строка состояния внизу слева называет их и настройки карты, с которыми Godot собирал:

    ![Строка состояния: Godot пересобрал 1 узел карты, но в res://crypt_settings.tres нет определения для func_button и func_door, поэтому они собираются как обычные узлы](../assets/entities-troubleshooting/status-missing-classes.png)

2. Панель «Проблемы»

    Откройте вкладку **Проблемы** рядом со Структурой и Историей слева. Она перечисляет каждый класс, который Godot собрал как обычный узел, с исправлением, а остальные предупреждения этой сборки начинаются с «Godot:». Щёлкните строку, чтобы выделить сущность.

    ![Панель «Проблемы» с двумя предупреждениями: Godot собрал func_button и func_door как обычные узлы, в каждом сказано, какой файл добавить в Base Fgd Files](../assets/entities-troubleshooting/issues-missing-classes.png)

    Пока Godot не собрал карту, панель «Проблемы» сравнивает ваши сущности с FGD, с которым собирает Godot, его аддон экспортирует вместе с [конфигурацией игры](project-setup.md#the-game-config). Если сущности в этом FGD нет, появляется предупреждение «Godot собирает с ..., в чьём FGD ... нет ...».

    Когда Godot показывает сцену, собранную до того, как появилось определение, строка состояния и панель «Проблемы» говорят «Godot показывает ..., собранное с другими определениями сущностей». Выберите *Godot > Собрать в Godot* или нажмите **Build Map** в Godot и сохраните, чтобы собрать её заново. **Запустить проект** говорит то же про сцены, которые запускает.

3. Панель Output в Godot

    Нажмите **Build Map** на узле `FuncGodotMap` в Godot. Панель Output внизу редактора Godot покажет предупреждение `[TrenchDot]` для классов без определения и по одному для каждого неподходящего определения. Отметьте *Print Build Report* в *Build Flags* на узле, чтобы получить весь [отчёт о сборке](building.md#build-report).

## Сущности без определения { #entities-without-a-definition }

| В сообщении сказано | Почему | Что сделать |
| --- | --- | --- |
| Установите пакет сущностей геймплея | Двери, кнопки, триггеры, пропсы и спавнеры идут с пакетом, а в проекте его нет | Выберите *Геймплей > Установить сущности геймплея* в TrenchDot, см. [Настройку проекта](project-setup.md#installing-and-updating-the-pack) |
| В вашем FGD нет пакета сущностей геймплея, добавьте `trenchdot_default_fgd.tres` в его Base Fgd Files | В вашем FGD нет *Base Fgd Files* | Добавьте `res://addons/func_godot/fgd/trenchdot_default_fgd.tres` в *Base Fgd Files* того FGD, который назван в настройках карты в *Entity Fgd* |
| Пакет установлен, но *Entity Fgd* это FGD аддона | Настройки карты используют собственный FGD от FuncGodot или другой файл аддона, который заменяет обновление аддона | Задайте в *Entity Fgd* этих настроек карты тот FGD, который использует ваша конфигурация игры |
| У вашего собственного класса нет определения | Он есть в FGD вашей конфигурации игры, но не в *Entity Fgd* тех настроек карты, с которыми собирает Godot | Задайте в *Entity Fgd* этих настроек карты тот FGD, который использует ваша конфигурация игры, см. [Свои ресурсы](project-setup.md#your-own-resources) |
| Узел карты использует настройки карты по умолчанию от аддона, а не из Project Settings | Узел добавили старым аддоном, который хранил настройки карты по умолчанию в сцене | Выделите узел карты в Godot и очистите *Map Settings* в Инспекторе |
| Сцена собрана с другими определениями сущностей | Она собрана до того, как появился пакет или определение, и с тех пор не пересобиралась | Нажмите **Build Map** и сохраните сцену. В [живом режиме](live.md#when-live-mode-rebuilds-the-whole-map) Godot делает это сам |

## Определения, которые не подходят { #definitions-that-do-not-fit }

Эти сообщения приходят из панели Output в Godot, а после сохранения из панели «Проблемы» как предупреждения «Godot:». Последние два панель «Проблемы» отмечает ещё до сохранения.

| В сообщении сказано | Почему | Что сделать |
| --- | --- | --- |
| `func_crusher builds as a Marker3D, so its brushes have no collision` | У определения нет *Node Class*, а его скрипт наследует узел, который не физическое тело | Задайте *Node Class* `StaticBody3D`, `AnimatableBody3D` или `Area3D` либо сделайте так, чтобы скрипт наследовал один из них |
| `func_crusher: Node Class AnimatedBody3D not found, building it as a Node3D` | Опечатка или `class_name`, который Godot ещё не зарегистрировал | Исправьте имя. Для C# см. [Сущности на C#](../gameplay/csharp.md) |
| `alarm: res://entities/alarm.gd has no @tool` | Редактор запускает только tool-скрипты, поэтому ключи из карты никогда не доходят до узла | Добавьте `@tool` в начало скрипта |
| `light is a point entity, so its brushes are dropped` | `FuncGodotFGDPointClass` использован для браш-сущности | Сделайте определение `FuncGodotFGDSolidClass` |
| `func_door is a brush entity without brushes` | Браш-сущность, из которой нечего строить | Дайте ей браши или сделайте определение точечным классом |

## Сущности, которые строятся, но не реагируют { #entities-that-build-but-do-not-react }

| Что вы видите | Почему | Что сделать |
| --- | --- | --- |
| Триггеры никогда не срабатывают, а Output Godot говорит, что триггер проигнорировал вашего игрока, потому что ни один узел не состоит в его `filter_group` | По умолчанию триггеры реагируют только на тела в группе `player` на физическом слое 1 | Добавьте вашего игрока в группу `player`. Если он на другом слое, добавьте этот слой в *Trigger Collision Mask* в настройках карты |
| Двери и кнопки никогда не двигаются | Они двигаются, когда код вашей игры вызывает у них `use()` | См. [Пусть игрок нажмёт её](../tutorials/button-door.md#let-the-player-press-it) |
| `info_spawner` и `npc_walker` выглядят пустыми в редакторе Godot | Они создают или загружают свою модель только в запущенной игре | См. [Спавнеры и пути](../gameplay/entities/actors.md) |
| Output Godot показывает `Parse Error` для скрипта в `res://trenchdot/entities` | Godot скомпилировал скрипт пакета раньше, чем узнал используемые им классы | Перезапустите Godot, затем нажмите **Build Map** и сохраните |
