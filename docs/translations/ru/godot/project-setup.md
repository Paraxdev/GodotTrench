# Настройка проекта { #project-setup }

Настроек аддона по умолчанию хватает для первых карт. Когда вы начнёте писать собственные сущности или захотите другую папку с текстурами, дайте проекту его собственные ресурсы, потому что обновление аддона заменяет значения по умолчанию.

## Установка и обновление аддона { #installing-and-updating-the-addon }

Каждый раз при открытии проекта TrenchDot проверяет его аддон. Если `addons/func_godot` отсутствует или его версия отличается от версии редактора, один раз всплывает окно *Настройка проекта*, а жёлтая заметка остаётся внизу справа в строке состояния. Наведите на неё курсор, чтобы увидеть обе версии, и щёлкните, чтобы вернуть окно.

![Строка состояния с наведённой жёлтой заметкой «Аддон 0.0.9, редактор 0.1.0» и её подсказкой](../assets/project-setup/status-addon-mismatch.png)

Окно можно открыть и в любой момент через *Godot > Установить или обновить аддон…*.

![Меню Godot с наведённым пунктом «Установить или обновить аддон…»](../assets/project-setup/menu-install-update-addon.png)

Оно предлагает только тот шаг, который проекту нужен следующим:

| В проекте | Что предлагает окно |
| --- | --- |
| Нет аддона | **Установить аддон**, затем **Включить плагин** |
| Старый аддон | **Обновить аддон до** версии редактора |
| Более новый аддон или аддон без версии | **Заменить аддон на** версию редактора |
| Аддон не включён | **Включить плагин**, что добавляет его в `[editor_plugins]` в `project.godot` и больше ничего не меняет |
| Аддон как git checkout или подмодуль | Ничего. Обновляйте его через git, редактор никогда его не заменяет |

![Окно «Настройка проекта» сообщает, что аддон 0.0.9 старше редактора, с кнопкой «Обновить аддон до 0.1.0»](../assets/project-setup/setup-update-addon.png)

> [!WARNING]
> Закройте Godot перед обновлением. Он продолжает работать со старым аддоном, пока не перезапустится, поэтому кнопка остаётся серой, пока live link видит Godot с открытым проектом. Включайте плагин тоже при закрытом Godot, иначе Godot запишет обратно собственную копию `project.godot`. Отметить его в Godot в *Project > Project Settings > Plugins* тоже можно.

Старый аддон не удаляется, он переезжает в `.trenchdot/addon-backups/func_godot-<version>` в вашем проекте. Godot пропускает папки, имена которых начинаются с точки, поэтому не импортирует резервную копию и не показывает её как второй плагин. Удалите её, когда новый аддон заработает. (Примечание: загрузка сначала распаковывается и только потом подменяет аддон, так что неудавшееся или отменённое обновление оставляет старый аддон как был.)

Если загрузка не удалась, окно ссылается на [релизы](https://github.com/Paraxdev/TrenchDot/releases) и [itch.io](https://paraxdev.itch.io/trenchdot), где лежит тот же `func_godot-trenchdot-addon.zip`. Распакуйте его в папку проекта, чтобы получился `addons/func_godot`, и замените старую папку, а не распаковывайте поверх неё.

## Базовые сущности и пакет сущностей геймплея { #core-entities-and-the-gameplay-entities-pack }

Каждый проект получает от аддона небольшое ядро: worldspawn, `func_detail`, `func_illusionary`, `func_geo`, `light`, `light_spot`, `light_probe`, `env_reflection_probe`, `env_voxel_gi` и `info_player_start`.

Двери, кнопки, лифты, поезда, триггеры, логика, спавнеры, телепорты, путевые точки, пропы, эффекты и остальное из [справочника сущностей](../gameplay/entities/README.md) приходят как пакет сущностей геймплея. Вы устанавливаете его, когда он нужен, и он копируется в `res://trenchdot/entities`:

| Путь | Что содержит |
| --- | --- |
| `gameplay_fgd.tres` | Файл FGD пакета со списком всех определений |
| `definitions/` | По одному определению на сущность: её ключи, входы, выходы и гизмо редактора |
| `scripts/` | GDScript, который выполняет каждая сущность |
| `pack.json` | Что было установлено, чтобы обновления отличали ваши правки. Оставьте как есть |

Копии принадлежат вашему проекту. Меняйте скрипт или определение, удаляйте ненужные сущности или добавляйте свои определения в `gameplay_fgd.tres`. Сам аддон никогда не определяет эти имена классов и классы скриптов, поэтому ничто из сделанного там с ним не конфликтует, а обновление аддона этого не отменяет.

### Установка и обновление пакета { #installing-and-updating-the-pack }

1. Установите пакет

    Нажмите **Установить сущности геймплея** в окне *Настройка проекта*, под аддоном.

    ![Окно «Настройка проекта» с разделом сущностей геймплея и его кнопкой «Установить сущности геймплея»](../assets/project-setup/setup-gameplay-entities.png)

    Пока в проекте только ядро, та же кнопка находится вверху меню «Геймплей» и в панели «Сущности».

    ![Меню «Геймплей» с наведённым пунктом «Установить сущности геймплея» и его подсказкой](../assets/project-setup/menu-install-gameplay-entities.png)

2. Проверьте, что получилось

    Теперь окно должно сказать зелёным «Установлено в res://trenchdot/entities», а редактор сразу предлагает новые сущности.

    ![Раздел сущностей геймплея после установки, сообщающий, что добавлено 86 файлов в res://trenchdot/entities и что Godot нужно перезапустить, если проект в нём открыт](../assets/project-setup/setup-gameplay-installed.png)

    Когда редактор Godot держит проект открытым, TrenchDot просит его подхватить новые файлы, и окно об этом сообщает. Сцена в [живом режиме](live.md#when-live-mode-rebuilds-the-whole-map) тогда пересобирается сама. В остальных сценах, использующих ваши карты, нажмите **Build Map** и сохраните их, потому что они были собраны без пакета. Когда Godot не запущен или запущен со старым аддоном, окно говорит перезапустить Godot, если проект в нём открыт, затем собрать и сохранить эти сцены.

3. (По желанию) Обновите позже

    Когда обновление аддона приносит более новый пакет, окно предлагает **Обновить сущности геймплея**, а меню «Геймплей» показывает его с числом изменённых файлов. Ничего не обновляется, пока вы не нажмёте. Обновление добавляет новые файлы и заменяет те, которых вы не трогали. Файлы, которые вы правили, остаются как есть, и редактор называет их, а удалённые вами файлы остаются удалёнными.

Старые карты, сделанные до того, как сущности ушли из аддона, продолжают работать. Когда карты проекта используют сущности пакета, которые в проекте ничто не определяет, пакет устанавливается сам, и когда редактор открывает проект, и когда Godot запускается с обновлённым аддоном. Файл `.tdm` в любом случае хранит каждую сущность, с определением или без.

> [!NOTE]
> В шаблоне внутри аддона, `addons/func_godot/gameplay_pack`, лежит файл `.gdignore`, чтобы Godot его пропускал. Оставьте этот файл, иначе после установки Godot найдёт каждый класс скрипта пакета дважды.

### Какое определение побеждает { #which-definition-wins }

Базовый FGD, `res://addons/func_godot/fgd/trenchdot/trenchdot_fgd.tres`, сам читает установленный пакет, так что каждый FGD, построенный на значениях аддона по умолчанию, получает пакет, не перечисляя его. Когда два определения делят имя класса, побеждает более позднее, в таком порядке:

1. Классы FuncGodot и ядро аддона
2. Установленный пакет в `res://trenchdot/entities`
3. Сущности вашего собственного файла FGD

Чтобы изменить сущность, отредактируйте её копию в пакете или определите то же имя класса в своём FGD. Работают оба способа, но класс, определённый дважды, легко забыть, поэтому редактор сообщает об этом: при открытии проекта строка состояния называет побеждающее определение, а панель «Проблемы» предупреждает о каждом дважды определённом классе, который использует карта. Удалите одно из двух, чтобы разрешить это.

## Ваши собственные ресурсы { #your-own-resources }

Три ресурса работают вместе. Файл FGD перечисляет сущности, которые могут использовать ваши карты. Настройки карты говорят сборке, где лежат текстуры и какой FGD читать. Конфигурация игры сообщает TrenchDot об обоих, чтобы редактор предлагал при правке те же сущности и текстуры.

Быстрее всего скопировать `demo_fgd.tres`, `demo_map_settings.tres` и `demo_game_config.tres` из [`godot/demo`](https://github.com/Paraxdev/TrenchDot/tree/main/godot/demo) в свой проект и поправить пути. Чтобы сделать их самому, действуйте в редакторе Godot:

1. Создайте `FuncGodotFGDFile`. Задайте *Base Fgd Files* равным `res://addons/func_godot/fgd/trenchdot_default_fgd.tres`, чтобы сохранить ядро и установленный пакет, затем добавьте свои сущности в *Entity Definitions*. Без этой основы в вашем FGD их нет, и даже worldspawn собирается без коллизии.
2. Создайте `FuncGodotMapSettings`. Задайте *Entity Fgd* равным FGD из шага 1, а *Base Texture Dir* равным вашей папке с текстурами (по умолчанию `res://textures`). Новый ресурс настроек карты начинается с `trenchdot_default_fgd.tres`, в котором есть ядро и пакет, но нет ваших собственных сущностей.
3. Создайте `TrenchDotGameConfig`. Задайте его *Fgd File* и *Map Settings* равными двум ресурсам выше. (По желанию) задайте *Game Name*, редактор показывает его вверху справа на панели инструментов рядом с папкой проекта.
4. В *Project > Project Settings* направьте `func_godot/default_map_settings` на ваши настройки карты, а `trenchdot/game_config` на вашу конфигурацию игры. Ей следует каждый узел карты с пустым полем *Map Settings*. Узел, добавленный старым аддоном, хранил в этом поле значения аддона по умолчанию, так что очистите его там.

Редактор предлагает сущности из FGD конфигурации игры, но Godot собирает по FGD из настроек карты, поэтому держите их одинаковыми. Когда они различаются, Godot предупреждает в панели Output при каждом экспорте конфигурации игры, а панель «Проблемы» TrenchDot называет каждую сущность, которой нет в FGD, с которым собирает Godot.

> [!TIP]
> Задайте *Entity Name Property* в настройках карты равным `targetname`, как в демо. Тогда собранные узлы называются по их targetname, и дерево сцены остаётся читаемым.

## Конфигурация игры { #the-game-config }

TrenchDot узнаёт ваши сущности, папки с текстурами и масштаб единиц из `res://trenchdot_game.json`, который пишет конфигурация игры. Аддон экспортирует его заново, как только Godot замечает изменение файлов, а редактор перезагружает его в течение секунды. Экспорт также называет настройки карты по умолчанию и классы, которые определяет их FGD, благодаря чему редактор предупреждает о сущностях, которые Godot собрал бы без определения. Чтобы экспортировать вручную, выберите в Godot *Project > Tools > TrenchDot: Export Game Config* или запустите это без окна, например в CI:

```sh
godot --headless --path <project> --script res://addons/func_godot/src/trenchdot/export_game_config_cli.gd
```

## Настройки проекта { #project-settings }

Большинство проектов меняют только первую и третью. Настройки live link важны, когда порт уже занят другой программой.

| Настройка | По умолчанию | Назначение |
| --- | --- | --- |
| `func_godot/default_map_settings` | значения аддона по умолчанию | Настройки карты для каждой карты, у которой нет своих |
| `func_godot/default_inverse_scale_factor` | 32 | Единиц карты на метр |
| `trenchdot/game_config` | конфигурация аддона | Конфигурация, которая пишет `trenchdot_game.json` |
| `trenchdot/auto_export_game_config` | true | Экспортировать конфигурацию игры заново при изменении файлов |
| `trenchdot/live_link_enabled` | true | Запускать сервер live link, с которым говорит TrenchDot |
| `trenchdot/live_link_port` | 7842 | Должен совпадать с *Live Link с Godot* в настройках редактора. Изменения применяются сразу. От 1024 до 65535, любое другое значение откатывается к 7842 с предупреждением |
| `trenchdot/threaded_build` | true | Конвертировать браши и чанки террейна в WorkerThreadPool, чтобы большие карты собирались быстрее |
| `trenchdot/live_chunk_size` | 16.0 | В живом режиме геометрия worldspawn делится на чанки такого размера в метрах, так что правка пересобирает только свой чанк |
| `trenchdot/csharp_entity_dirs` | `res://` | Где при сборке ищутся сущности на C# |
