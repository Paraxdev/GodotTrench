# Сборка карт { #building-maps }

TrenchDot сохраняет файл `.tdm` и сам никогда не пишет сцены Godot. В Godot узел аддона `FuncGodotMap` читает этот файл и создаёт меши, коллизию и узлы сущностей. Результат сохраняется вместе с вашей сценой, как любой узел, собранный вручную, так что во время игры ничего не пересобирается, пока вы сами этого не попросите.

## Узел FuncGodotMap { #the-funcgodotmap-node }

1. Добавьте узел

    В редакторе Godot нажмите Ctrl+A в вашей сцене, найдите `FuncGodotMap` и добавьте его.

2. Укажите ему карту

    Выделив узел, задайте в Инспекторе Godot *Local Map File*, выбрав сохранённый `.tdm`.

3. Соберите

    Нажмите **Build Map** вверху Инспектора. Карта должна появиться во вьюпорте Godot, а у узла появятся дочерние узлы для мешей и сущностей. Сохраните сцену через Ctrl+S, чтобы они остались. **Clear Map** убирает их снова.

Вот настройки, которые вы видите в Инспекторе:

| Свойство | Что делает |
| --- | --- |
| Local Map File | Путь `res://` к `.tdm`, который нужно собрать. Это обычный выбор. |
| Global Map File | Файл карты вне проекта. Если заданы оба, побеждает этот. |
| Auto Rebuild On Save | Пересобирает узел всякий раз, когда TrenchDot сохраняет эту карту, пока её сцена остаётся текущей вкладкой в редакторе Godot, см. [Пересборку при сохранении](live.md#rebuild-on-save). По умолчанию включено. |
| Map Settings | Откуда берутся текстуры, материалы и определения сущностей и какого размера единица карты. Если поле пустое, берётся настройка проекта `func_godot/default_map_settings`, см. [Настройку проекта](project-setup.md). Узел карты, добавленный старым аддоном, хранил здесь настройки карты по умолчанию от аддона, и его сборка предупреждает об этом в Output Godot, очистите поле, чтобы следовать настройке проекта. |
| Use Baked Lighting | Освещает карту светом, [запечённым в редакторе](baked-lighting.md). По умолчанию включено, снимите галочку, чтобы использовать другой лайтмаппер. |
| Warm Up Shaders | Компилирует шейдеры карты во время загрузки, чтобы первые секунды игры не подлагивали. См. [Прогрев шейдеров](warm-up.md). |

Аддон собирает только файлы `.tdm`. Чтобы использовать `.map` из Quake или `.vmf` из Hammer, сначала откройте его через *Файл > Импорт* в TrenchDot и сохраните как `.tdm`.

> [!WARNING]
> Сборка удаляет всех потомков узла карты, кроме [оверлеев](overlays.md). Держите свои узлы рядом с узлом карты или в оверлее.

## Три способа сборки { #three-ways-to-build }

| Запуск | Что собирается | Когда использовать |
| --- | --- | --- |
| Сохранение в TrenchDot | Каждый `FuncGodotMap`, использующий этот файл, в сцене, открытой в редакторе Godot | Повседневный цикл: сохранить и посмотреть результат в Godot |
| *Godot > Собрать в Godot* | Карта такой, какая она в TrenchDot прямо сейчас, сохранённая или нет, без записи файла | Чтобы попробовать несохранённое изменение в Godot, ничего не фиксируя |
| **Build Map** в Godot | Сохранённый файл | Когда TrenchDot закрыт или нужно пересобрать только что открытую сцену |

Первые два требуют редактор Godot с открытым этим проектом и затрагивают только открытую там сцену. Пересборка помечает эту сцену как изменённую, так что сохраните её в Godot, чтобы оставить результат.

Пока Godot не открыл проект, *Собрать в Godot* остаётся серым. Ещё ему нужно, чтобы карта была один раз сохранена в проект, чтобы Godot знал, какой `FuncGodotMap` её использует.

## Сборка из кода { #building-from-code }

Карту можно собрать и во время игры, например чтобы загрузить уровень, выбранный в меню:

```gdscript
var map := FuncGodotMap.new()
map.map_settings = load("res://demo/demo_map_settings.tres")
map.local_map_file = "res://demo/maps/scripted_scene.tdm"
add_child(map)
map.build()
```

Узел посылает `build_complete`, когда закончил, или `build_failed`, когда файла карты нет или это не `.tdm`.

## Окружение и солнце { #environment-and-sun }

Ключи неба, тумана и солнца у worldspawn строят в карте `WorldEnvironment` и свет с именем `sun`, так что карта выглядит освещённой без всякой настройки в Godot. Нажмите Escape, чтобы ничего не было выделено, и Инспектор покажет *Карта (worldspawn)* со списком этих ключей. Ключ `environment` выбирает, что будет построено. Ключ, который вы оставили незаданным, в карту не попадает, так что карта без этих ключей вообще не строит окружение. Если в проекте, сделанном старым аддоном, этих ключей в списке нет, обновите аддон и [экспортируйте конфигурацию игры](project-setup.md#the-game-config) заново.

| `environment` | Строит |
| --- | --- |
| `1` | Окружение и солнце. Это значение по умолчанию. |
| `sun_only` | Только солнце, для игры, которая приносит свой `WorldEnvironment` |
| `0` или `none` | Ничего |

Если в сцене уже есть собственный `WorldEnvironment` или `DirectionalLight3D`, карта оставляет его и своих не добавляет, так что игра со своим видом всегда побеждает. Когда одна сцена общая у нескольких карт, освещает её та, что построилась первой.

## Отчёт о сборке { #build-report }

`build()` возвращает Dictionary, который также хранится в `build_report`. Он сообщает, сколько длился каждый шаг, сколько сущностей каждого класса построено и сколько вершин у карты. Полезнее всего список того, что сборка не нашла, обычно это опечатка или файл, который переименовали или так и не закоммитили:

| Ключ | Что перечисляет | Что вы видите в игре |
| --- | --- | --- |
| `missing_classes` | Классы сущностей, которые не описывает ни одно определение сущности | Браш-сущность сохраняет меш, но без скрипта и коллизии, точечная сущность это пустой `Marker3D`, см. [Сущности, которые ничего не делают](entities-troubleshooting.md) |
| `missing_models` | Пути моделей, которых не существует, с сущностями, использующими каждый | У пропса нет модели |
| `missing_materials` | Текстуры граней, для которых нет ни файла материала, ни изображения | Грани показывают текстуру-заглушку |
| `unknown_tool_textures` | Служебные текстуры вроде `special/clip`, которые настройки карты называют иначе | Грани по-прежнему ничего не рисуют, но браш origin не задаёт начало координат своей сущности |
| `unresolved_targets` | Выходы и ключи target, цель которых не совпадает ни с одним targetname в карте или её оверлеях | Выход срабатывает в никуда |

Чтобы печатать его после каждой сборки, отметьте *Print Build Report* в *Build Flags* на узле или добавьте в коде `FuncGodotMap.BuildFlags.PRINT_REPORT` к `build_flags`. Тест или проверка в CI могут вместо этого прочитать Dictionary:

```gdscript
var report := map.build()
if not report["missing_models"].is_empty():
	push_error("missing models: %s" % [report["missing_models"]])
```

Каждая сборка также печатает в Output Godot предупреждение о том, что не нашла: одно на все отсутствующие классы и по одному на каждую отсутствующую модель, материал или служебную текстуру, сколько бы пропсов ни делили путь. После сохранения TrenchDot показывает те же предупреждения в своей панели «Проблемы».

> [!NOTE]
> Оверлеи, которые вы добавляете после `build()`, ещё не существуют, когда отчёт ищет цели, поэтому их targetname попадают в `unresolved_targets`.

## Повреждённые карты { #damaged-maps }

Повреждённая карта всё равно собирается из частей, которые удалось прочитать, с предупреждением `[TDM]` для каждой части, которую не удалось. См. [формат карты .tdm](../format/recovery.md).
