# Навигация { #navigation }

`TrenchDotNav` запекает навигационный меш из собранной карты, чтобы враги и NPC могли находить в ней дорогу.

```gdscript
map.build()
var region := await TrenchDotNav.bake_region(map)
```

`bake_region` запекает в рабочем потоке, добавляет под карту узел `NavigationRegion3D` с именем `navigation` и возвращается, когда пути по нему уже работают. Передайте узел, в котором лежит несколько карт, чтобы запечь их все в один меш. Пересборка освобождает регион, так что после неё запеките заново.

## Что учитывается { #what-counts }

Запекание читает коллизию карты, а не её меши, поэтому агент обходит всё, обо что может удариться игрок.

| В карте | В навигационном меше |
| --- | --- |
| Мировые браши, `func_detail`, коллизия террейна и пропов | Да |
| Клип-браши | Да, они блокируют как стены |
| Иллюзорные браши, триггеры и физические пропы | Нет |
| Двери, кнопки, платформы и поезда | Нет, поэтому закрытая дверь не запечатывает проём |
| Тела в группе `navigation_ignore` | Нет |

Это значит, что пути ведут сквозь закрытые двери, и агенту нужно открыть дверь, в которую он упирается.

## Размер агента { #agent-size }

`TrenchDotNav.profile(radius, height, max_climb, max_slope)` выдаёт настройки для одного размера агента. Радиус держит пути подальше от стен, высота исключает низкие потолки, *max_climb* это самая высокая ступень, на которую агент поднимается, а *max_slope* самый крутой пандус. Размеры задаются в метрах, уклон в градусах:

| Аргумент | По умолчанию |
| --- | --- |
| `radius` | 0.3 |
| `height` | 1.8 |
| `max_climb` | 0.3 |
| `max_slope` | 45 |

Меш использует ячейки по 0,1 м и округляет размеры до них. Передайте профиль вторым аргументом, например для широкого низкого существа:

```gdscript
var region := await TrenchDotNav.bake_region(map, TrenchDotNav.profile(0.5, 1.2))
```

(`bake_region` задаёт размер ячейки навигационной карты по запеканию, и другие регионы на этой карте обязаны его разделять.)

## Кэш { #caching }

Первое запекание большой карты занимает несколько секунд. Результат кэшируется в `user://trenchdot_navigation` по ключу из коллизии и настроек, поэтому при следующем запуске с той же картой он загружается за долю секунды. Передайте `false` третьим аргументом, чтобы запечь без кэша.

## Проверка карты { #checking-a-map }

`TrenchDotNav.bake(map)` запекает в вызывающем потоке и возвращает `NavigationMesh`, что удобно для инструментов и тестов. `TrenchDotNav.islands(nav)` перечисляет его несвязные части как индексы полигонов, самые большие первыми.

Комната, которая должна быть достижимой, но лежит на собственном острове, обычно имеет проём, перекрытый чем-то низким, или ступень выше `max_climb`. Верхушки стен и пол внутри толстых стен тоже появляются как маленькие острова.

> [!WARNING]
> Godot прекращает поиск пути после 4096 полигонов и возвращает путь, найденный к этому моменту, что на большой карте выглядит как недостижимое место. У `TrenchDotNav.path(node, from, to)` ограничения нет. Для агентов задайте `path_search_max_polygons` у `NavigationAgent3D` равным 0.

## Как это выглядит в TrenchDot { #seeing-it-in-trenchdot }

Где ходит агент, видно прямо в TrenchDot, не запуская игру.

1. Откройте сцену в Godot

    Сохраните карту внутри проекта и откройте проект в редакторе Godot со сценой, в которой `FuncGodotMap` собирает эту карту.

2. Включите проходимую зону

    Выберите пункт *Вид > Проходимая зона > Показать проходимую зону*. Размер агента находится сразу под ним, а нижняя строка сообщает, сколько зоны проходимо и сколько островов отрезано.

    ![Меню «Вид» с открытым подменю «Проходимая зона»: Показать проходимую зону, затем Радиус 0.30 м, Высота 1.80 м, Макс. подъём 0.30 м, Макс. уклон 45.00 градусов и «Ещё не запечено»](../assets/navigation/menu-walkable-area.png)

Godot запекает сцену по [live link](live-link.md), и TrenchDot рисует результат в 3D и 2D видах. (Если запечь не удаётся, строка состояния говорит почему, например что карту сначала нужно сохранить в проекте.)

Цвета означают следующее:

| Цвет | Значение |
| --- | --- |
| Голубовато-зелёный | Самая большая связная область, где окажется большинство агентов |
| Киноварный | Острова, до которых агент с зелёной области не доберётся. Ищите ступень выше *Макс. подъём*, зазор уже двух *Радиус* или уклон круче *Макс. уклон* |

Оверлей снова запекается через мгновение после каждой правки. Без [живого режима](live.md) Godot сначала собирает карту в том виде, как она показана, как при *Собрать в Godot*.

> [!TIP]
> Верхушки стен и крыш видны как маленькие киноварные острова. Ищите киноварный пол рядом с зелёным.

## MCP { #mcp }

[Сервер MCP](../mcp.md) позволяет агентам и скриптам управлять редактором. Карту они проверяют инструментом `walkability`, который возвращает острова с их площадями и границами в единицах карты.
