# Сохранение, живой режим и горячая перезагрузка { #saving-live-mode-and-hot-reload }

## Пересборка при сохранении { #rebuild-on-save }

Держите сцену с вашим `FuncGodotMap` открытой в редакторе Godot и просто сохраняйте в TrenchDot через Ctrl+S. Godot тут же пересобирает эту сцену, пока её вкладка та, что показывает Godot, а у узла карты включён *Auto Rebuild On Save*. Сцена на другой вкладке, использующая карту, пересобирается, когда вы переключитесь на её вкладку. Закрытие и повторное открытие вкладки или перезагрузка сцены этому не мешают. Сохранение [префаба](../editor/prefab-library.md) пересобирает карты этой сцены, которые его используют, напрямую или через другой префаб.

Что сделал Godot, сообщает строка состояния внизу слева. Если всё получилось, она должна сказать следующее:

![Строка состояния с текстом «Живая связь: Godot пересобрал узлов карты: 1»](../assets/live/status-rebuilt.png)

Сохраните сцену в Godot, чтобы сохранить результат. Если строка состояния говорит что-то другое, сообщение объясняет почему:

![Строка состояния с сообщением, что room.tscn использует room.tdm, но не является текущей вкладкой сцены в Godot и пересоберётся при переключении на неё](../assets/live/status-not-current-tab.png)

| Строка состояния говорит | Сделайте так |
| --- | --- |
| Сцена не является текущей вкладкой сцены в Godot | Переключитесь на эту вкладку, тогда она пересоберётся |
| На текущей вкладке сцены нет `FuncGodotMap` для карты | Откройте сцену, которая собирает карту, или включите *Auto Rebuild On Save* у её узла карты |
| В Godot нет открытой сцены | Откройте в Godot сцену с картой, а если она открыта, читайте дальше |
| Godot запущен без аддона TrenchDot | Откройте проект в редакторе Godot с включённым аддоном |
| Godot пересобрал карту, но в настройках карты нет определения для некоторых классов, поэтому они собираются как обычные узлы | Добавьте определения, см. [Сущности, которые ничего не делают](entities-troubleshooting.md) |
| Godot пересобрал карту с предупреждениями, см. панель «Проблемы» | Прочитайте их на панели «Проблемы», где они начинаются с «Godot:» |

Порт live link может занимать только один редактор Godot. Второй редактор с тем же проектом предупредит в своей панели Output, что live link не удалось слушать, а TrenchDot продолжит говорить с первым, у которого может не быть открытой сцены. Закройте редактор, которым не пользуетесь, и другой подхватит связь в течение нескольких секунд. (Примечание: *Godot > Открыть проект в редакторе Godot* выводит на передний план редактор, в котором проект уже открыт, вместо запуска второго.)

## Живой режим { #live-mode }

Живой режим отправляет ваши правки в сцену, открытую в редакторе Godot, до сохранения, так что освещение и масштаб можно оценить в настоящем рендерере.

1. Откройте сцену в Godot

    Карту нужно один раз сохранить внутри проекта, а в сцене, открытой в Godot, нужен `FuncGodotMap`, который её использует.

2. Включите его

    Щёлкните кнопку-звено на правом краю панели инструментов, рядом с роботом Godot, или выберите *Godot > Живой режим*. Кнопка загорится, а её подсказка скажет, чего она ещё ждёт, если ждёт.

    ![Панель инструментов с включённой кнопкой живого режима и её подсказкой о том, что правки доходят до Godot до сохранения](../assets/live/toolbar-live-mode-on.png)

3. Правьте как обычно

    Каждое изменение сразу появляется в Godot.

    ![Правки в TrenchDot появляются в редакторе Godot до сохранения](../screenshots/TrenchDot-demo-live-view.gif)

Живому режиму нужен live link с Godot, он включён по умолчанию. Оба находятся в *Файл > Настройки*, где *Живой режим Godot* это тот же переключатель, что и кнопка на панели инструментов.

![Строки «Live Link с Godot», «Живой режим Godot» и «Горячая перезагрузка запущенной игры» в настройках](../assets/live/prefs-live-link.png)

Перетаскивание двигает узлы прямо во время перетаскивания, а большинство правок пересобирает только то, чего они коснулись, так что предпросмотр успевает за вами. Переключение *Omit From Export* у слоя и правка экземпляров префабов вместо этого пересобирают всю карту, когда вы делаете паузу.

Предпросмотр близок к полной сборке, но не всегда идентичен. Сохранение всегда делает полную сборку, а выход без сохранения возвращает Godot к сохранённому файлу, так что ничего из испробованного в живом режиме не закрепится, пока вы не сохраните.

### Когда живой режим пересобирает всю карту { #when-live-mode-rebuilds-the-whole-map }

Godot сам пересобирает всю карту, когда сцена перестала совпадать с тем, что дала бы полная сборка. Если живой режим включается на сцене, это происходит сразу, иначе когда вы делаете паузу в правках:

| Когда | Почему |
| --- | --- |
| Живой режим включается на сцене, собранной с другими определениями сущностей | Сцена была собрана до того, как вы установили пакет сущностей геймплея или добавили определение, так что некоторые сущности это обычные узлы |
| Живой режим включается на сцене, которую изменили более ранние живые правки | В сцене всё ещё лежат живые правки прежнего сеанса, которые вы не сохранили |
| Определения сущностей меняются, пока работает живой режим | Вы сохранили FGD или определение в Инспекторе Godot, изменился класс скрипта или пришли новые файлы, например установленный пакет |
| Вы сохраняете префаб, который использует карта | Сцена всё ещё показывает префаб таким, каким он был |

Сцены, открытые вне живого режима, хранят сущности такими, какими их собрали, и панель Output в Godot предупреждает, когда одна из них была собрана с другими определениями сущностей. Нажмите в ней **Build Map** и сохраните.

### Сущности без определения { #entities-without-a-definition }

Когда живой режим собирает сущность, для класса которой в Godot нет определения, строка состояния называет класс и FGD, в который его нужно добавить:

![Строка состояния с сообщением, что у Godot нет определения для crypt_lamp, он показывает обычный узел, добавьте класс в FGD из res://crypt_settings.tres](../assets/live/status-no-definition.png)

Подсказка кнопки живого режима хранит ту же заметку, пока карта использует этот класс:

![Включённая кнопка живого режима, её подсказка о том, что правки доходят до Godot до сохранения и что у Godot нет определения для crypt_lamp](../assets/live/toolbar-live-mode-no-definition.png)

Добавьте определение и сохраните его, и Godot сам пересоберёт карту. Заметка исчезнет при вашем следующем сохранении. О том, куда кладётся определение, см. [Сущности, которые ничего не делают](entities-troubleshooting.md).

## Горячая перезагрузка в запущенной игре { #hot-reload-in-a-running-game }

Чтобы видеть ваши сохранения в уже запущенной игре:

1. Добавьте автозагрузку

    В Godot откройте *Project > Project Settings > Globals > Autoload* и добавьте этот скрипт:

    ```
    res://addons/func_godot/src/trenchdot/runtime/trenchdot_hot_reload.gd
    ```

2. Запустите игру из редактора Godot

    Автозагрузка слушает только в играх, запущенных из редактора Godot, если только вы не задали её `enabled_in_exported_builds` равным true.

3. Сохраните в TrenchDot

    Игра пересоберёт карты, использующие сохранённый файл, и испустит `map_reloaded(map)`. Используйте этот сигнал, чтобы вернуть игрока в точку появления или сбросить состояние игры. Строка состояния должна закончиться словами «запущенная игра перезагрузила карт: 1».

Она слушает порт 7843, который должен совпадать с *Горячей перезагрузкой запущенной игры* в настройках редактора. TrenchDot отправляет ей сохранения, только пока live link включён.
