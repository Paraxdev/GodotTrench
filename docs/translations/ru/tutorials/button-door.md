# Кнопка открывает дверь { #button-opens-a-door }

Кнопка на стене, которая сдвигает дверь, когда игрок её нажимает. Это самый маленький полезный кусочек entity I/O:
кнопка запускает выход `pressed`, а связь превращает его в вызов входа `open` у двери.

> [!TIP]
> Если выходы, входы и `targetname` вам пока незнакомы, сначала прочитайте [Как работает entity I/O](../gameplay/io.md).
> Это займёт пару минут, а эта страница опирается на неё.

## Соедините их { #wire-it }

`func_door` и `func_button` входят в пакет сущностей геймплея. Если в вашем проекте его ещё нет, выберите
*Геймплей > Установить сущности геймплея* или нажмите **Установить сущности геймплея** в окне *Настройка проекта*
(*Godot > Установить или обновить аддон…*).

1. Сделайте дверь

    Нарисуйте браш размером с дверь в дверном проёме, как вырезать проём, показано в разделе [Первые шаги](../getting-started.md#4-build-a-room).
    Щёлкните по брашу правой кнопкой мыши и выберите *Создать браш-сущность > func_door*.

    ![Контекстное меню на оранжевом браше двери: открыт пункт «Создать браш-сущность», выделен func_door](../assets/button-door/create-brush-entity-func-door.png)

2. Дайте ей имя

    В Инспекторе справа впишите `main_door` в `targetname`. По этому имени другие сущности находят дверь.
    Оставьте `travel` равным `0 64 0`, тогда при открытии дверь поедет вверх на 64 единицы (2 м).

    ![Инспектор func_door с targetname main_door и travel 0 64 0](../assets/button-door/inspector-targetname.png)

3. Сделайте кнопку

    Нарисуйте маленький браш на стене рядом с дверью и таким же способом превратите его в `func_button`.

4. Выделите обе

    Щёлкните по кнопке, затем по двери с зажатым Ctrl, в виде или в Структуре слева. Мешают стены? Впишите `func` в поле
    *Фильтр* вверху Структуры, и в списке останутся только эти две.

    ![Структура, отфильтрованная по func, func_door (main_door) и func_button выделены обе](../assets/button-door/outliner-filter-func.png)

5. Свяжите их

    Выберите *Геймплей > Логика > Связать две выбранные сущности…* или нажмите **Связать…** вверху Инспектора.

    ![Меню «Геймплей» с открытым подменю «Логика», выделен пункт «Связать две выбранные сущности…»](../assets/button-door/menu-link-two-selected.png)

    Сущность, которая запускает выход, должна стоять слева, здесь это кнопка. Диалог ставит слева ту, что вы создали
    первой, то есть дверь, поэтому нажмите маленькую кнопку обмена между двумя именами. Выберите `pressed` в поле
    *Когда* и `open` в поле *вызвать*, затем нажмите **Связать**.

    ![Окно «Связать сущности»: слева func_button, справа func_door (main_door), Когда pressed, вызвать open](../assets/button-door/link-dialog.png)

В строке состояния внизу слева теперь должно быть написано `pressed > main_door.open`. Читайте это как «когда pressed,
вызвать open у main_door».

![Строка состояния с надписью pressed > main_door.open](../assets/button-door/status-linked.png)

Если выделить одну кнопку, связь найдётся в её Инспекторе в разделе *Выходы*, там её позже можно изменить или удалить.

![Раздел «Выходы» у func_button: выход pressed, цель main_door, вход open](../assets/button-door/inspector-button-output.png)

> [!TIP]
> *Геймплей > Двери и подвижные части*, он же в разделе *Геймплей* Инспектора, одним щелчком превращает выделенный
> браш в распашную или сдвижную дверь. Он даёт двери имя, настраивает, как она открывается, и ставит перед ней
> `trigger_multiple`, который открывает дверь, когда игрок подходит. Удалите этот триггер, если дверь должна
> открываться только кнопкой.
>
> ![Меню «Геймплей» с открытым подменю «Двери и подвижные части»: распашная дверь с левой или правой петлёй, сдвижная дверь вверх или вбок, Лифт, подвижная платформа](../assets/button-door/menu-doors-and-movers.png)

## Дайте игроку нажать её { #let-the-player-press-it }

У аддона нет собственной системы взаимодействия, ведь в каждой игре «использовать» работает по-своему. У дверей и кнопок
есть метод `use(activator)`, и его вызывает скрипт вашего игрока. Демо-игрок делает это по **E**: он пускает луч из
камеры и вызывает `use` у первого, во что попал, если у него есть такой метод
([godot/demo/player.gd](https://github.com/Paraxdev/TrenchDot/blob/main/godot/demo/player.gd)):

```gdscript
func use_target() -> void:
	var from := camera.global_position
	var query := PhysicsRayQueryParameters3D.create(from, from - camera.global_basis.z * use_distance)
	query.exclude = [get_rid()]
	query.collide_with_areas = false
	var hit := get_world_3d().direct_space_state.intersect_ray(query)
	var node: Node = hit.get("collider")
	while node:
		if node.has_method(&"use"):
			node.call(&"use", self)
			return
		node = node.get_parent()
```

Игрок передаёт себя как активатор, поэтому `pressed(activator)` несёт игрока дальше. Следующие выходы в цепочке могут
указывать целью `!activator`, чтобы действовать на того, кто нажал кнопку.

## Вариации { #variations }

| Чего вы хотите | Что изменить |
| --- | --- |
| Дверь открывается только кнопкой | Снимите галочку `interact` у двери. Иначе нажатие **E** на двери тоже её откроет |
| Дверь закрывается сама | Задайте в `wait` у двери, сколько секунд она остаётся открытой. По умолчанию -1, то есть дверь остаётся открытой |
| Запертая дверь | Поставьте галочку `locked`. Дверь игнорирует `open` и `use` и вместо этого запускает `locked_use`, пока какой-нибудь выход не вызовет её вход `unlock`, например от подбора ключа |
| Одна кнопка, несколько дверей | Назовите двери `gate_1`, `gate_2` и так далее и укажите целью `gate_*`. Завершающая `*` подходит под любое имя, начинающееся с `gate_` |
| Распашная дверь | Возьмите `func_door_rotating` и перетащите в виде её ручку петли туда, где должна быть петля |

## То же самое в коде { #the-same-wiring-in-code }

Хотите соединять всё в GDScript, а не в редакторе? Вот то же, что делает связь выше:

```gdscript
# pressed(activator) > main_door.open
button.pressed.connect(func(activator):
	for door in TrenchDotIO.find_targets(button, "main_door", activator):
		TrenchDotIO.invoke(door, &"open", "", activator))
```

Подключить `pressed` прямо к `door.open` не получится, потому что `pressed` передаёт один аргумент, а `open()` не принимает
ни одного. `invoke` подгоняет аргументы под метод, так же, как это делают связи карты.
