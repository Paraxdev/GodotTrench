# Скриптовая кат-сцена { #scripted-cutscene }

Игрок заходит в комнату, появляется подсказка, проводник уходит, бочка взрывается, зажигается лампа и открывается
выход. Собственного кода для этого не нужно: сущность-таймер запускает по одному выходу на каждый такт, а каждый выход
связан с сущностью, которая должна подействовать. Найти это можно в демо-проекте, это карта `scripted_scene`.

![Карта scripted_scene в панели «Логика»: start_zone запускает cutscene.start, выходы step у cutscene идут к проводнику, бочке и подсказке, а выход broken бочки идёт к hp_readout. Лампа и выходная дверь ниже, за пределами картинки](../assets/cutscene/logic-graph.png)

## Таймлайн { #the-timeline }

Все сущности здесь входят в пакет сущностей геймплея. Если в вашем проекте его ещё нет, сначала установите его через
*Геймплей > Установить сущности геймплея*.

1. Закройте вход

    Нарисуйте браш поверх входа и сделайте его `trigger_once` с именем `start_zone` (правый щелчок, *Создать
    браш-сущность > trigger_once*). Он запускает `triggered`, когда игрок входит впервые, а потом сам выключается,
    поэтому сцена проигрывается только один раз.

2. Добавьте таймлайн

    Выберите `logic_sequence` в *Геймплей > Логика*, он появится у 3D-курсора. Назовите его `cutscene`, задайте `steps`
    равным 5 и `interval` равным 1.5. После запуска он по очереди запускает `step_1`, `step_2` и так далее с
    промежутком 1,5 секунды.

    ![Меню «Геймплей» с открытым подменю «Логика», под заголовком «Поместить у курсора» выделен logic_sequence](../assets/cutscene/menu-logic-sequence.png)

3. Запустите его из триггера

    Свяжите выход `triggered` у `start_zone` с `cutscene.start` через *Геймплей > Логика > Связать две выбранные
    сущности…*, как в уроке [Кнопка открывает дверь](button-door.md).

4. Подключите каждый такт

    Свяжите каждый выход step у `cutscene` с сущностью, которая действует в этот такт, по одной паре за раз. Можно
    и протянуть связь от пина выхода к пину входа в [панели «Логика»](../gameplay/logic-graph.md).

| Выход | Цель и вход | Что происходит |
| --- | --- | --- |
| `step_1` | `hint.show` | `game_text` показывает «Следуй за проводником» |
| `step_2` | `guide.start` | `npc_walker` отправляется по цепочке `path_corner`, это ряд маркеров, каждый из которых называет следующий |
| `step_3` | `barrel.ignite` | Взрывоопасная `prop_physics` горит по запалу, потом взрывается и разлетается |
| `step_4` | `lamp.turn_on` | Лампа включается |
| `step_5` | `exit_door.open` | Выходная дверь уезжает вверх |

Выделите `cutscene`, и в её Инспекторе в разделе *Выходы* должны быть все пять.

![Инспектор logic_sequence с именем cutscene: steps 5, interval 1.5 и Выходы (I/O, 5), первый из которых step_1 к hint.show](../assets/cutscene/inspector-sequence.png)

Последовательность ждёт перед каждым шагом, перед первым тоже, поэтому шаг 1 срабатывает на 1,5 с, а шаг 5 на 7,5 с.
Для неравномерных пауз задайте в `times` по одному ожиданию на шаг, например `0.5 2 1 1 3`.

## Чтение здоровья игрока { #reading-the-players-health }

Некоторым реакциям нужна небольшая логика, которую не покрывает ни один встроенный вход. `logic_script` выполняет
короткий фрагмент GDScript, когда его запускают. Свяжите выход `broken` бочки с `hp_readout.run`, это `logic_script`,
чей `source` выводит здоровье игрока на HUD-`game_text` с именем `hpmsg`:

```gdscript
var players = io.find_targets(this, "!player", null)
if players.is_empty():
	return
var hp = int(players[0].health)
for label in io.find_targets(this, "hpmsg", null):
	label.set_text("HP " + str(hp))
	label.show()
```

Здесь нужен `!player`, а не `!activator`. `!activator` это тот, кто запустил цепочку, а выходы step и `broken` никого не
несут. `!player` всегда находит узел в группе `player`. `broken` срабатывает после того, как взрыв уже нанёс урон,
поэтому здоровье уже актуально.

## Запуск { #playing-it }

Скрипт сцены,
[godot/demo/scenes/scripted_scene.gd](https://github.com/Paraxdev/TrenchDot/blob/main/godot/demo/scenes/scripted_scene.gd),
только собирает карту, создаёт игрока в `info_player_start` и добавляет `TrenchDotDebugOverlay`. Нажмите **F3** в игре,
чтобы смотреть, как срабатывает каждый выход. Это самый быстрый способ найти шаг, связанный не с тем именем.
