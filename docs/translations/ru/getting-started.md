# Первые шаги { #getting-started }

Шаги с 1 по 3: первая настройка. Если у вас уже есть проект Godot, настроенный для TrenchDot, их можно пропустить.

Шаги 4 и 5: создание первой комнаты в TrenchDot и просмотр её в Godot.

## Что вам понадобится { #what-you-need }

* Godot 4.7 или новее, сборка .NET, если вы хотите писать сущности на C#
* Свежий [релиз TrenchDot](https://github.com/Paraxdev/TrenchDot/releases/tag/beta)

## Убедитесь, что TrenchDot видит исполняемый файл Godot { #ensure-trenchdot-can-see-the-godot-executable }

Убедитесь, что TrenchDot видит вашу установку Godot. Чтобы проверить, всё ли определилось правильно, откройте
*Файл > Настройки… > Исполняемый файл Godot*.

Если TrenchDot нашёл Godot сам, строка под полем ввода уже говорит «Используется» и показывает путь. Если там вместо
этого написано «Не найден», исполняемый файл нужно найти на диске.

Для этого нажмите кнопку «…» рядом с полем ввода

![Кнопка … рядом с полем ввода исполняемого файла Godot](assets/getting-started/godot-path-browse.png)

и найдите исполняемый файл, имя которого начинается с «Godot_v».

Если вы выбрали правильный файл, там должно быть написано «Используется» и только что выбранный путь.

![Строка под полем ввода с надписью «Используется» и путём к исполняемому файлу Godot](assets/getting-started/godot-path-using.png)

## 1. Создайте проект в Godot { #1-create-a-project-in-godot }

Откройте Godot и нажмите «Create» в левом верхнем углу.

![Менеджер проектов Godot, кнопка Create со значком плюса в левом верхнем углу](assets/getting-started/godot-create-project.png)

Выберите имя проекта, для этого урока пусть это будет TrenchDotTest, и (по желанию) папку, в которой он будет лежать.

Затем нажмите «Create».

## 2. Открытие проекта в TrenchDot { #2-opening-the-project-within-trenchdot }

Выберите *Godot > Открыть проект Godot…*

![Меню Godot в TrenchDot с выделенным пунктом «Открыть проект Godot…»](assets/getting-started/menu-open-godot-project.png)

или кнопку **Открыть проект Godot…** справа вверху на панели инструментов

![Кнопка «Открыть проект Godot…» справа вверху на панели инструментов TrenchDot, которая показывает имя проекта, когда он открыт](assets/getting-started/toolbar-open-godot-project.png)

и выберите папку проекта или любую папку внутри него. При следующем запуске редактор откроет его снова.

## 3. Окно приветствия { #3-the-welcome-screen }

Когда TrenchDot понимает, что это новый проект Godot, он показывает окно «Настройка проекта».

![Окно «Настройка проекта» с разделами про аддон, сущности геймплея и готовый контент](assets/getting-started/setup-window.png)

Здесь можно скачать аддон, который Godot нужен, чтобы превращать ваши карты в сцены и общаться с TrenchDot, и, если
хотите, дополнительный контент. Можно, конечно, начать и без всего этого.

Несколько простейших сущностей входят всегда, например простые `info_player_start` и `light`.

1. Установите аддон

    Нажмите кнопку «Установить аддон» сверху, чтобы скачать форк FuncGodot от TrenchDot в ваш проект, это
    необходимо для TrenchDot.
    (Примечание: он загружается из релизов на GitHub. Если у вас нет доступа в интернет, сначала скачайте
    `func_godot-trenchdot-addon.zip` и распакуйте его в корень проекта, чтобы установить аддон вручную.)

    Сделав это, нажмите «Включить плагин», чтобы Godot его загрузил.
    (Примечание: сначала закройте Godot, если у него открыт проект, иначе Godot запишет обратно свою копию
    `project.godot`, и плагин останется выключенным.)

2. Установите сущности геймплея

    Нажмите **Установить сущности геймплея** под аддоном.

    ![Раздел сущностей геймплея в окне «Настройка проекта» с кнопкой «Установить сущности геймплея»](assets/getting-started/setup-gameplay-entities.png)

    В этот пакет входят двери, кнопки, лифты, триггеры, пропсы и спавнеры. Без него Godot строит их как обычные
    фигуры без коллизии, которые ничего не делают. Помощники для дверей и триггеров в меню «Геймплей» сами ставят пакет
    при первом использовании, но если установить его сейчас, до первого открытия проекта в Godot, ни одна сцена не
    будет собрана без него.

3. (По желанию) Дополнительный контент

    У TrenchDot есть необязательный контент, который можно загрузить заранее: текстуры и модели CC0 с Poly Haven и
    ambientCG, а также модели, сделанные для TrenchDot. Лицензии и список источников всего этого прилагаются.

    Если дополнительный контент вам не нужен, выберите «Ничего лишнего», минимальные сущности всё равно войдут.

4. Один раз откройте проект в Godot

    Когда плагин включён, откройте проект в Godot (для этого в окне есть кнопка «Открыть проект в редакторе Godot»).
    Тогда аддон создаст в корне проекта файл `trenchdot_game.json`. Из него TrenchDot узнаёт о ваших текстурах и
    сущностях и загружает его в течение секунды.

    Аддон записывает его заново при каждом изменении файлов, так что править его вручную не нужно. Пока файла нет,
    строка состояния сообщает, что `trenchdot_game.json` отсутствует, а редактор предлагает основные сущности и, если
    вы их установили, сущности геймплея.

Чтобы добавить собственные сущности, смотрите [Собственные сущности на GDScript](gameplay/custom-entities.md) и
[Сущности на C#](gameplay/csharp.md). [Настройка проекта](godot/project-setup.md) объясняет ресурсы, которые их
перечисляют.

## 4. Постройте комнату { #4-build-a-room }

В редакторе 4 основных вида: 3D-вид, по которому можно летать, как в Godot, и 3 каркасных вида сверху, спереди и
сбоку.

Браши и операции зависят от размера сетки. На панели инструментов можно задать размер сетки (чем меньше, тем мельче).

![Настройка размера сетки на панели инструментов, выставлено 16](assets/getting-started/toolbar-grid-size.png)

На пустом уровне вам покажут небольшой текст с объяснением, как рисовать. Его можно скрыть кнопкой «Скрыть подсказки»
или просто начать рисовать, он пропадёт, как только на карте что-то появится.

![Новая карта: карточка в 3D-виде предлагает тянуть в виде сверху, чтобы нарисовать первую коробку, а в виде сверху стоит жёлтая надпись «Тяните здесь, чтобы нарисовать первую коробку»](assets/getting-started/empty-map.png)

1. Нарисуйте первую коробку

    Инструментом «Выделить» (Q) потяните по пустому месту в любом виде.
    Вы должны увидеть, как рисуется коробка. Не отпуская левую кнопку, двигайте мышь, чтобы задать прямоугольник.

    ![Все четыре вида с нарисованной первой коробкой, вид сверху показывает её размер, 512 на 256](assets/getting-started/draw-first-box.png)

2. Добавьте высоту

    В виде сбоку наведите мышь на верхнее ребро коробки, пока оно не станет жёлтым, зажмите левую кнопку и
    двигайте мышь вверх, пока коробка не станет высотой 256 единиц.

    ![Вид сбоку с верхним ребром коробки, вытянутым вверх, над ним и рядом с ним напечатано 256](assets/getting-started/side-view-depth.png)

3. Сделайте её полой

    Нажмите Ctrl+Shift+K или кнопку «Сделать полым» на панели инструментов.

    ![Панель инструментов с наведённой кнопкой «Сделать полым» и её подсказкой](assets/getting-started/toolbar-hollow.png)

    Теперь коробка разделена на стены, пол и потолок, это оптимально, если вы хотите сделать небольшую комнату или
    коридор. Теперь, управляя полётом (удерживайте правую кнопку мыши и пользуйтесь WASD), влетите внутрь полой коробки.

4. Прорежьте дверной проём

    Клавишей Escape можно снять выделение с выбранных брашей. Когда ничего не выбрано, нарисуйте в виде спереди внутри
    коробки прямоугольник поменьше, вертикальный, в форме дверного проёма.

    ![Браш двери внутри полой коробки, 64 в ширину и 96 в высоту в виде спереди](assets/getting-started/doorway-brush.png)

    Затем в виде сбоку вытяните одну сторону браша двери, чтобы у него появилась глубина, насквозь через всю стену.

    ![Перетаскивание одной стороны браша двери в виде сбоку, чтобы он пересёк стену](assets/getting-started/doorway-extend.gif)

    Теперь, с выбранным брашем, нажмите Ctrl+K или кнопку «Вычесть» на панели инструментов.

    ![Панель инструментов с наведённой кнопкой CSG «Вычесть» и её подсказкой](assets/getting-started/toolbar-subtract.png)

    Вы должны увидеть, как браш исчезает, а в стене вырезан дверной проём.

    ![Стена в 3D-виде с вырезанным дверным проёмом](assets/getting-started/doorway-cut.png)

5. Наложите текстуру

    У вас должно быть 5 встроенных текстур для прототипирования. Чтобы наложить текстуру только на одну грань
    (например, на дверную раму), перетащите текстуру с вкладки «Материалы» на грань (удерживайте Shift, чтобы
    покрыть весь браш).

    ![Перетаскивание dev/blue с вкладки «Материалы» на грань, виден предпросмотр сброса](assets/getting-started/texture-drop.png)

6. Сохраните карту

    Чтобы увидеть изменения в Godot, карту нужно сохранить. Нажмите Ctrl+S или выберите *Файл > Сохранить*.

    Диалог сохранения открывается в папке вашего проекта Godot. Сохраните карту где угодно внутри проекта, папка
    `maps` в корне проекта помогает держать порядок, например `res://maps/room.tdm`.
    (Примечание: имя папки за вами, но держите карту внутри проекта, чтобы Godot мог загрузить её по пути `res://`.)

    После сохранения она появится в *Файл > Карты проекта*.

    ![Меню «Файл» с пунктами «Сохранить» и «Карты проекта», который перечисляет room в res://maps](assets/getting-started/file-menu-maps-in-project.png)

## 5. Посмотрите её в Godot { #5-see-it-in-godot }

В Godot уровень это сцена: дерево узлов, сохранённое как файл `.tscn`, где каждый узел это что-то одно, например меш,
свет или камера. Godot записывает пути внутри проекта через `res://`, так что `res://maps/room.tdm` это файл
`maps/room.tdm` в папке вашего проекта. В узлы карту превращает один узел из аддона, `FuncGodotMap`.

1. В редакторе Godot выберите *Scene > New Scene* и нажмите **3D Scene** на панели Scene слева.
2. Нажмите Ctrl+A (*Add Child Node*), найдите `FuncGodotMap` и добавьте его.
3. Выбрав новый узел, задайте *Local Map File* на ваш `.tdm` в собственном Инспекторе Godot, это панель справа в
   редакторе Godot. Он работает как Инспектор в TrenchDot, но принадлежит Godot.
4. Нажмите **Build Map** вверху этого Инспектора, затем сохраните сцену клавишами Ctrl+S.

Браши становятся мешами с коллизией, а сущности становятся узлами со своими скриптами, и всё это сохраняется со сценой.
[Сборка карт](godot/building.md) объясняет остальные настройки узла. Если сущность получилась голым мешем без
коллизии, строка состояния TrenchDot скажет почему, смотрите [Сущности, которые ничего не делают](godot/entities-troubleshooting.md).

Оставьте эту сцену открытой в Godot, и каждое сохранение в TrenchDot будет её пересобирать, сразу, пока её вкладка
текущая, или когда вы вернётесь на неё. Сохраните сцену в Godot, чтобы закрепить результат. Если после сохранения
пересборки нет, строка состояния говорит почему, смотрите [Пересборка при сохранении](godot/live.md#rebuild-on-save).

> [!WARNING]
> Сборка сначала удаляет дочерние узлы `FuncGodotMap`. Размещайте свои узлы рядом с узлом карты или в
> [оверлее](godot/overlays.md).

## Попробуйте демо-проект { #try-the-demo-project }

Папка `godot` в репозитории, она же в релизе как `trenchdot-demo-project.zip`, это проект с установленным аддоном. Его
главная сцена проигрывает демонстрационные карты, которые лежат в `godot/demo/maps/showcase`. Откройте проект в
редакторе и выберите одну из них в *Файл > Карты проекта*, чтобы увидеть, как собрана законченная карта.

Демо-вариант в *Godot > Добавить контент в проект…* кладёт те же карты и сцены в ваш собственный проект. В Godot
откройте `res://demo/demo.tscn` и нажмите F6, чтобы их проиграть. Открытые в TrenchDot из вашего проекта, они
показываются без текстур, потому что используют папку текстур демо `res://demo/textures`, а не вашего проекта.
Демо-проект показывает их такими, какими они были построены.

| Клавиша | Действие |
| --- | --- |
| WASD, Space, Shift | Идти, прыгать, бежать |
| E | Использовать двери и кнопки |
| От 1 до 5 | Переключаться между демонстрационными картами |
| F3 | Показать оверлей отладки I/O, журнал каждого входа и выхода в момент срабатывания, с нарисованными триггерными объёмами |

## Дальше { #next }

Чтобы комната что-то делала, прочитайте [Как работает entity I/O](gameplay/io.md) и постройте
[Кнопка открывает дверь](tutorials/button-door.md).

Вашему игроку для сущностей из пакета нужны две вещи. Триггеры реагируют только на тела из группы Godot `player` на
физическом слое 1, так что поместите игрока туда. Двери и кнопки двигаются, когда код вашего игрока вызывает `use()` у
той, на которую он смотрит, смотрите [Дайте игроку нажимать](tutorials/button-door.md#let-the-player-press-it).

## MCP { #mcp }

Вопрос о контенте не открывается сам в редакторе, которым управляет MCP-клиент: первый вызов инструмента, кроме
`get_state`, `screenshot` и `simulate_input`, закрывает его, а проект, открытый через `open_project`, об этом не
спрашивают. `project_content` добавляет тот же контент, смотрите [MCP](mcp.md).
