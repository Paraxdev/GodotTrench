# Скрипты MCP { #mcp-scripts }

Скрипт MCP это файл JSON со списком вызовов инструментов [MCP](mcp.md), а `run_script` воспроизводит их по порядку.
Он хранит, как была построена карта, в виде читаемых шагов, так что вы можете собрать карту с нуля и просмотреть её как
текст в pull request, а тесты тоже могут её воспроизвести.

Демонстрационные карты в [examples/mcp](https://github.com/Paraxdev/TrenchDot/tree/main/examples/mcp) построены именно
так, и заодно служат примерами для каждого инструмента.

| Скрипт | Что строит |
| --- | --- |
| `mountain_house.json` | Хижина, нависшая над обрывом, с подъёмником на утёсе и лесами |
| `church_school.json` | Церковь и школа, где три кнопки открывают ворота двора |
| `lighthouse_forest.json` | Маяк с вращающимся огнём, лодка на `func_train` и появляющиеся огоньки |
| `withered_city.json` | Разрушенный неоновый город ночью с молнией, свечением и `ssr` |
| `night_district.json` | Промышленная улица ночью с рольставнями и поездом на виадуке |
| `sea_island.json` | [Учебник по острову в море](tutorials/sea-island.md) |
| `scripted_scene.json` | [Учебник по кат-сцене](tutorials/cutscene.md) |
| `logic_playground.json` | Зал для [узлов математики и логики](gameplay/entities/logic.md): монеты, счёт, вентиль на двери хранилища и световая лотерея |

## Запуск { #running-them }

Запустите редактор с демонстрационным проектом и его HTTP-сервером, см. [Запуск](mcp.md#starting-it), затем
воспроизведите скрипт через `tools/mcp_script.py`. Если редактор запрашивает [токен](mcp.md#the-http-token), передайте
его через `--token` или `TRENCHDOT_MCP_TOKEN`. Его команда `shot` сохраняет скриншот с заданной вами позиции камеры, а
`--shade` выбирает затенение:

```sh
trenchdot --mcp-http --project godot                        # the editor with the demo project
python tools/mcp_script.py run examples/mcp/sea_island.json   # replay a script
python tools/mcp_script.py shot view.png --pos 4300,900,3300 --look 2200,700,1200 --shade lit
```

Скрипты сохраняются в `godot/demo/maps/showcase`, кроме `scripted_scene.json` и `logic_playground.json`, которые
сохраняются в `godot/demo/maps`.

Запуск останавливается на первом неудавшемся шаге, если не передать `--continue-on-error`, а `--url` направляет исполнитель
на редактор на другом порту. Каждый запуск это один шаг отмены в каждой карте, которую он меняет, с именем из `label`
скрипта или из имени его файла.

## Формат скрипта { #script-format }

```json
{
  "format": "trenchdot-mcp-script",
  "label": "Hollow room",
  "vars": { "save_dir": "${project}/maps" },
  "steps": [
    { "note": "A hollow room." },
    { "tool": "map_file", "args": { "op": "new" } },
    { "tool": "create_brush", "args": { "min": [0, 0, 0], "max": [256, 128, 256] }, "save": "room" },
    { "tool": "select", "args": { "ids": "$room.ids" } },
    { "tool": "run_action", "args": { "action": "csg_hollow" } },
    { "tool": "map_file", "args": { "op": "save", "path": "${save_dir}/room.tdm" } }
  ]
}
```

`vars` задаёт значения по умолчанию для ваших переменных. Объект `vars`, переданный в `run_script`, переопределяет их,
так что один скрипт может сохранять в разные места, а папки, переданные таким образом, это те, из которых скрипту можно
читать и в которые можно писать.

Шаг без `tool` это комментарий. Шаг с `save` сохраняет свой результат под этим именем, чтобы последующие шаги могли
использовать созданные им идентификаторы.

Скриптами делятся так же, как картами, поэтому их шаги только правят и сохраняют карту. Шаг не может открыть другой
проект или одну из его карт, запустить Godot, собирать в нём, включить живой режим, отключить MCP, скопировать или
вырезать в буфер обмена, отбросить несохранённые изменения или закрыть другие вкладки. Отмена и повтор достают только до
того, что сделал сам скрипт, поэтому несохранённая работа остаётся в каждой вкладке. `screenshot`, `simulate_input`,
`walkability` и `run_script` тоже нельзя запускать внутри скрипта, как и установки `project_content`, кроме `gameplay`.

Каждый файл, который шаг читает или записывает, должен находиться в открытом проекте, в папке самого скрипта или в папке,
которую вы передали в `vars`, и даже когда ссылка внутри них указывает в другое место. Это относится к картам, которые он
открывает, проверяет, сравнивает, сохраняет и экспортирует, к картам, моделям, префабам и текстурам, которые он
импортирует вместе с файлами, которые они называют, и ко всему, что записывают преобразования, импорт, экспорт и
библиотека префабов. Префабы, файлы моделей, текстуры и экземпляры Hammer, которые карта или модель называет в другом
месте, остаются в стороне, сетевые пути отклоняются раньше, чем редактор на них посмотрит, а сохранение без пути
записывает обратно только в ту карту, которая была открыта при запуске скрипта.

Правило действует и для файлов материалов, их изображений и файлов хотспотов, библиотеки префабов и пресетов природы.
Текстура, файлы которой лежат вне этих папок, внутри скрипта считается отсутствующей, поэтому её подгонка или
выравнивание откатывается к размеру текстуры по умолчанию. После этого итог перечисляет файлы, которые не удалось
прочитать, в `unread_textures`.

Отклонённый шаг появляется в `errors` итога с причиной. Итог считает вызовы инструментов как `steps`, а комментарии как
`notes`.

Строки в `args` могут ссылаться на сохранённые результаты и несколько встроенных переменных:

| Запись | Значение |
| --- | --- |
| `"$name.path"` | Сохранённое значение JSON. Числа индексируют массивы, как в `$room.ids.0` |
| `"${name.path}"` | Его текст внутри более длинной строки |
| `"$a.ids + $b.ids"` | Оба, объединённые в один массив. `["$a.ids", "$b.ids"]` тоже работает |
| `$last` | Результат предыдущего шага |
| `$project` | Папка открытого проекта Godot, ошибка, если ни один не открыт |
| `$script_dir` | Папка файла скрипта |
| `$$` | Буквальный `$`, поэтому путь узла записывается как `"$$Player"` |

Неизвестное имя это ошибка. Знак `$`, с которого не может начинаться имя, как в `"$5"`, остаётся как есть.
Идентификаторы, заданные текстом, например `"42"`, работают везде, где ожидается идентификатор узла.

`$name/rest` без фигурных скобок не раскрывается, поэтому `$project/maps` без скобок это ошибка, а не путь, который никто
не собирался писать. Используйте `"${project}/maps"`.

## Идентификаторы после CSG { #ids-after-csg }

Шаги CSG и обрезки заменяют браши, которые они режут, новыми с новыми идентификаторами. Исполнитель переписывает
идентификаторы, сохранённые прежними шагами, чтобы они соответствовали, поэтому `"$wall.ids"` по-прежнему означает всю
стену после того, как вы прорезали в ней окно, а удалённый браш выпадает из списка.

Переписываются только значения под ключами, которые несут идентификаторы узлов: `id`, `ids`, `selection`, `selected`,
`nodes`, `letters`, `copies`, `entity`, `group`, `parent`, `insert_parent`, `current_layer`, `open_groups`, `targets` и
ключи, оканчивающиеся на `_id` или `_ids`. Счётчики, такие как `moved` из `hierarchy reparent`, остаются как есть,
используйте вместо них его `ids`.

> [!TIP]
> Явно задавайте каждую настройку кисти в вызовах `scatter` и `blend`. Всё пропущенное берётся из текущих настроек панели
> Разброс или инструмента смешивания в редакторе.
