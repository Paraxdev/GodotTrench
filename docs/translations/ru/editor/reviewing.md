# Просмотр изменений { #reviewing-changes }

Храните карты в git, и вы сможете смотреть, что изменилось между двумя версиями, так же, как вы проверяете код. Для изменений внутри текущей сессии [панель «История»](organizing.md#history) перечисляет каждую правку и откатывает назад к любой из них.

## Карты в git { #maps-in-git }

Файлы `.tdm` двоичные, но git всё равно умеет показывать читаемые диффы. Он просит редактор напечатать каждую версию как JSON и сравнивает их. Настроить это нужно один раз:

1. Добавьте эту строку в `.gitattributes` вашего проекта:

    ```
    *.tdm binary diff=tdm
    ```

2. Скажите git, как печатать карту, один раз для каждого клона:

    ```sh
    git config diff.tdm.textconv "trenchdot --dump"
    ```

3. (По желанию) уберите резервные копии и автосохранения из репозитория этими строками в `.gitignore`:

    ```
    *.tdm.bak
    *.tdm.autosave
    ```

Теперь `git diff` и `git log -p` должны показывать изменения карт как JSON, а не просто сообщать, что двоичные файлы отличаются.

> [!WARNING]
> `trenchdot` должен быть в вашем `PATH`, иначе `git diff` на картах завершится ошибкой.

Чтобы получить этот JSON файлом, выполните `trenchdot --to-json map.tdm map.json`, а `trenchdot --to-tdm map.json
map.tdm` превратит его обратно в двоичную карту. См. [Командную строку](../command-line.md).

## MCP { #mcp }

Инструменты просмотра в MCP показывают, что ИИ-агент сделал с вашей картой.

### Правки ИИ-агента { #edits-made-by-an-ai-agent }

Когда агент правит вашу карту через [MCP](../mcp.md), каждый вызов инструмента становится одним шагом отмены с названием `MCP: ...` на [панели «История»](organizing.md#history). Целый `run_script` тоже один шаг, например `MCP: Add crates, 6 steps`. Отмените этот шаг, чтобы забрать работу агента обратно.

![Панель «История»: сверху MCP: Add crates, 6 steps, ниже правки, сделанные вручную, такие как Rename, Group и Hollow](../assets/reviewing/history-mcp-script.png)

| Что посмотреть | О чём просить агента |
| --- | --- |
| Что изменилось с последнего сохранения | `changes_since`, он перечисляет добавленные, удалённые, перемещённые и иначе изменённые узлы |
| Что изменил его последний вызов или скрипт | `changes_since` с `undo_steps: 1` |
| Что изменилось с коммита git | `changes_since` с `file`, указывающим на ту версию, которую можно получить командой `git show HEAD:maps/level.tdm > old.tdm` |

> [!TIP]
> Попросите агента уложить многошаговую работу в один `run_script` с `label`, тогда вся работа отменяется одним шагом под понятным вам названием.
