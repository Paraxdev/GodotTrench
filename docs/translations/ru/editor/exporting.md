# Экспорт в Blender и другие 3D-инструменты { #exporting-to-blender-and-other-3d-tools }

Вид вашей карты можно сохранить одним файлом 3D-модели: браши, меши, ландшафт и модели вместе с текстурами внутри. Удобно, чтобы отрендерить уровень в Blender, собрать кадр для трейлера или передать заготовку художнику, который построит поверх неё финальные меши.

> [!WARNING]
> Экспортируются только геометрия и материалы. Логика сущностей, связи I/O, триггеры, скрипты и игровое поведение остаются за бортом, а файл нельзя снова открыть в TrenchDot как карту. Картой остаётся `.tdm`, продолжайте править его.

## Шаги { #steps }

1. Откройте экспорт

    Выберите *Файл > Экспорт > glTF Binary (.glb) для Blender и других 3D-программ…* или наберите «glTF» в палитре команд (Ctrl+Shift+P или F1).

    ![Меню «Файл» с открытым «Экспорт» и наведённым курсором на glTF Binary (.glb) для Blender и других 3D-программ](../assets/exporting/menu-export.png)

2. Выберите, что включить

    Откроется окно *Экспорт для 3D-инструментов*. Отметьте нужное, см. [параметры](#options) ниже. Числа рядом с *Модели пропсов* и *Экземпляры разброса* показывают, сколько объектов добавляет каждый пункт. Формат можно переключить на OBJ вверху.

    ![Окно «Экспорт для 3D-инструментов»: выбран glTF Binary, «Вся карта», отмечены «Модели пропсов (5)», не отмечены «Экземпляры разброса (4081)»](../assets/exporting/export-dialog.png)

3. Сохраните

    Нажмите **Экспортировать…** и выберите, куда положить файл. Экспорт идёт в фоне с окном прогресса, поэтому можно продолжать править, а **Отмена** останавливает его, ничего не записав. Когда он закончится, в строке состояния будет сказано, сколько объектов, материалов и треугольников вышло.

4. Откройте в Blender

    Выберите *File > Import > glTF 2.0 (.glb/.gltf)* и укажите файл. Значения по умолчанию подходят, импортёр сам поворачивает модель осью Z вверх.

Файл содержит карту такой, какой она была, когда вы нажали **Экспортировать…**. Несохранённые изменения сначала автосохраняются, если только автосохранение не выключено в *Файл > Настройки*. Если в строке состояния назван материал, для которого в проекте нет изображения, он выйдет без текстуры.

## Параметры { #options }

| Параметр | Что делает |
| --- | --- |
| Вся карта, Только выделенное | Всё или только выделенные объекты, по-прежнему внутри своих слоёв и групп |
| Скрытые слои и объекты | Экспортирует и то, что скрыто в видах. Выключено, вы получаете то, что видите |
| Модели пропсов | Модели, которые показывают пропсы и другие точечные сущности, на своём месте, с их поворотом и масштабом |
| Экземпляры разброса | Каждое дерево, камень и пучок травы из [наборов разброса](scatter.md) отдельным объектом. По умолчанию выключено, потому что тысячи таких объектов дают большой файл, который медленно открывается |
| Точечные сущности как пустые маркеры | Пустой объект с именем сущности там, где стоит каждая точечная сущность без модели, удобно для расстановки света или камер в Blender |
| Объединить безымянные браши | Браши, которые вы не переименовали, сливаются в один объект на слой, группу или сущность, это сокращает Outliner в Blender. Именованные браши остаются отдельными |

## Что экспортируется { #what-is-exported }

| В карте | В файле |
| --- | --- |
| Слои и группы | Пустые родительские объекты с теми же именами, так что структура из панели «Структура» переносится |
| Браши | По одному объекту, названному как в «Структуре», `brush12` или данным вами именем |
| Браш-сущности вроде дверей и лифтов | Родительский объект с именем сущности, в котором лежат её браши, там, где они стоят в редакторе |
| Меши, декали | По одному объекту. Декали получают смешанные двусторонние материалы |
| Ландшафт | Один объект. Каждый треугольник берёт текстуру самого сильного из нарисованных слоёв, поэтому нарисованные переходы выглядят ступенчатыми |
| Экземпляры префабов | Содержимое префаба на своих местах, под объектом с именем экземпляра |
| Материалы | По одному на материал с его текстурой альбедо, плюс карты нормалей, шероховатости, металличности, ambient occlusion и излучения, если они есть. Вырезанные и прозрачные материалы сохраняют альфу, пиксель-арт остаётся резким. Встроенные цвета для разработки выходят своими текстурами с сеткой |

В файл не попадает то, что сборка Godot не рисует: грани со служебными текстурами (clip, skip, origin, sky, trigger, nodraw, hint), грани, скрытые другим брашем, триггеры и прочие объёмные сущности и слои с включённым пунктом *Пропуск при экспорте*. Свет, звуки, точки появления, небо и туман тоже не экспортируются.

Грани друг у друга скрывают только объекты, которые попадают в файл. Поэтому колонна, экспортированная с *Только выделенное*, сохраняет низ, которым стоит на полу, а слой с включённым пунктом *Пропуск при экспорте* не оставляет дыр у соседей.

## Единицы и оси { #units-and-axes }

Один метр в Godot это один метр в Blender. Единицы карты делятся на число единиц проекта в метре, 32, если настройки карты не говорят иное. Файл с осью Y вверх, как в Godot, этого и ждёт glTF. У каждого браша, меша и ландшафта начало координат в центре его габаритов, а модели сохраняют начало координат файла модели.

## Когда нужен OBJ { #when-to-use-obj }

*Файл > Экспорт > Файл Wavefront OBJ (.obj)…* нужен для инструментов, которые не читают glTF. Он записывает три вещи рядом, например `level.obj`, `level.mtl` с материалами и папку `level_textures` с копиями текстур. Держите их вместе, когда переносите. В Blender используйте *File > Import > Wavefront (.obj)*.

В OBJ нет родительских объектов и нельзя разделить один меш между копиями, поэтому каждый объект записывается плоско в мировых координатах, а каждый экземпляр разброса становится полной копией. Если отмечены экземпляры разброса, окно предупреждает, когда они в сумме дают миллион треугольников, и сообщает, насколько большим выйдет файл. Экспорт OBJ откажется принимать больше 10 миллионов треугольников, это файл больше гигабайта. Материалы сохраняют текстуры альбедо, нормалей, шероховатости и излучения. Выбирайте glTF всегда, когда другой инструмент его читает.

В файле `.glb` помещается не больше 4 ГБ. glTF записывает каждую модель один раз, сколько бы экземпляров разброса её ни показывало, так что до такого размера дорастёт только огромная карта, и тогда экспорт скажет об этом, а не запишет битый файл.

## Командная строка { #command-line }

`trenchdot --export-glb <map> <out.glb>` и `--export-obj <map> <out.obj>` экспортируют с параметрами по умолчанию, не открывая окно. Проект Godot для карты находится по её папке. См. [Командную строку](../command-line.md).

## MCP { #mcp }

`map_file {op: export_glb, path}` записывает `.glb`, а `map_file {op: export_obj, path}` записывает `.obj` вместе с `.mtl` и папкой текстур, из открытой карты как она есть, сохранённой или нет. Параметры задаются флагами: `selection_only`, `hidden`, `scatter`, `models` (true, если не задан), `markers` и `merge_brushes`. Результат перечисляет `objects`, `meshes`, `materials`, `images`, `triangles`, `bytes` и `missing_textures`. `run_action` отказывается от `export_glb` и `export_obj`, потому что пункты меню открывают диалог файла.
