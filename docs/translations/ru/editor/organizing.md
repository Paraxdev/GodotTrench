# Организация карты { #organizing-a-map }

Когда карта разрастается, хочется разложить её по частям, находить нужное и хранить переиспользуемые куски в одном месте. Почти всё это начинается в Структуре, панели слева.

## Слои { #layers }

Структура показывает карту как дерево из слоёв, групп и объектов. Слои позволяют разбить карту на части, например по зданию на слой, чтобы скрыть или заблокировать часть, пока вы работаете над остальным.

Нажмите **Добавить слой** вверху Структуры, чтобы создать новый, он сразу становится текущим слоем. Новые объекты попадают в текущий слой, отмеченный *(текущий)*, а щелчок по слою делает его текущим. Глаз перед строкой скрывает её, замок не даёт её выделять и править.

Наведите курсор на строку, и увидите материалы, размер и границы. Объект обводится во всех видах сразу, так что вы поймёте, какая стена `brush7`.

![Структура с открытым слоем House и строкой brush7 под курсором, подсказка показывает её материал, размер и границы, а в 3D-виде и виде спереди задняя стена обведена](../assets/organizing/outliner-hover.png)

Браши и меши перечисляются по виду и номеру, например `brush12` или `mesh40`, так что стены, которые остаются после «Сделать полым» или «Вычесть», можно различить. Номер не меняется при перемещении объекта и между сохранениями.

### Имена { #naming-things }

Выделите объект и нажмите F2 или щёлкните по нему правой кнопкой в Структуре либо в виде и выберите *Переименовать*. Строка превратится в текстовое поле. Enter сохраняет имя, Escape отменяет, а пустое имя возвращает имя по умолчанию.

![Строка браша в Структуре превратилась в текстовое поле с набранным «front wall»](../assets/organizing/outliner-rename.png)

Имена сохраняются вместе с картой. У сущностей `targetname` хранится отдельно от этого имени, так что переименование никогда не меняет, до чего доходит выход. Куски, оставшиеся после отсечения, операции CSG или преобразования, сохраняют имя, а имя объекта внутри связанной группы получают все её копии.

(Слои, группы и наборы разброса всегда сохраняют имя, поэтому для них пустое имя ничего не меняет. Переименование набора разброса переименовывает и слой, который создал для него инструмент «Разброс».)

### Выбор объектов в Структуре { #picking-objects-in-the-outliner }

Ctrl+щелчок по строке добавляет её в выделение или убирает. Shift+щелчок выделяет все строки между последней, по которой вы щёлкали, и этой, а Ctrl+Shift+щелчок добавляет этот диапазон к уже выделенному. В Структуре часто проще выбирать объекты, которые в видах спрятаны за другими.

### Как оставить слой за пределами Godot { #keeping-a-layer-out-of-godot }

Для справочной геометрии, которая не должна попадать в игру, щёлкните правой кнопкой по её слою и выберите *Переключить пропуск при экспорте*. После этого у слоя после названия появится *[пропущен]*. Скрыть мало, Godot всё равно строит скрытые объекты.

![Меню правого щелчка слоя Blockout reference с наведённым курсором на «Переключить пропуск при экспорте»](../assets/organizing/layer-menu-omit.png)

## Группы { #groups }

Группа держит объекты вместе, чтобы они выделялись и двигались как один, например браши стола. Всё о группах находится в *Правка > Группы*.

![Меню «Правка» с открытым «Группы» и наведённым курсором на «Дублировать со связью»](../assets/organizing/menu-groups.png)

| Ввод | Результат |
| --- | --- |
| Ctrl+G, Ctrl+Shift+G | Сгруппировать выделение, разгруппировать его |
| Щелчок | Выделить объект внутри группы |
| Двойной щелчок | Выделить всю группу |

**Дублировать со связью** (Ctrl+Shift+D) создаёт копию, которая остаётся синхронной с оригиналом, так что поправив одну оконную раму, вы поправите все. Связанные копии показывают в Структуре *(linked)*, а щелчок по одной выделяет всю группу, поскольку её копии правятся как одно целое. *Правка > Группы > Разорвать связь групп* разрывает связь, когда одна копия должна отличаться.

## Префабы { #prefabs }

Для кусков, которые вы используете в разных картах, выделите их и выберите *Правка > Префабы > Создать из выделения…*. Выделение сохранится отдельным `.tdm`, а на его место встанет экземпляр. Каждый экземпляр обновляется, когда файл префаба меняется.

![Меню «Правка» с открытым «Префабы» и наведённым курсором на «Создать из выделения…»](../assets/organizing/menu-prefabs.png)

> [!NOTE]
> Один раз сохраните карту, прежде чем создавать префаб. Пути префабов хранятся относительно карты, поэтому редактор откажется, пока у карты нет файла.

Для кусков, которые вы вставляете один раз, а потом свободно меняете, используйте вместо этого [библиотеку префабов](prefab-library.md).

Если поставить префаб дважды, у двух сущностей будет одинаковый targetname. Это решает fixup экземпляра: при fixup `p1` каждое имя внутри получает этот префикс, так что `door` становится `p1-door`, и у каждой копии связи остаются отдельными. Файл карты и сборка Godot fixup знают, но поля, где его задать, в редакторе пока нет.

## Кордон { #cordon }

Кордон сжимает редактор до одной части большой карты.

1. Выделите то, над чем хотите работать.
2. Выберите *Вид > Кордон > Задать кордон по выделению* или нажмите **Кордон** в Инспекторе.

    ![Меню «Вид» с открытым «Кордон» и наведённым курсором на «Задать кордон по выделению»](../assets/organizing/menu-cordon.png)

3. Всё, что не касается жёлтой рамки вокруг выделения, теперь скрыто и не выделяется, а в строке состояния написано *cordon*.

    ![До: вся карта с домом, лужайкой, садовой стеной, колонной и высоким справочным блоком. После: только дом внутри жёлтой рамки и касающаяся его лужайка](../assets/organizing/cordon-before-after.png)

*Вид > Кордон > Кордон включён* выключает и снова включает его, а *Убрать кордон* убирает совсем. Кордон сохраняется вместе с картой.

Он меняет только то, что показывает редактор, Godot всё равно строит всю карту. Чтобы передать одну область другому инструменту, *Файл > Экспорт > .map, только кордон…* записывает лишь объекты внутри неё.

## Проблемы { #issues }

Панель «Проблемы», вкладка рядом со Структурой и Историей, проверяет карту, пока вы работаете. Она перечисляет неполадки, из-за которых в Godot что-то сломается или будет выглядеть неправильно, например браши без объёма, грани без материала или выходы, нацеленные на targetname, которого ни у кого нет.

![Панель «Проблемы» с ошибкой про отсутствующую цель, тремя предупреждениями про дубликат браша, сущность без определения и две грани с z-fighting, и информационной строкой про пустую группу, у большинства есть кнопка «Исправить»](../assets/organizing/issues-panel.png)

Щёлкните проблему, чтобы выделить объект и показать его в кадре. У многих есть кнопка **Исправить**, а **Исправить все** в заголовке исправляет всё, что может.

Предупреждение, что грань перекрывает грань другого браша в той же плоскости, значит, что в Godot они будут мерцать. Сдвиньте одну грань с плоскости или обрежьте перекрытие.

Предупреждение, что модели не существует, значит, что в `model` пропса назван файл, которого нет, поэтому проп строится без меша. Если есть файл с тем же именем и другим расширением, например `chair.gltf` вместо `chair.glb`, предупреждение называет его.

Предупреждение, что что-то запускает GDScript из карты, значит, что в карте есть собственный код, который выполняется, как только сцена запускается в Godot. Такое предупреждение появляется для каждого `logic_script` с `source` или `expression`, для каждого выхода или `logic_call`, который может передать им код, например выхода, отправляющего им `source`, и для каждого префаба, содержащего что-то из этого. Прочитайте их, прежде чем запускать чужую карту.

Предупреждения, начинающиеся со слова «Godot», приходят от последней сборки в Godot, после сохранения или *Собрать в Godot*: это классы, которые собрались без своего определения, и прочие предупреждения этой сборки. См. [Сущности, которые ничего не делают](../godot/entities-troubleshooting.md).

## История { #history }

Панель «История» перечисляет каждую правку, самая новая сверху. Щёлкните старую запись, чтобы откатиться до неё, включая саму запись. Отменённые правки остаются приглушёнными над *текущей*, щёлкните одну из них, чтобы вернуть всё до неё.

![Панель «История» с приглушёнными Rename и Group над маркером текущего состояния и записью Hollow под курсором](../assets/organizing/history-panel.png)

## MCP { #mcp }

Агент или скрипт, управляющий редактором через [сервер MCP](../mcp.md), запускает те же проверки, что и панель «Проблемы», инструментом `validate_map`, который называет их кодами, например `coplanar_faces` и `missing_model`. Действие `insert_prefab` у `run_action` принимает `fixup`, так что агент может задать экземпляру его fixup при размещении.
