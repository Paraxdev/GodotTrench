# Как работает entity I/O { #how-entity-io-works }

Entity I/O это способ заставить карту что-то делать без написания кода, связи устроены так же, как в Hammer для Source.

У каждой сущности есть **выходы**, события, о которых она сообщает, например нажатие кнопки, и **входы**, то, что ей можно приказать сделать, например открыть дверь. Соединение говорит: когда сработает этот выход, вызови тот вход у цели. Связи сохраняются в карте, так что вы соединяете кнопку с дверью в редакторе, и в игре дверь открывается.

## Соединение { #a-connection }

У выхода может быть сколько угодно соединений. У каждого есть такие поля:

| Поле | Что делает |
| --- | --- |
| Выход | Событие этой сущности, которое запускает соединение, например `pressed` у кнопки |
| Цель | Какие сущности получают вызов, обычно это targetname, см. [Цели](parameters.md#targets) |
| Вход | Что цели должны сделать, например `open` у двери |
| Параметр | Необязательное значение, передаваемое входу, например величина урона, см. [Параметры](parameters.md#parameters) |
| Задержка | Секунды ожидания перед вызовом входа, 0 вызывает его сразу. С её помощью события разносятся по времени, например лампы включаются одна за другой |
| Раз | Сколько раз соединение может сработать. -1 означает каждый раз, 1 делает событие одноразовым |

Их можно править в Инспекторе, в разделе **Выходы** выбранной сущности, или как провода в [Логическом графе](logic-graph.md). Оба способа меняют одни и те же выходы. (В Инспекторе для *Раз* есть только флажок **один раз**, для любого другого числа используйте поле соединения в Логическом графе.)

![Раздел «Выходы» в Инспекторе кнопки: выход pressed, цель front_door, вход open, пустой параметр, задержка 0.00 с и флажок «один раз»](../assets/io/inspector-outputs.png)

В Godot выход это сигнал, а вход это метод: у `func_button` есть `signal pressed(activator)`, а у `func_door` есть `func open()`. Ваши собственные скрипты участвуют так же, см. [Собственные сущности](custom-entities.md).

## Когда срабатывает выход { #when-an-output-fires }

Спустя *Задержка* секунд вход вызывается у каждого узла, который находит цель. Цель, которая ничего не находит, ничего не делает. Для targetname или пути узла это почти всегда опечатка, поэтому при первом срабатывании выводится предупреждение. Отложенный вызов отбрасывается, если сущность за это время покинула дерево, например потому что её убили.

Без задержки вся цепочка выполняется внутри `emit` сигнала, до того как продолжит работу код, который его вызвал. Это важно, если ваш скрипт читает состояние сразу после `emit`, двери и счётчики дальше по цепочке уже отреагировали.

## Активатор { #the-activator }

Активатор это тот, кто запустил цепочку, обычно игрок, который нажал кнопку или вошёл в триггер. Дальше по цепочке `!activator` означает этот узел, так что триггер может ранить или телепортировать именно того, кто его коснулся.

Он берётся из первого аргумента типа `Node` у сработавшего сигнала, поэтому сохраняется только пока каждый сигнал в цепочке передаёт его дальше. Встроенные сигналы ведут себя так:

| Сигналы | Что происходит с активатором |
| --- | --- |
| `triggered`, `pressed`, `entered`, `exited`, `hurt`, `teleported`, `pushed` | Передаётся без изменений, эти сигналы несут узел, который их вызвал |
| `arrived(corner)`, `spawned(node)`, `reached(train)` | Заменяется узлом в скобках, так что дальше `!activator` это эта точка пути, созданный узел или поезд |
| `opened`, `timer`, `step_N`, `on_true`, `on_case_N`, `result`, `broken`, `switched`, `map_spawn` | Теряется. Эти сигналы не несут узла, поэтому с этого места `!activator` ничего не находит |

> [!TIP]
> Нужен игрок через несколько шагов цепочки, потерявшей активатор? Укажите целью `!player`, он не зависит от цепочки.
