# Скрипты и вызовы { #scripts-and-calls }

> [!NOTE]
> Эти сущности входят в пакет сущностей геймплея, см.
> [Установка и настройка](README.md#installing-and-customizing).

Точечные сущности для того, до чего не достаёт обычное связывание: состояние игры, ваш собственный код, анимации и выяснение, почему цепочка не срабатывает.

## logic_script { #logic_script }

Выполняет фрагмент GDScript при срабатывании, для небольшой логики, которой нет во встроенных сущностях, например чтения здоровья игрока, без написания собственной сущности.

* **Входы:** `run(activator)`, `run_with(parameter)`
* **Выходы:** `ran(result)`, с возвращаемым значением фрагмента
* **Ключи:** `source` пусто, `expression` пусто (однострочник, используется, когда `source` пуст)

Фрагмент видит `this` (саму сущность), `activator` (того, кто запустил цепочку), `parameter` (пришедшее значение), `io` (помощники `TrenchDotIO`, например для поиска сущностей по имени) и `tree` (`SceneTree`). У `run_with` `activator` всегда null. Ошибка компиляции записывается в журнал как предупреждение при загрузке карты. Этот фрагмент ранит игрока:

```gdscript
var p = io.find_targets(this, "!player", null)
if not p.is_empty():
	p[0].take_damage(25, this)
```

> [!WARNING]
> Вложенные строки отбивайте табами. Пробелы не скомпилируются, будет ошибка смешанных отступов.

> [!WARNING]
> Фрагмент это код, который приходит внутри карты. Он выполняется, когда запускается игра, с теми же правами, что и собственные скрипты проекта, так что скачанную карту с кодом воспринимайте как любую скачанную программу: она может делать на вашем компьютере что угодно. Панель «Проблемы» предупреждает о каждом `logic_script` с кодом, каждом выходе, который может передать ему код, и каждом префабе с тем или другим, прочтите это до того, как играть в карту.

## logic_call { #logic_call }

Вызывает метод у любой цели с фиксированными аргументами, чтобы добраться до кода вашей игры, например добавить очки в автозагрузке `Game`. В отличие от обычного выхода он предупреждает, когда цели или метода нет, так что опечатки видны в журнале. Методы C# работают под своими именами в PascalCase.

* **Входы:** `trigger(activator)`, `call_with(parameter)`
* **Выходы:** `called(result)`
* **Ключи:** `call_target` `/root/Game`, `method` пусто, `arguments` `[]`

`call_target` это путь узла, `@group`, targetname, `!activator` или `!self`. `arguments` это массив JSON, например `["key_red", "$activator"]`, он принимает подстановки из страницы [Параметры](../parameters.md), которые подставляются на самом `logic_call`. `call_with` кладёт свой параметр туда, где стоит `"$parameter"`, или передаёт его единственным аргументом.

## logic_animate { #logic_animate }

Проигрывает анимации у первого `AnimationPlayer` в `target` или под ним, для персонажей и пропов с собственными анимациями. Поставьте `target` в `!activator`, чтобы анимировать того, кто запустил цепочку.

* **Входы:** `play(name)`, `stop`, `queue(name)`, `seek(time)`
* **Выходы:** `finished(anim)`
* **Ключи:** `target` `!self`, `animation` пусто (проигрывается, когда у `play` нет имени), `speed` 1.0

## logic_debug { #logic_debug }

Печатает строку по `write` и показывает свои последние строки плавающей надписью в отладочных сборках, так что в игре видно, доходит ли до него цепочка и с каким параметром. С включённым `trace_all` он пишет в журнал каждый выход в игре, это быстрый способ наблюдать за всей цепочкой. См. [Отладка](../debugging.md).

* **Входы:** `write(parameter)`, `toggle` (надпись), `show`, `hide`
* **Выходы:** `printed(text)`
* **Ключи:** `message` `{name} received {parameter} from {activator}` (`{time}` тоже работает), `show_label` 1, `trace_all` 0
