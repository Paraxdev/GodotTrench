# Логический граф { #the-logic-graph }

Панель **Логика** показывает entity I/O карты в виде графа. Каждая связанная сущность и каждая логическая сущность это узел, а каждое соединение это провод от выходного пина справа у одного узла к входному пину слева у другого.

Граф показывает те же выходы, что правит Инспектор, поэтому изменение в одном сразу видно в другом. Карта, сборка в Godot и игра работают совершенно одинаково, пользуетесь вы графом или нет.

## Как его открыть { #opening-it }

Выберите *Вид > Панели > Логика*.

![Меню «Вид» с открытым пунктом «Панели» и наведённой «Логикой»](../assets/logic-graph/menu-panels-logic.png)

Он открывается рядом с «Материалами» под видами и увеличивает эту панель примерно до половины середины окна, потому что графу нужно место. Перетащите разделитель или вкладку, чтобы это изменить.

![Панель «Логика» демо-карты Night District: кнопки, связанные с дверями, триггер и таймер, заголовки окрашены по категориям, и рамка «Hall lights» вокруг триггера, который с задержками включает три лампы](../assets/logic-graph/graph.png)

## Как читать граф { #reading-the-graph }

| Что вы видите | Что это значит |
| --- | --- |
| Заголовок узла | targetname сущности, а если его нет, её имя из *Переименовать*, а если и его нет, её classname. Под ним категория и classname |
| Серые строки под заголовком | Настройки, отличающиеся от значений сущности по умолчанию, например `max 3`, `wait 2 s` или `once`, обрезанные до двух коротких строк. Узел без них стоит на значениях по умолчанию. Инспектор показывает все |
| Цвет заголовка | Категория: группа определения, а если её нет, первое слово classname, так что `logic_relay` это *logic*. См. [Цвета](#colors) |
| Пины | Входы слева, выходы справа, из [определения сущности](entities/README.md) плюс любое имя, которое карта уже использует у этой сущности. Заполненный пин означает, что у него есть провод. Наведите указатель на пин, чтобы увидеть его тип и передаваемые значения |
| Жёлтое имя пина | Имени нет в определении сущности, панель «Проблемы» тоже предупреждает о нём |
| Подпись провода | Задержка, `once` или сколько раз он может сработать, и параметр, когда они заданы. Наведите указатель на провод, чтобы увидеть его выход, цель, вход и задержку полностью |
| Синий узел и провод | [Цель](parameters.md#targets), которую находит только запущенная игра, например `!player`, `@enemies`, путь узла или шаблон вроде `door_*` |
| Красный узел, пунктирный красный провод | targetname, которого нет ни у одной сущности, обычно опечатка |

Узел получают только связанные сущности и логические и математические сущности. Выделите любую другую сущность, в виде или в «Структуре», и она тоже появится, готовая к связыванию.

## Цвета { #colors }

Цвета помогают просматривать большой граф, но у каждого цвета есть ещё и название или форма, а палитры остаются различимыми при распространённых видах цветовой слепоты.

| Категория | Цвет |
| --- | --- |
| logic | синий |
| math | оранжевый |
| trigger | сине-зелёный |
| func, двери, кнопки и движители | киноварный |
| light | жёлтый |
| env | бирюзовый |
| game | голубой |
| prop | розовый |
| npc | красно-фиолетовый |
| info | серый |

| Тип пина | Цвет |
| --- | --- |
| pulse, событие без значения | белый |
| bool | киноварный |
| int | голубой |
| float | сине-зелёный |
| string | розовый |
| vector3 | жёлтый |
| color | красно-фиолетовый |
| node, например активатор | синий |
| variant, любое значение | серый |

Пины, передающие значение, это круги, импульсы это треугольники. Провод берёт цвет выхода, от которого начинается. Собственная категория, заданная через `group` определения, тоже получает свой цвет.

## Связывание { #wiring }

Тяните от выходного пина к входному. Пока вы тянете, пины, которые подходят проводу, получают кольцо, а пин, на котором он закончится, заполняется. Отпустите, и соединение добавится в выходы исходной сущности.

![Перетаскивание провода от выхода released у button_1 ко входу turn_off у hall_light, подходящие пины показывают кольца](../assets/logic-graph/wire-drag.gif)

Импульс подходит к любому пину, а значение подходит к пину своего типа, так что узел `activator` не подходит ко входу `int`. (Int подходит и к пину float или bool, и наоборот, а variant подходит ко всему.) Любой пин всё равно принимает провод, имена в entity I/O проверяются только при запуске игры.

Цель без targetname получает его в тот же момент: имя, которое вы дали ей через *Переименовать* в «Структуре», так что лампа, названная `lamp`, становится целью `lamp`, а иначе свободное имя вроде `door_2`. Имя, которое уже есть у другой сущности, получает после себя число.

Провод можно отпустить и в другом месте:

* На заголовке узла, чтобы выбрать из всех его входов или ввести любое имя.
* На пустом месте, чтобы добавить там логическую сущность, сразу связанную с пином, от которого вы тянули.

### Добавление логических сущностей { #adding-logic-entities }

Щёлкните правой кнопкой по пустому месту или нажмите **Добавить** слева вверху панели, чтобы добавить логическую сущность без провода.

![Список «Добавить»: поле поиска, затем группа logic с подсвеченным logic_animate, logic_auto, logic_branch и другие](../assets/logic-graph/add-menu.png)

Без поиска список сгруппирован по категориям, сначала logic и math, затем другие сущности, у которых есть входы или выходы. Введите текст, чтобы искать среди всех: сначала идут классы, имя которых начинается с текста или содержит его, затем те, у которых это есть в категории или описании. Клавиши со стрелками вверх и вниз двигают подсветку, а Enter добавляет этот класс.

Новые сущности это точечные сущности, и сборка в Godot создаёт для каждой узел, поэтому им нужно место на карте. Они попадают на слой *Logic*, рядом с сущностью, с которой они связаны, или перед камерой 3D-вида. Каждая сразу получает свободный targetname, например `relay_2`, который становится заголовком её узла. Измените его в Инспекторе, ведь *Переименовать* задаёт только имя в «Структуре».

> [!NOTE]
> Без пакета сущностей геймплея добавлять нечего, логических сущностей нет. Тогда меню «Добавить» предлагает его установить.

### Правка соединения { #editing-a-connection }

Щёлкните по проводу, и окошко справа вверху графа позволит изменить его выход, цель, вход, параметр, задержку и число раз. Его кнопка **Удалить** или клавиша Delete, пока указатель над графом, удаляет его.

![Выбранный провод от button_1 к hall_light и окошко «Связь от button_1» справа вверху: выход released, цель hall_light, вход turn_off, задержка 0.00 с, раз: каждый раз, и «Удалить»](../assets/logic-graph/connection-box.png)

Щёлкните правой кнопкой в любом месте вдоль провода, а не только на его подписи, чтобы получить **Изменить связь** и **Удалить связь**. Каждое изменение это один шаг в «Истории», так что отмена работает как везде.

### Меню узла { #the-node-menu }

Щёлкните правой кнопкой по узлу, чтобы увидеть, что можно сделать с его сущностью.

![Контекстное меню узла hall_light: Показать в видах, Переименовать, Дублировать, Выбрать связанные, Отключить все, Удалить сущность и «Симулировать» с его выходом switched](../assets/logic-graph/node-menu.png)

| Пункт | Что делает |
| --- | --- |
| Показать в видах | Выделяет её и переносит виды к ней, как двойной щелчок |
| Переименовать | Переименовывает сущность в «Структуре». Узел называется по targetname, если он есть, поэтому имя видно там только у сущности без него |
| Дублировать | Копирует сущность на один шаг сетки в сторону, вместе с её проводами |
| Выбрать связанные | Выделяет узел и каждый узел, с которым его соединяет провод |
| Отключить все | Удаляет за один шаг каждый провод, входящий в узел или исходящий из него. Сущности остаются |
| Удалить сущность | Убирает сущность с карты, см. [Копирование, вставка и удаление](#copy-paste-and-delete) |
| Симулировать | Запускает один из её выходов на бумаге, см. [Симуляцию](#simulate) |

Если выделено несколько узлов, «Дублировать» и «Удалить» действуют на все из них, когда вы щёлкаете правой кнопкой по одному из выделенных.

## Копирование, вставка и удаление { #copy-paste-and-delete }

Граф показывает сущности карты, поэтому эти клавиши работают на выделенных сущностях, браши в том числе, пока указатель над графом.

| Клавиша | Что делает |
| --- | --- |
| Ctrl+C, Ctrl+V | Копирование и вставка. Копия ложится на один шаг сетки от оригинала, вместе с проводами, потому что под указателем нет вида, куда её поместить. Вставьте с указателем над видом, чтобы разместить её там |
| Ctrl+D | Дублирование, тоже на один шаг сетки от оригинала |
| Delete | Убирает выбранный провод или рамку. Если ничего не выбрано, удаляет выделенные **сущности с карты**, а не только их узлы. Провода от других сущностей к удалённой становятся красными. Отмена возвращает всё |
| Ctrl+A | Выделяет всё на карте, а не только показанные узлы |

## Как перемещаться { #moving-around }

| Чтобы | Сделайте |
| --- | --- |
| Масштабировать | Крутите колесо |
| Сдвигать | Тяните средней или правой кнопкой. Щелчок правой кнопкой без движения открывает меню, поэтому дрожащий сдвиг может его вызвать, Escape закрывает |
| Выделять | Щёлкните по узлу, Shift- или Ctrl-щелчок добавляет, перетаскивание по пустому месту выделяет рамкой. Сущности выделяются и в видах, и в «Структуре», и наоборот |
| Показать в видах | Дважды щёлкните по узлу |
| Перемещать | Тяните узлы. Их позиции сохраняются в карте |
| Навести порядок | **Упорядочить** раскладывает выделенные узлы по ходу сигнала. Если выделено меньше двух, каждый узел возвращается к автоматической раскладке |
| Увидеть всё | **Вписать** или Home, пока указатель над графом |
| Увидеть выделенное | F, пока указатель над графом, показывает выделенные узлы |

Узлы, которые никто не двигал, следуют автоматической раскладке, слева направо по ходу сигналов, а вид масштабируется под панель, пока вы сами не измените масштаб или сдвиг. Когда вы переместили узел или связали что-то в графе, остальные остаются на своих местах, а новый узел появляется рядом с тем, с чем он связан. Синие и красные узлы-маркеры не сущности, поэтому двигать их нельзя. Они стоят рядом с узлом, который на них нацелен.

## Рамки { #frames }

Рамка это подписанная коробка позади группы узлов, чтобы держать большой граф в порядке: двери одного здания, головоломка, кат-сцена. Выделите узлы и нажмите **C** над графом или **Показать всё** на панели инструментов, затем введите название. Рамка *Hall lights* на картинке в начале это одна из них.

| Чтобы | Сделайте |
| --- | --- |
| Переместить рамку со всем внутри | Тяните её заголовок |
| Изменить её размер | Тяните угол справа внизу |
| Переименовать её | Дважды щёлкните по заголовку или выделите её и нажмите F2 |
| Перекрасить или удалить её | Щёлкните правой кнопкой по заголовку. Удаление рамки оставляет её узлы |

Рамки сохраняются в карте как данные редактора, сборка в Godot их игнорирует.

## Симуляция { #simulate }

Выделите одну сущность, нажмите **Симулировать** и выберите один из её выходов или щёлкните правой кнопкой по узлу. Граф нумерует жёлтым каждый провод, который сработает от этого выхода, а список под графом показывает каждый шаг по заголовкам узлов, в порядке прихода шагов, со временем в секундах после задержек. **Очистить** завершает предпросмотр. Щёлкните по шагу, чтобы выделить его провод.

![Симуляция у button_2: провода к garage_door и дальше к garage_beacon жёлтые и пронумерованы от 1 до 3, а список под графом называет каждый шаг](../assets/logic-graph/simulate.png)

Она следует правилам рантайма: цели находятся по targetname, а реле, таймеры, счётчики, гейты, двери и другие распространённые сущности передают цепочку дальше. Цели времени выполнения вроде `!player` показываются, но дальше не прослеживаются.

Сущность, которая запускает один из нескольких выходов, показывает каждый провод, который она могла бы запустить. Эти шаги и всё после них заканчиваются на `(maybe)` в списке, в интерфейсе это «(возможно)», и на `?` у номера провода, а наведение указателя говорит, чего шаг ждёт. Так счётчик, который питают `add` или `subtract`, продолжает к `hit_max` и `hit_min`, поскольку предпросмотр не считает нажатия: шаг есть, и он происходит, когда счётчик достигает своего `max` или `min`. `logic_sequence` запускает свои шаги в моменты, заданные свойствами `interval`, `times` и `steps`, так что кат-сцена читается как временная шкала.

Симуляция работает на бумаге, без Godot. Что на самом деле происходит в игре, описано в [Отладке связей](debugging.md).
