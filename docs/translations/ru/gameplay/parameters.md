# Цели, параметры и входы { #targets-parameters-and-inputs }

Соединение называет свою цель, свой вход и необязательный параметр простым текстом. Эта страница показывает, как этот текст превращается в узлы, метод и значения, которые используются в игре.

## Цели { #targets }

Цель соединения, а также ключей вроде `call_target`, определяет, какие узлы получат вход. Чаще всего это targetname, который вы дали другой сущности. Остальные формы достают до групп объектов и узлов вне карты.

| Цель | Куда достаёт | Для чего |
| --- | --- | --- |
| `main_door` | До каждой сущности с этим targetname в той же карте | Обычный случай, одна именованная сущность или несколько с общим именем |
| `door_*` | До каждого targetname, начинающегося с `door_` | Открыть сразу целый набор. Работает только завершающая `*` |
| `@enemies` | До каждого узла в группе Godot `enemies`, в любом месте дерева | То, что создаётся во время игры или размещается кодом игры |
| `!player` | До первого узла в группе `player` | Добраться до игрока, когда цепочка потеряла активатор |
| `!activator` | До того, кто запустил цепочку, `!caller` означает то же самое | Ранить или телепортировать того, кто коснулся триггера |
| `!self` | До сущности, которой принадлежит выход | Сущность действует сама на себя, например кнопка, которая отключает себя |
| `/root/Game` | Абсолютный путь узла, он должен начинаться с `/` | Автозагрузки и другой код игры вне карты |

Targetname ищутся внутри ближайшего `FuncGodotMap`, поэтому две карты в одной сцене не могут достать до имён друг друга. Группы, пути узлов и `!player` работают по всему дереву, используйте их, когда одной карте нужно говорить с другой.

> [!NOTE]
> В Source `!caller` это сущность, которая вызвала выход. Здесь он означает то же, что `!activator`, а для самой сущности используйте `!self`.

### Изменения во время игры { #runtime-changes }

Поиск по targetname кэшируется для каждой карты ради скорости. После того как вы создали или переименовали именованные сущности во время игры, вызовите `TrenchDotIO.invalidate(node)` с любым узлом этой карты, чтобы следующий поиск их увидел. Переименование означает изменение меты `td_targetname`, `name` узла тут роли не играет. Для удаления сущности вызов не нужен, кэш замечает освобождённые узлы.

У узлов, созданных спавнером, нет targetname. Доставайте их через их группу, например `@enemies`.

## Параметры { #parameters }

Параметр это значение, которое вы вводите в соединение и передаёте входу, например `25` для `take_damage` или скорость для двери. Текст становится первым типом, которому он подходит:

| Вы вводите | Вход получает |
| --- | --- |
| `25` | Целое число 25 |
| `0.5` | Число с плавающей точкой 0.5 |
| `true` или `false` | Bool |
| `0 64 0` | `Vector3`, из трёх чисел через пробелы |
| `hello` | Строку `"hello"`, когда ничего другого не подходит |

JSON-массив вроде `[10, "$activator"]` разворачивается в несколько аргументов, для входов, которым нужно больше одного. Значения приводятся к типам, которые объявляет метод, поэтому `1234` приходит в аргумент `String` как текст. Если метод принимает узел перед другими аргументами, текст вроде `!player` или targetname ищется и передаётся как этот узел.

Параметром может быть и один из этих плейсхолдеров, которые подставляются при вызове входа:

| Плейсхолдер | Становится |
| --- | --- |
| `$activator` | Активатором, узлом, запустившим цепочку |
| `$self`, `$caller` | Самой принимающей сущностью |
| `$position` | Глобальной позицией принимающей сущности |
| `$caller_name` | targetname принимающей сущности, а если его нет, именем её узла |

Плейсхолдеры подставляются для **принимающей** сущности, а не для той, что сработала. Они должны быть всем параметром целиком или целым элементом массива, внутри более длинного текста они не заменяются.

## Без параметра { #no-parameter }

Оставьте параметр пустым, и активатор попадёт в первый аргумент с типом объекта или без типа с именем `activator`, где бы он ни стоял. Поэтому `take_damage(amount, source)` получает его в `source`. Остальные значения, которые нёс выход, заполняют оставшиеся аргументы по порядку, так что `changed(value)`, связанный с `set_value`, передаёт значение дальше.

Это передаёт и `false`, поэтому `switched(false)`, связанный с `add` счётчика, прибавляет 0. Задайте параметр, когда вам нужно фиксированное значение.

## Как находится вход { #how-an-input-is-found }

Когда соединение срабатывает, имя входа сопоставляется с целью в таком порядке:

1. Метод с таким именем или его написание в PascalCase или camelCase, так что `AddScore` на C# отвечает на `add_score`.
2. Свойство с таким именем, которому присваивается параметр или значение, которое нёс выход. Вход `speed` с параметром `4` меняет скорость двери, дополнительный метод не нужен.
3. Один из встроенных входов ниже, которые понимает каждый узел.

| Вход | Эффект |
| --- | --- |
| `kill` | Освобождает узел, убирая его из игры |
| `show`, `enable` | Делает его видимым и снова включает обработку |
| `hide`, `disable` | Делает его невидимым и приостанавливает обработку |
| `toggle` | Переключает только видимость, обработка остаётся как есть |

Собственные методы сущности имеют приоритет, поэтому `disable` у триггера выключает триггер, а не прячет его. `show` и `hide` встроенные, если скрипт сущности не определяет свои. Любой другой вход печатает `[TD I/O] <node> has no input '<name>'`.
