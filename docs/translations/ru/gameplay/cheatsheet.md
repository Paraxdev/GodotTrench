# Шпаргалка по I/O { #io-cheatsheet }

Краткое содержание на одну страницу для [Как работает entity I/O](io.md) и [Цели, параметры и входы](parameters.md), на случай, когда вы знаете идею и вам нужны только детали.

## Когда срабатывает выход { #when-an-output-fires }

Сигнал срабатывает, засчитывается в *Раз*, ждёт *Задержку*, затем вызывает вход у каждого узла, который находит цель. Если не находит ни одного, ничего не происходит, а targetname или путь узла, которые ничего не нашли, предупреждают один раз.

## Цели { #targets }

| Пишете | Достаёт до |
| --- | --- |
| `main_door` | Каждой сущности с этим targetname, в той же карте |
| `door_*` | Каждого targetname, начинающегося с `door_` |
| `@enemies` | Каждого узла в этой группе Godot, в любом месте дерева |
| `!player` | Первого узла в группе `player` |
| `!activator` | Того, кто запустил цепочку, `!caller` означает то же самое |
| `!self` | Сущности, которой принадлежит выход |
| `/root/Game` | Узла по этому абсолютному пути |

## Параметры { #parameters }

Простое значение пробуется как int, float, bool, затем `x y z` как `Vector3`, иначе остаётся строкой. JSON `[a, b]` разворачивается в несколько аргументов. `$activator`, `$self`, `$position` и `$caller_name` подставляются для **принимающей** сущности.

Без параметра активатор попадает в первый объектный аргумент, а остальные значения, которые нёс выход, заполняют остальные по порядку.

## У кого сохраняется активатор { #who-keeps-the-activator }

| Сигналы | Активатор |
| --- | --- |
| `triggered`, `pressed`, `entered`, `exited`, `hurt`, `teleported`, `pushed` | Передаётся без изменений |
| `arrived(corner)`, `spawned(node)`, `reached(train)` | Заменяется узлом в скобках |
| `opened`, `timer`, `step_N`, `on_true`, `on_case_N`, `result`, `broken`, `switched`, `map_spawn` | Теряется |

Если цепочка его потеряла, а вам нужен игрок, укажите целью `!player`.

## Входы, которые есть у каждого узла { #inputs-every-node-has }

`kill`, `show`, `hide`, `enable`, `disable` и `toggle` работают на любом узле, если у сущности нет метода с таким именем. Вход, совпадающий со свойством, присваивает ему параметр.

## Область видимости logic_script { #logic_script-scope }

[`logic_script`](entities/scripting.md) при срабатывании выполняет фрагмент GDScript. Внутри `this` это сам logic_script, `activator` узел, запустивший цепочку, `parameter` переданное значение, `io` помощники `TrenchDotIO`, а `tree` это `SceneTree`. Делайте отступы табуляцией.

```gdscript
var p = io.find_targets(this, "!player", null)
if not p.is_empty():
	p[0].take_damage(25, this)
```

## Ничего не произошло? { #nothing-happened }

Проверьте панель «Проблемы», затем Логический граф, затем F3 в игре, затем залогируйте `TrenchDotIO.events()`. См. [Отладка связей](debugging.md).
