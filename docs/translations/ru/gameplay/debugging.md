# Отладка связей { #debugging-wiring }

Большинство ошибок в связях проявляются тихо: дверь просто остаётся закрытой. Проверяйте в таком порядке, от самой быстрой проверки к самой тщательной.

> [!TIP]
> Дверь или триггер, которые даже не мешают игроку, собраны без своего определения, и это не ошибка связей. См. [Сущности, которые ничего не делают](../godot/entities-troubleshooting.md).

## 1. Панель «Проблемы» { #1-the-issues-panel }

Откройте вкладку **Проблемы**, рядом со «Структурой» и «Историей» слева. Она отмечает выходы, нацеленные на targetname, которого нет ни у одной сущности, и входы, которых нет у класса цели. Опечатка в targetname самая частая причина того, что дверь остаётся закрытой.

![Панель «Проблемы» с одной ошибкой: выход triggered указывает на неизвестную сущность 'hall_lihgt' у trigger_once, с кнопкой «Исправить»](../assets/debugging/issues-panel.png)

Щёлкните по проблеме, чтобы выделить её сущность и показать её в видах, затем исправьте имя в Инспекторе.

> [!WARNING]
> **Исправить** при отсутствующей цели не угадывает правильное имя, а удаляет соединение. При опечатке лучше поправьте имя вручную.

## 2. Логический граф { #2-the-logic-graph }

В [Логическом графе](logic-graph.md) цель, которой ни у кого нет, показана красным узлом с пунктирным красным проводом и надписью, что ни у одной сущности нет такого имени.

![Логический граф: выход triggered у trigger_once идёт по пунктирному красному проводу к красному узлу hall_lihgt, ни у одной сущности нет такого имени](../assets/debugging/graph-missing-target.png)

**Симулировать** запускает выход на бумаге и подсвечивает всю цепочку, см. [Симуляцию](logic-graph.md#simulate).

## 3. F3 в игре { #3-f3-in-game }

Добавьте узел `TrenchDotDebugOverlay` в свою сцену в Godot или добавьте его как автозагрузку. Запустите игру и нажмите F3: он перечисляет выходы по мере их срабатывания и рисует каждый объём `Area3D` с его targetname, так что вы видите, не сработал ли триггер вовсе или сработал впустую.

Переключите его ещё раз после появления триггеров, объёмы собираются в момент включения. Клавиша задаётся свойством `toggle_key` оверлея.

## 4. Журнал { #4-logging }

Поставьте сущность `logic_debug` и отметьте её флажок `trace_all` в Инспекторе. Тогда каждый сработавший выход печатается в вывод Godot.

Из кода подключитесь к `TrenchDotIO.events().fired`, он испускается для каждого выхода, в том числе для тех, чья цель ничего не нашла.

```gdscript
TrenchDotIO.events().fired.connect(func(source, output, target, input, parameter):
	print(source.name, ".", output, " -> ", target, ".", input))
```

## Как выглядит каждая ошибка { #what-each-mistake-looks-like }

| Ошибка | Симптом | Решение |
| --- | --- | --- |
| Цель ничего не находит | `[TD I/O] <node>.<output>: target '<name>' matches no node` при первом срабатывании | Сделайте цель в точности равной targetname сущности, с учётом регистра |
| У цели нет такого входа | `[TD I/O] <node> has no input '<name>'` в выводе Godot | Выберите вход, который есть у класса цели, см. [Справочник сущностей](entities/README.md) |
| Выход, который сущность никогда не испускает | `[TD I/O] <node> has no signal '<output>'` один раз, при сборке карты | Выберите выход, который есть у класса, или запустите его из кода через `TrenchDotIO.fire_output()` |
| Сущность создана или переименована во время игры | Не находится по своему targetname | Вызовите `TrenchDotIO.invalidate()`, см. [Изменения во время игры](parameters.md#runtime-changes) |
