# 放置与接线 { #placing-and-wiring }

## 放置实体 { #placing-entities }

打开**实体**标签页，它就在右侧检查器旁边。你的项目认识的每个类都在那里有一张卡片，按类别分组。把鼠标悬停在卡片上就能看到它的作用。

![实体面板，func_door 卡片处于悬停状态，提示写着笔刷实体，滑动门](../assets/placing/entities-panel.png)

把卡片拖进任意视图就能放置它，也可以双击它，把它放在 3D 光标处。（按住 Ctrl 或 Shift 点击可以选多张卡片，一起拖进去，它们会排成一排落下。）笔刷实体的卡片自带一个方盒。选中笔刷后双击它，就会改为用这个实体把那些笔刷包起来。

实体会落在指针下方的第一个实体表面上。触发体积、只由工具纹理组成的笔刷和其他实体会被穿过。拖动时，一个青色标记会显示它将落在哪里。2D 视图显示不出深度，所以在那里，标记上会标出它落点的高度（或深度）。在顶视图里，房间的屋顶会挡路，所以放下时按住 Alt，实体就会穿过屋顶，落在里面的地板上。在前视图和侧视图里，Alt 会穿过近处的墙，把实体放在房间的中间。

### 笔刷实体 { #brush-entities }

门、按钮和触发器都是笔刷实体，它们的形状取自你搭好的笔刷。

1. 搭出形状，比如在门的位置放一个薄方盒，然后选中它。
2. 在视图里右键，在*创建笔刷实体*下选一个类。*笔刷 > 笔刷实体*里有同样的列表。

![视图的右键菜单，创建笔刷实体已展开，悬停在 trigger_once 上](../assets/placing/context-create-brush-entity.png)

常见的几种有更快的途径：

| 工具或菜单 | 它做出什么 |
| --- | --- |
| *玩法 > 门与移动体* | 根据所选笔刷做出带触发器的铰链门或滑动门，或者电梯 |
| *玩法 > 触发器* | 围绕所选内容大小的触发体积 |
| **体积**工具（Shift+E） | 一次拖出任意触发体积，不需要先有笔刷 |
| **路径**工具（Shift+P） | 一点一点地点出一串 `path_corner` 实体，供列车和行走者沿着走，按 Enter 结束 |

![玩法菜单，门与移动体已展开：铰链门、滑动门和电梯、移动平台](../assets/placing/gameplay-doors-menu.png)

![工具栏，悬停在体积工具上并显示提示：体积工具 (Shift+E)，拖出触发、出生、伤害、传送或推动体积](../assets/placing/toolbar-volume-tool.png)

### 手柄 { #handles }

选中门、闸门、平台、按钮、推动触发器、生成器、爆炸或物理道具，它就会在视图里显示手柄。拖动手柄来设置它的铰链、打开或移动的距离、半径或大小，不用再输入数字。铰链角度以 15 度为步长吸附，按住 Shift 则是一度一度地变。

![在顶视图里拖动铰链门的角度手柄，标签从 95° 降到 30°](../assets/placing/door-hinge-handle.gif)

## 接线 { #wiring }

连接存在于触发它的实体上。选中那个实体，看检查器底部的**输出**。**+ 添加输出**会添加一条连接，然后你填写输出、目标和输入。每个字段的作用见[实体 I/O 是怎么工作的](io.md)。

![一个按钮的检查器“输出”部分：输出 pressed，目标 front_door，输入 open](../assets/io/inspector-outputs.png)

要更快地连接两个实体，选中它们，然后选择*玩法 > 逻辑 > 链接两个所选实体…*。恰好选中两个实体时，检查器里也会出现一个**连接…**按钮。

![玩法菜单，逻辑已展开，悬停在链接两个所选实体…上](../assets/placing/menu-link-two-entities.png)

*链接实体*窗口左边是源，右边是目标。在*当*下选输出，在*调用*下选输入，然后按**链接**。

![链接实体窗口：左边是 func_button，右边是 light，当 pressed，调用 turn_on，以及交换的提示](../assets/placing/link-dialog.png)

> [!WARNING]
> 源不一定是你先点的那个实体。请检查顶部的两个名字，如果顺序反了，按它们中间的**交换**按钮。

[逻辑图](logic-graph.md)能一次显示所有接线，并通过从引脚拖到引脚来连接实体。

## 不用 Godot 检查接线 { #checking-wiring-without-godot }

在[逻辑图](logic-graph.md#simulate)里选中一个实体，按**模拟**并选一个输出。图会高亮随后会发生的每一步 `source.output → target.input`，并连同它们的延迟一起列出来，这样你不用构建和运行游戏，也能跟踪很长的链。红色标出不存在的目标，通常是 targetname 打错了。蓝色标出像 `!player` 或 `@enemies` 这样的运行时目标，它们只在游戏里存在，不会再往下跟踪。

## 任何实体的代码 { #code-for-any-entity }

**参考**面板会为任何实体类显示 GDScript 和 C# 代码。当游戏代码需要和地图实体通信时，它很方便，比如打开一扇门或监听一个按钮。用*视图 > 面板 > 参考*、*帮助 > 实体与代码参考*来打开它，或者用检查器里的**代码参考**，它会直接跳到所选实体的类。拖动类列表和详情之间的分隔线可以调整列表的大小，双击则让它适应名称。

![参考面板选中了 func_button：它的输入和输出，以及在 GDScript 代码中使用](../assets/placing/reference-panel.png)

在左边选一个类，再选一个标签页。*在 GDScript 中使用*和*在 C# 中使用*演示如何调用这个实体，*GDScript 类*、*C# 类*和 *FGD.tres* 是供你编写自己的实体用的骨架。**复制**会把代码放到剪贴板。在骨架标签页上，**在项目中创建**会把文件写到 `res://entities/` 下，已经存在的文件则不会动。
