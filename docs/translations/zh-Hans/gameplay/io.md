# 实体 I/O 是怎么工作的 { #how-entity-io-works }

实体 I/O 是让地图不写代码就能“发生点什么”的办法，接线方式和 Hammer 为 Source 引擎做的一样。

每个实体都有**输出**，也就是它对外宣布的事件，比如按钮被按下；还有**输入**，也就是你可以让它去做的事，比如把门打开。一条连接的意思是：当这个输出触发时，对目标调用那个输入。接线保存在地图里，所以你在编辑器里把按钮连到门上，游戏里门就会打开。

## 一条连接 { #a-connection }

一个输出可以有任意多条连接。每条连接有这些字段：

| 字段 | 作用 |
| --- | --- |
| 输出 | 这个实体上启动连接的事件，例如按钮上的 `pressed` |
| 目标 | 哪些实体会收到调用，通常是一个 targetname，见[目标](parameters.md#targets) |
| 输入 | 告诉目标去做什么，例如门上的 `open` |
| 参数 | 交给输入的可选值，比如伤害量，见[参数](parameters.md#parameters) |
| 延迟 | 调用输入前等待的秒数，0 表示立即调用。用它错开事件，比如让灯一盏接一盏地亮起 |
| 次数 | 这条连接可以触发多少次。-1 表示每次都触发，1 则是只发生一次的事件 |

你可以在检查器里所选实体的**输出**下编辑它们，也可以在[逻辑图](logic-graph.md)里用连线来编辑。两者改的是同一份输出。（检查器里的*次数*只有一个**仅触发一次**复选框，要设置其他次数，请用逻辑图里的连接框。）

![一个按钮的检查器“输出”部分：输出 pressed，目标 front_door，输入 open，参数为空，延迟 0.00 秒，以及“仅触发一次”复选框](../assets/io/inspector-outputs.png)

在 Godot 里，输出是一个信号，输入是一个方法：`func_button` 有 `signal pressed(activator)`，`func_door` 有 `func open()`。你自己的脚本也以同样的方式参与进来，见[自定义实体](custom-entities.md)。

## 输出触发时 { #when-an-output-fires }

等待*延迟*秒之后，会对目标找到的每个节点调用输入。找不到任何节点的目标什么也不会做。对于 targetname 或节点路径来说，这几乎总是拼写错误，所以它第一次触发时会打印一条警告。如果延迟的调用发生时，它的实体已经离开了场景树，比如被消灭了，这次调用就会被丢弃。

没有延迟时，整条链都在信号的 `emit` 里运行，先于发出信号的那段代码继续往下执行。当你的脚本在 emit 之后立刻读取状态时，这一点很重要，后面的门和计数器已经做出了反应。

## 激活者 { #the-activator }

激活者是启动这条链的那个人，通常是按下按钮或走进触发器的玩家。链的后面部分里，`!activator` 指的就是那个节点，所以触发器可以只伤害或传送碰到它的那一个。

它取自触发的信号的第一个 `Node` 参数，所以只有链里每个信号都把它传下去时，它才会保留下来。内置信号的表现如下：

| 信号 | 激活者会怎样 |
| --- | --- |
| `triggered`、`pressed`、`entered`、`exited`、`hurt`、`teleported`、`pushed` | 原样传下去，这些信号带着引起它们的节点 |
| `arrived(corner)`、`spawned(node)`、`reached(train)` | 被括号里的节点替换，所以后面的 `!activator` 就是那个转角、生成的节点或列车 |
| `opened`、`timer`、`step_N`、`on_true`、`on_case_N`、`result`、`broken`、`switched`、`map_spawn` | 被丢弃。这些信号不带节点，所以从这里起 `!activator` 什么也找不到 |

> [!TIP]
> 激活者在链中途丢了，但你在后面几步还需要玩家？改为以 `!player` 为目标，它不依赖这条链。
