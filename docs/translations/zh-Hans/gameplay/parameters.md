# 目标、参数和输入 { #targets-parameters-and-inputs }

一条连接用纯文本写明它的目标、它的输入和一个可选的参数。这一页讲这些文本如何变成游戏里实际用到的节点、方法和值。

## 目标 { #targets }

连接的目标，以及 `call_target` 这类键的目标，决定哪些节点会收到输入。大多数时候它是你给另一个实体起的 targetname。其他形式可以触达成组的东西，以及地图之外的节点。

| 目标 | 触达 | 用在哪里 |
| --- | --- | --- |
| `main_door` | 同一张地图里带这个 targetname 的每个实体 | 常规情况，一个有名字的实体，或几个共用一个名字的实体 |
| `door_*` | 每个以 `door_` 开头的 targetname | 一次打开一整套。只有结尾的 `*` 有效 |
| `@enemies` | 树中任何位置、属于 Godot 分组 `enemies` 的每个节点 | 运行时生成的东西，或由游戏代码放置的东西 |
| `!player` | `player` 分组里的第一个节点 | 链丢了激活者时去找玩家 |
| `!activator` | 启动这条链的那个人，`!caller` 的意思相同 | 伤害或传送碰到触发器的那一个 |
| `!self` | 拥有这个输出的实体 | 实体对自己动手，比如会把自己禁用的按钮 |
| `/root/Game` | 绝对节点路径，必须以 `/` 开头 | 自动加载，以及地图之外的其他游戏代码 |

targetname 在最近的 `FuncGodotMap` 内部查找，所以同一个场景里的两张地图碰不到彼此的名字。分组、节点路径和 `!player` 在整棵树里都有效，一张地图要和另一张地图通信时就用它们。

> [!NOTE]
> 在 Source 里，`!caller` 是触发输出的那个实体。这里它和 `!activator` 的意思相同，要指实体自己，请用 `!self`。

### 运行时的变化 { #runtime-changes }

targetname 的查找结果会按地图缓存以提高速度。在运行时生成或重命名带名字的实体之后，请用那张地图里的任意节点调用 `TrenchDotIO.invalidate(node)`，这样下一次查找才能看到它们。重命名指的是修改 `td_targetname` 元数据，节点的 `name` 不起作用。消灭一个实体不需要调用，缓存会发现已释放的节点。

由生成器创建的节点没有 targetname。请通过它们的分组去找，例如 `@enemies`。

## 参数 { #parameters }

参数是你填进连接里、交给输入的值，比如给 `take_damage` 的 `25`，或者门的速度。这段文本会变成它能匹配的第一种类型：

| 你输入 | 输入收到 |
| --- | --- |
| `25` | 整数 25 |
| `0.5` | 浮点数 0.5 |
| `true` 或 `false` | 布尔值 |
| `0 64 0` | 一个 `Vector3`，由三个以空格分隔的数字组成 |
| `hello` | 字符串 `"hello"`，在没有其他类型匹配时 |

像 `[10, "$activator"]` 这样的 JSON 数组会展开成多个参数，供需要多个参数的输入使用。值会被转换成方法声明的类型，所以 `1234` 到达 `String` 参数时是文本。如果方法在其他参数之前先接收一个节点，那么像 `!player` 这样的文本或某个 targetname 会被查找出来，并作为那个节点传入。

参数也可以是下面这些占位符之一，在调用输入时填入：

| 占位符 | 变成 |
| --- | --- |
| `$activator` | 激活者，也就是启动这条链的节点 |
| `$self`、`$caller` | 接收的实体本身 |
| `$position` | 接收的实体的全局位置 |
| `$caller_name` | 接收的实体的 targetname，没有则是它的节点名 |

占位符是在**接收**的实体上填入的，而不是触发的那个。它们必须是整个参数或整个数组元素，不会在更长的文本里被替换。

## 没有参数 { #no-parameter }

参数留空时，激活者会进入第一个类型为对象的参数，或者无类型且名为 `activator` 的参数，无论它在哪个位置。所以 `take_damage(amount, source)` 会把它放进 `source`。输出带来的其他值按顺序填入其余参数，所以把 `changed(value)` 连到 `set_value`，就会把这个值传下去。

这也会转发 `false`，所以把 `switched(false)` 连到计数器的 `add`，加上的是 0。想要固定的值，就设置一个参数。

## 输入是怎么找到的 { #how-an-input-is-found }

连接触发时，输入名会按这个顺序和目标匹配：

1. 同名的方法，或它的 PascalCase 或 camelCase 写法，所以 C# 的 `AddScore` 会响应 `add_score`。
2. 同名的属性，设置为参数或输出带来的值。输入 `speed` 加参数 `4` 会改变门的速度，不需要额外的方法。
3. 下面的内置输入之一，每个节点都认识它们。

| 输入 | 效果 |
| --- | --- |
| `kill` | 释放节点，把它从游戏里移除 |
| `show`、`enable` | 让它可见，并让它重新处理 |
| `hide`、`disable` | 让它不可见，并暂停它的处理 |
| `toggle` | 只切换可见性，处理保持原样 |

实体自己的方法优先，所以对触发器用 `disable` 是把触发器关掉，而不是把它隐藏。除非实体的脚本定义了自己的版本，否则 `show` 和 `hide` 用的是内置的。其他任何输入都会打印 `[TD I/O] <node> has no input '<name>'`。
