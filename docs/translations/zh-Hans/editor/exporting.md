# 导出到 Blender 和其他 3D 工具 { #exporting-to-blender-and-other-3d-tools }

你可以把地图的样子存成一个 3D 模型文件：笔刷、网格、地形和模型，连同里面的纹理。用来在 Blender 里渲染关卡、搭一个预告片镜头，或者把一个白模交给美术，让他在上面做最终的网格，都很方便。

> [!WARNING]
> 只会导出几何体和材质。实体逻辑、I/O 接线、触发器、脚本和玩法行为都会被省略，这个文件也无法再在 TrenchDot 里作为地图打开。`.tdm` 仍然才是地图，请继续编辑它。

## 步骤 { #steps }

1. 打开导出

    进入*文件 > 导出 > glTF Binary (.glb)，供 Blender 等 3D 工具使用…*，或者在命令面板里输入“glTF”（Ctrl+Shift+P 或 F1）。

    ![文件菜单里导出已展开，鼠标停在 glTF Binary (.glb)，供 Blender 等 3D 工具使用上](../assets/exporting/menu-export.png)

2. 选出要放进去的内容

    *导出到 3D 工具*窗口会打开。勾选你想要的内容，参见下面的[选项](#options)。*道具模型*和*散布实例*旁边的数字，告诉你每一项会加入多少个对象。你可以在顶部把格式切换成 OBJ。

    ![导出到 3D 工具窗口，选的是 glTF Binary，整个地图、道具模型（5）已勾选，散布实例（4081）未勾选](../assets/exporting/export-dialog.png)

3. 保存

    点击**导出…**，选择文件放在哪里。导出在后台运行，带一个进度窗口，所以你可以继续编辑，点击**取消**会停止导出，并且什么都不写。完成之后，状态栏会说一共导出了多少个对象、材质和三角形。

4. 在 Blender 里打开

    用*File > Import > glTF 2.0 (.glb/.gltf)*，选中这个文件。默认设置就是对的，导入器会自己把模型转成 Z 轴朝上。

文件里保存的是你点击**导出…**时地图的样子。未保存的更改会先自动保存，除非*文件 > 偏好设置*里关掉了自动保存。如果状态栏点出某个材质，说项目里没有它的图片，那个材质导出来就没有纹理。

## 选项 { #options }

| 选项 | 作用 |
| --- | --- |
| 整个地图、仅选中项 | 导出所有内容，或者只导出选中的对象，仍然放在它们的图层和组里 |
| 隐藏的图层和对象 | 也导出在视图里被隐藏的内容。关掉时，你得到的就是你看到的 |
| 道具模型 | 道具和其他点实体显示的模型，按它们的位置、旋转和缩放放置 |
| 散布实例 | [散布集合](scatter.md)里的每一棵树、每块石头和每丛草，各自成为一个对象。默认关闭，因为成千上万个会让文件很大，打开很慢 |
| 点实体导出为空标记 | 在每个没有模型的点实体所在的位置，放一个以实体命名的空对象，方便在 Blender 里摆放灯光或相机 |
| 合并未命名的笔刷 | 你没有重命名过的笔刷，会按每个图层、组或实体合并成一个对象，这样 Blender 的大纲会保持简短。已命名的笔刷仍然各自独立 |

## 导出了什么 { #what-is-exported }

| 地图里的 | 文件里的 |
| --- | --- |
| 图层和组 | 同名的空父对象，所以大纲的布局会保留下来 |
| 笔刷 | 每个一个对象，名字和大纲里一样，是 `brush12` 或你起的名字 |
| 门和升降机这类笔刷实体 | 一个以实体命名的父对象，装着它的笔刷，位置和它们在编辑器里站的位置一致 |
| 网格、贴花 | 每个一个对象。贴花会得到混合的双面材质 |
| 地形 | 一个对象。每个三角形取用它最强的那个绘制图层的纹理，所以绘制出来的混合会呈阶梯状 |
| 预制体实例 | 预制体的内容移到位置上，放在一个以实例命名的对象下面 |
| 材质 | 每个材质一个，带着它的反照率纹理，以及它有的法线、粗糙度、金属度、环境光遮蔽和自发光贴图。镂空和透明的材质保留它们的 alpha，像素画保持清晰。内置的开发用颜色会以它们的网格纹理导出 |

文件会省略 Godot 构建时不会画的东西：带工具纹理的面（碰撞体、跳过、原点、天空、触发器、nodraw、hint），贴在另一个笔刷上而被遮住的面，触发器和其他体积实体，以及设为*导出时省略*的图层。灯光、声音、出生点、天空和雾也不会导出。

只有会进入文件的对象，才会互相遮住对方的面。所以只用*仅选中项*导出的一根柱子，会保留它贴在地板上的底面，而设为*导出时省略*的图层，也不会在它的邻居身上留下洞。

## 单位和坐标轴 { #units-and-axes }

Godot 里的一米，在 Blender 里也是一米。地图单位会除以项目的每米单位数，默认是 32，除非地图设置另有说明。文件和 Godot 一样是 Y 轴朝上，这正是 glTF 所期望的。每个笔刷、网格和地形的原点都在它边界的中心，模型则保留模型文件的原点。

## 什么时候用 OBJ { #when-to-use-obj }

*文件 > 导出 > Wavefront OBJ（.obj）…*是给读不了 glTF 的工具用的。它会并排写出三样东西，比如 `level.obj`、带着材质的 `level.mtl`，以及一个存着纹理副本的 `level_textures` 文件夹。搬动它们时要放在一起。在 Blender 里，用*File > Import > Wavefront (.obj)*。

OBJ 没有父对象，也没办法让多个副本共用一个网格，所以每个对象都是平铺在世界空间里写出的，每个散布实例都是一份完整的副本。勾选了散布实例时，一旦它们加起来达到一百万个三角形，窗口就会警告一次，并说明文件会变得多大。OBJ 导出会拒绝超过 1000 万个三角形，也就是超过一个 GB 的文件。材质保留反照率、法线、粗糙度和自发光纹理。只要另一个工具能读 glTF，就优先用 glTF。

一个 `.glb` 文件最多容纳 4 GB。无论有多少个散布实例显示同一个模型，glTF 都只写一次，所以只有超大的地图才会到这一步，这时导出会说明情况，而不是写出一个损坏的文件。

## 命令行 { #command-line }

`trenchdot --export-glb <map> <out.glb>` 和 `--export-obj <map> <out.obj>` 用默认选项导出，不用打开窗口。地图所属的 Godot 项目会从它所在的文件夹找到。参见[命令行](../command-line.md)。

## MCP { #mcp }

`map_file {op: export_glb, path}` 会写出一个 `.glb`，`map_file {op: export_obj, path}` 则写出一个 `.obj`，连同它的 `.mtl` 和纹理文件夹，内容来自打开的地图的当前状态，不管保存没保存。选项是一些标志：`selection_only`、`hidden`、`scatter`、`models`（除非设置，否则为 true）、`markers` 和 `merge_brushes`。结果会列出 `objects`、`meshes`、`materials`、`images`、`triangles`、`bytes` 和 `missing_textures`。`run_action` 会拒绝 `export_glb` 和 `export_obj`，因为菜单项会打开一个文件对话框。
