# 烘焙光照 { #baking-lighting }

烘焙会把太阳、天空、你的灯和发光材质的光一次性算好，包括反弹，并作为光照贴图存进地图里。之后 Godot 直接绘制这份光，而不是每一帧都去计算。你几乎不花运行时的代价，就能得到柔和的反弹光、灯投下的彩色溢光和更暗的角落。想要开关或移动的灯，则在烘焙之外保持实时。

![左：光照预览里的一个房间，一片灰色，窗下有边缘生硬的阳光斑块。右：同一个房间烘焙之后，暖色的灯光、更暗的角落和柔和的阳光斑块](../assets/light-baking/lit-preview-and-baked.png)

烘焙覆盖的是静态几何体：世界笔刷、网格、地形、置换，以及不会移动的笔刷实体。门和平台这类会移动的笔刷实体、触发体积、贴花、工具纹理，以及被排除在导出之外的图层，既不会被烘焙照亮，也不会投下烘焙阴影。

## 烘焙一张地图 { #baking-a-map }

1. 打开烘焙光照窗口

    选 *Godot > 烘焙光照…*。

    ![Godot 菜单，鼠标停在烘焙光照上，并显示它的提示](../assets/light-baking/menu-bake-lighting.png)

2. 检查有哪些东西参与

    最上面一行会做出汇总，例如“把太阳、1 盏灯、天空和发光材质烘焙进 102 个表面”，并说明哪些灯保持实时。

    ![烘焙光照窗口，质量设为中，纹素大小 16.0 u，阴影柔和度 0.30，运行于 CPU](../assets/light-baking/bake-dialog.png)

3. 选一个质量和纹素大小

    参见下面的[各个选项](#dialog-options)。第一次看效果，默认值就够了。

4. 点击**烘焙**

    进度窗口会显示当前阶段，期间你可以继续编辑。烘焙期间做出的改动不会包含在里面。**取消**会停止它，地图保留原来的光照。

5. 查看结果

    完成后，3D 视图会切换到**烘焙光照**着色，状态栏会告诉你用了多久，以及光照贴图有多大。

烘焙结果保存在 `.tdm` 里面，烘焙是一步撤销。同一个窗口里的**移除烘焙**会把它丢掉，Godot 随后重新用实时方式给地图打光。

## 对话框选项 { #dialog-options }

| 选项 | 作用 |
| --- | --- |
| 质量 | 追踪器花费多少光线和反弹，见下表 |
| 纹素大小 | 一个光照贴图纹素覆盖多少地图单位，2 到 128，默认 16（50 厘米）。越小越清晰，也越慢 |
| 阴影柔和度 | 0 到 1。把没有自己 `light_size` 的灯的光扩散开，让阴影有柔和的边缘。0 则保持生硬 |
| 运行于 | CPU、GPU 或 CPU + GPU，见下文 |

| 质量 | 每个纹素的光线数 | 反弹次数 | 每盏灯的阴影光线数 | 用于 |
| --- | --- | --- | --- | --- |
| 预览 | 32 | 1 | 4 | 摆放灯光，有噪点但很快 |
| 中 | 96 | 2 | 8 | 日常工作，默认值 |
| 高 | 192 | 3 | 12 | 干净的结果 |
| 最终 | 384 | 4 | 16 | 要发布的构建，大地图上很慢 |

光照贴图每边最多 4096 个纹素。当地图在你要求的纹素大小下放不下时，烘焙会改用更粗的纹素，并在状态栏里说明。地图会记住上一次烘焙所用的选项。

### CPU、GPU 还是两者 { #cpu-gpu-or-both }

| 运行于 | 什么时候选它 |
| --- | --- |
| CPU | 一定能用，用上每个核心。稳妥的默认值 |
| GPU | 机器有独立显卡，通常快得多 |
| CPU + GPU | 两者都很强。显卡和每个核心从同一个队列里领取工作，各自按自己跟得上的量来 |

当 GPU 用不了时，比如根本没有，它是软件渲染器，或者地图对它的缓冲区来说太大，就由 CPU 烘焙这张地图，状态栏会说明原因。GPU 中途失败时，剩下的交给 CPU。

## 查看烘焙结果 { #looking-at-the-bake }

*视图 > 着色 > 烘焙光照*会显示烘焙结果，地图有了烘焙之后，F4 循环切换着色时也会包含它。*视图 > 着色 > 烘焙视图*决定它显示什么。

![视图 > 着色 > 烘焙视图已展开，勾选了带烘焙光照的纹理，鼠标停在仅光照贴图上](../assets/light-baking/menu-baked-view.png)

| 烘焙视图 | 显示 |
| --- | --- |
| 带烘焙光照的纹理 | 被光照贴图照亮的纹理，接近 Godot 里显示的样子 |
| 仅光照贴图 | 只有光，没有纹理，用来判断反弹和噪点 |
| 太阳阴影遮罩 | 每个位置能接收到多少太阳光，全日照处为白色 |
| 环境光遮蔽 | 角落和物体下方的变暗，只用于检查，Godot 不使用它 |

![同一个房间的四种烘焙视图：左上是带烘焙光照的纹理，右上是单独的光照贴图，左下是太阳阴影遮罩，右下是环境光遮蔽](../assets/light-baking/baked-views.png)

## 灯光的键 { #light-keys }

每个 `light` 和 `light_spot` 都有一个 `bake_mode` 键，worldspawn 则有用于太阳的 `sun_bake_mode`：

| 值 | 在烘焙中 | 在 Godot 里 |
| --- | --- | --- |
| `auto` | 类似 `baked`，但带有 `targetname` 或 `start_on` 为 0 的灯保持实时，因为 I/O 可以开关它。太阳总是被烘焙 | 静态或禁用 |
| `baked` | 直接光和反弹光及其阴影 | 静态，由光照贴图承载 |
| `bounce` | 只有反弹光 | 动态，Godot 实时绘制直接光及其阴影 |
| `realtime` | 排除在外 | 禁用，完全实时 |

如果一盏灯的阴影必须跟随移动的物体，而它的反弹光仍要填满房间，就用 `bounce`。Godot 自己的名称 `static`、`dynamic` 和 `disabled` 也可以用。实时的灯还会通过[光照探针](../godot/baked-lighting.md#light-probes)照亮移动的物体。

`light_size` 是灯的半径，以米计。灯越大，投下的阴影越柔和，0 则改用窗口里的阴影柔和度。`light_indirect_energy` 缩放反弹光，`omni_attenuation`、`spot_attenuation` 和 `spot_angle_attenuation` 决定衰减的形状。Godot 的灯会把它们全部作为同名属性接收，所以实时的灯与烘焙保持一致。

## 烘焙过期时 { #when-a-bake-goes-out-of-date }

烘焙会记住它所用的几何体和灯光。移动、重塑、添加或删除静态几何体，或者更改灯、光照探针、worldspawn 的太阳和天空键、所用的纹理或它们的设置，都会让它过期。烘焙光照窗口随后会警告你，地图自上次烘焙以来发生了变化。

![烘焙光照窗口，有一行黄色的“自上次烘焙以来地图已更改。请重新烘焙以更新光照。”，以及烘焙和移除烘焙按钮](../assets/light-baking/bake-dialog-out-of-date.png)

在你重新烘焙之前，改动过的面在编辑器里显示光照预览，在 Godot 里显示地图的平均光，其余部分保持它们的烘焙光照。这里柱子是在烘焙之后移动的：它显示光照预览，它原来的阴影还留在地板上。发布之前请重新烘焙。

![移动柱子之后的烘焙房间，柱子被均匀照亮，它原来的烘焙阴影还留在它站过的地方](../assets/light-baking/bake-out-of-date.png)

## 纹理设置 { #texture-settings }

选中一个面，在检查器里展开**纹理设置**，就能设定整张地图里所有使用该纹理的面如何处理。这些设置会随地图一起保存。

![选中一个面的检查器，纹理设置已展开：在其上烘焙光照、投射烘焙阴影、光照贴图细节、每隔重复和投影](../assets/light-baking/texture-settings.png)

| 设置 | 作用 | 用于 |
| --- | --- | --- |
| 在其上烘焙光照 | 关闭会把这些面排除在光照贴图之外，Godot 给它们地图的平均光 | 天空、水、没人会凑近看的面 |
| 投射烘焙阴影 | 关闭会让光在烘焙中穿过这些面 | 玻璃、格栅、薄贴花 |
| 光照贴图细节 | 对这些面的纹素大小做乘法，小于 1 更清晰，大于 1 节省空间 | 地板上要锐利的阴影，远处天花板上模糊的阴影 |
| 每隔重复 | 纹理重复一次覆盖多少地图单位，取代它的像素大小 | 让一种纹理在各处使用同一个比例 |
| 投影 | 世界会忽略每个面自己的偏移、缩放和旋转，让纹理无缝地延伸下去 | 墙纸、瓷砖、混凝土 |

> [!TIP]
> 做 backrooms 风格的地图时，把墙纸设为世界投影并设一次重复尺寸，之后你用它画的每一面墙都能对齐，不用碰纹理工具。

两个烘焙选项都关闭的面，会被整个排除在烘焙之外。重复尺寸和投影在 Godot 里也同样生效。

## MCP { #mcp }

`bake_lighting` 工具使用与窗口相同的选项进行烘焙，包括 `quality`、`texel_size`、`softness` 和 `backend`（`cpu`、`gpu` 或 `hybrid`），`view` 则切换烘焙视图。它会等烘焙完成，并返回光照贴图大小、各项计数、使用的 GPU 或没有使用的原因，以及 `out_of_date`。`texture` 工具的 `settings` 操作可以读取和设置纹理设置，用到 `material`、`bake`、`casts`、`texel_scale`、`size`（`null` 表示清除）和 `projection`（`face` 或 `world`）。参见 [MCP 服务器](../mcp.md)。
