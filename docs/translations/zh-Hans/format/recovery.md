# 损坏的文件 { #damaged-files }

二进制地图损坏时，只会丢掉损坏的数据块，其余内容照常打开。如果你要写读取器，想和编辑器的行为保持一致，这一页就是你要做到的事。

读取器从第 12 个字节开始遍历[数据块](container.md#chunks)。一个有效的数据块头要有同步标记、匹配的头校验、不超过 1 GiB 的原始大小和一个可打印的标签。找不到有效的头时，读取器就向后搜索下一个同步标记，然后从那里继续。

`HEAD`、`NODE` 或 `END` 数据块的负载解压失败、校验和不对、大小不对或解码失败时，这个数据块会被丢弃。

| 损坏情况 | 结果 |
| --- | --- |
| 一个 `NODE` 数据块 | 其中存放的节点丢失 |
| 某个节点的父节点丢失 | 该节点连同它下面的所有内容，被移到地图末尾一个名为 `Recovered` 的图层里。这个图层在加载时会得到新的 id |
| 嵌套超过 60 层 | 同样移到 `Recovered`，这样读取时不会耗尽栈空间。只有人为构造的文件才会这样 |
| `HEAD` 数据块 | worldspawn 属性和编辑器状态丢失，地图版本改由 `END` 提供 |
| `HEAD` 和 `END` 都损坏 | 文件被拒绝 |
| 没有 `END` 数据块 | 文件被截断。直到最后一个完整数据块为止的内容都会加载 |
| `END` 里的计数大于实际读到的数量 | 报告为缺少的节点数或数据块数 |

每个读取器都会报告所有的丢失：

| 读取器 | 报告方式 |
| --- | --- |
| 编辑器 | 打开能读到的部分，在状态栏列出丢失的内容，并把地图标记为未保存。损坏的预制体也会在状态栏里报告 |
| Godot 插件 | 构建能读到的部分，每处丢失打印一条警告，前缀是 `[TDM]` 和文件路径 |
| `trenchdot --dump` | 输出能读到的部分，把丢失的内容写到 stderr |

每次保存前，编辑器都会把旧文件复制成 `<map>.tdm.bak`，所以保存一份恢复过的地图时，损坏的原件仍然留在它旁边。新文件会先写到 `<map>.tdm.tmp`，再改名覆盖地图，所以保存到一半崩溃也不会留下写了一半的地图。
