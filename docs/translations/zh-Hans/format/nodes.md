# 节点 { #nodes }

地图的内容是一棵节点树。每个节点的外层结构都一样，键按这个顺序排列：

| 键 | 类型 | 何时写入 | 含义 |
| --- | --- | --- | --- |
| `id` | 整数 | 总是 | 在地图里唯一 |
| `type` | 字符串 | 总是 | `layer`、`group`、`entity`、`brush`、`mesh`、`terrain`、`scatter` 或 `instance` |
| 类型字段 | | | 该节点类型的键，见下文、[几何体](geometry.md)和[地形与散布](terrain-scatter.md) |
| `label` | 字符串 | 设置后 | 用*重命名*给的名称，见下 |
| `graph` | 2 个数字的数组 | 设置后 | 实体的节点在[逻辑图](../gameplay/logic-graph.md)里的位置 |
| `hidden` | 布尔 | 为 `true` 时 | 在编辑器里隐藏 |
| `locked` | 布尔 | 为 `true` 时 | 在编辑器里无法被选中或编辑 |
| `children` | 节点数组 | 不为空时 | 子节点，按顺序 |

`hidden` 和 `locked` 只是编辑器状态，所以 Godot 仍然会构建隐藏的节点。想让某样东西不进入构建，就把它放进带 `omit_from_export` 的图层。

`label` 是你在编辑器里给笔刷、网格、实体、实例或地形起的名字，会代替 `brush12` 这样的默认名称显示出来。图层、组和散布集合从不带它，它们的名字存在 `name` 里。

Godot 只对地形使用 `label`，把节点命名为 `terrain_<id>_<label>`。笔刷和网格会并入它们所属的实体，实体的节点名取自 `targetname`。比这个键更早的编辑器仍然能读带它的文件，但保存时会丢掉它。

`graph` 也是编辑器状态。它是实体的节点在逻辑图里的位置，单位是图的点，只有被人移动过的节点才有。Godot 会忽略它，不是两个数字的值在加载时被丢弃。

## id { #ids }

id 是正整数，在多次保存之间保持不变，这样其他数据就能指向某个节点。Live Link 按 id 发送编辑，散布集合按 id 指明它们所在的表面，Godot 把每个生成节点的 id 存在它的 `_td_id` 元数据里。id 为 `0` 或重复的情况只有手动编辑过的文件才会出现，加载时会给它一个新的 id。

预制体是一个单独的 `.tdm` 文件，有自己的一套 id，所以它的两份副本会冲突。为了避免这一点，Godot 构建时会给[实例](#instance)带进来的每个节点的 id 加上一百万乘以出现次数序号。同一个预制体的两份副本不会共用 id，不管嵌套多深。

## 节点放在哪里 { #where-nodes-go }

| 节点 | 允许的父节点 |
| --- | --- |
| 图层 | 只能在顶层 |
| 组 | 图层或组 |
| 笔刷、网格、地形、散布集合、点实体、实例 | 图层或组 |
| 笔刷实体的笔刷或网格 | 那个实体 |

带子节点的实体是笔刷实体，比如由笔刷做成的门。不在任何实体里的笔刷和网格属于 worldspawn。

## 图层 { #layer }

地图的顶层部分，显示在编辑器的大纲里。

| 键 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `name` | 字符串 | 必填 | 大纲里显示的名称 |
| `color` | 字符串 | 必填 | `#rrggbbaa`。读取时也接受 `#rrggbb` |
| `omit_from_export` | 布尔 | `false` | 总是写入。为 true 时，构建会跳过整个图层，用于永远不该进入 Godot 的参考几何 |

## 组 { #group }

聚在一起的节点，方便你一起选中和移动。

| 键 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `name` | 字符串 | 必填 | 大纲里显示的名称 |
| `link_id` | 整数 | 省略 | link id 相同的组互为链接副本，用*链接复制*做出 |
| `transform` | 16 个数字 | 单位矩阵，省略 | 这份副本相对其他副本的摆放，一个按列主序排列的 4x4 矩阵 |

组的内容存的是世界空间坐标，已经就位。[链接副本](../editor/organizing.md#groups)会把在某一份副本里做的编辑重复到其他所有副本里，`transform` 只是编辑器用来把编辑从一份副本带到下一份的数据。Godot 构建会忽略 `transform` 和 `link_id`。

## 实体 { #entity }

| 键 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `classname` | 字符串 | 必填 | 游戏配置里的实体类，例如 `prop_physics` |
| `origin` | `[x, y, z]` | `[0, 0, 0]` | 总是写入。点实体的位置 |
| `angles` | `[pitch, yaw, roll]` | `[0, 0, 0]` | 总是写入。单位是度，YXZ 顺序，和 `rotation_degrees` 一样 |
| `properties` | 字符串到字符串的对象 | 省略 | 实体的键，按名称排序 |
| `outputs` | 数组 | 省略 | I/O 连接，见下 |

属性值永远是字符串，不管它在 FGD 里是什么类型，例如 `"travel": "0 168 0"`。

`angles`、`angle` 或 `mangle` 属性优先于节点的 `angles`，并按 Quake 的方式读取：俯仰和翻滚取反，偏航转 180 度。在以 `light` 开头的类上，`mangle` 则是偏航、俯仰、翻滚。`angle` 为 -1 或 -2 表示笔直朝上或朝下。编辑器把实体画成朝同样的方向，在那里转动它会把属性挪进节点的 `angles`。

构建会忽略笔刷实体的 `origin` 和 `angles`，因为它的笔刷已经在该在的位置。

每个输出是一条 [I/O 连接](../gameplay/io.md)：当这个实体触发某个信号时，调用目标上的一个方法。

| 键 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `output` | 字符串 | 必填 | 这个实体上触发连接的信号 |
| `target` | 字符串 | 必填 | 谁接收调用，见[目标](../gameplay/parameters.md#targets) |
| `input` | 字符串 | 必填 | 要在目标上调用的方法 |
| `parameter` | 字符串 | `""`，省略 | 传给输入的值 |
| `delay` | 数字 | `0`，省略 | 调用前等待的秒数 |
| `times` | 整数 | `-1`，省略 | 最多可以触发几次，`-1` 表示每次都触发 |

## 实例 { #instance }

对另一个 `.tdm` 文件的引用，带位置和旋转地放置，类似 Hammer 的 `func_instance`。预制体就是这样放置的：内容只在它自己的文件里存一份，每个实例都显示它。

| 键 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `path` | 字符串 | 必填 | 被引用的地图，相对于引用它的地图、绝对路径，或 `res://` |
| `origin` | `[x, y, z]` | 必填 | 实例放在哪里 |
| `angles` | `[pitch, yaw, roll]` | 必填 | 单位是度，YXZ 顺序 |
| `fixup` | 字符串 | `""`，省略 | 实例内容的名称前缀，见下 |

构建会取出被引用地图里每个未被排除出导出的图层的子节点，并按 `origin` 和 `angles` 移动它们。纹理投影随几何一起移动。被引用地图的 worldspawn 不会用到。实例最多嵌套八层。

Godot 构建对每张被引用的地图只读取一次，同一张地图的所有实例加起来最多可以增加 2,097,152 个值，这里一个值指被引用地图里的一个数组项或字典条目，每 8 个字符的文本再多算一个。超过这个数，构建会把剩下的实例排除在外并报告一个错误。普通地图远远达不到，只有实例套实例、成倍地相乘很多次才会到。

fixup 为 `p1` 时，`door` 会在 `targetname`、`target`、`destination`、`call_target`、FGD 中声明为 `target_source` 或 `target_destination` 的每个属性，以及每个输出的 `target` 里变成 `p1-door`。以 `!`、`@` 或 `/` 开头的值保持不变。嵌套的 fixup 从外向内叠加，所以 `a` 里面的 `b` 得到 `a-b-door`，编辑器里的*拆解实例*给出同样的名称。
