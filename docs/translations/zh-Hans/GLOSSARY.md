# 术语表 { #glossary }

## 3D 光标 { #3d-cursor }
世界中鼠标下方的那个点，取决于你最后悬停的视图。放在光标处的东西都会落在那里，比如通过“实体”面板里的“放置”按钮放下的实体，或者一块新地形。

## 激活者 { #activator }
触发实体 I/O 链的玩家或物体，通常是按下按钮或走进触发器的那一个。链中后面的步骤可以把 !activator 当作目标，这样就能只作用于这一个。

## 反照率 { #albedo }
材质的基础颜色，也就是加上光照、法线贴图或发光之前的纯纹理。Godot 把材质的颜色纹理叫作它的 Albedo 纹理。

## Alpha 裁剪 { #alpha-scissor }
Godot 的一种透明模式，在某个 alpha 阈值处把纹理硬生生切开，每个像素要么完全显示，要么完全隐藏。它适合格栅、树叶和边缘硬朗的贴花，而且和 alpha 混合不同，它仍然会投射阴影。

## 自动加载 { #autoload }
Godot 在启动时加载一次、并在整个游戏期间一直保留的脚本或场景，在 Project Settings > Globals > Autoload 下设置。全游戏通用的代码放在其中，比如计分器或热重载监听器。

## 烘焙光照 { #baked-lighting }
提前追踪一次并存储起来的光，而不是每一帧重新计算。Godot > 烘焙光照 会把太阳、天空、灯和发光材质烘焙进光照贴图，Godot 再通过 LightmapGI 把它画出来。

## 泛光 { #bloom }
明亮的灯和发光材质向周围像素扩散出的柔和光晕。用 worldspawn 的键 glow_intensity 打开。

## 布尔值 { #boolean }
只有真或假两种取值的值，比如电源是否开着。logic_branch、logic_gate 和 logic_flipflop 这些实体用来存储和组合布尔值。

## 笔刷 { #brush }
一个凸的实体，比如方盒或楔形，是关卡最基本的构件。你在视图中画出笔刷，用 CSG 把它们组合起来，Godot 会把每个笔刷变成带有对应碰撞的网格。

## 笔刷实体 { #brush-entity }
形状来自你所建笔刷的实体，比如门、按钮或触发器。你先画出笔刷，再把它们变成实体，这一点不同于只位于单个位置的点实体。

## 凸包 { #convex }
处处向外鼓起、没有凹坑或凹陷的形状，像方盒、楔形或圆柱那样。每个笔刷都必须是凸的，所以编辑器会拒绝会把笔刷压出凹陷的顶点移动。想要凹的形状，就把笔刷转换成网格。

## 隔离框 { #cordon }
在你工作时把地图限制在一块区域内的方框。启用隔离框后，框外的对象会被隐藏，也不会进入按隔离框导出的内容。

## CSG { #csg }
构造实体几何，通过组合实体来构建形状，比如从一个笔刷里减去另一个来切出门洞。编辑器的 CSG 命令有减去、挖空、凸合并和相交。

## 贴花 { #decal }
铺在表面上的纹理，像污渍、裂缝或海报。在 TrenchDot 中，贴花是贴在面上、不会闪烁的一层薄网格，按住 Alt 把材质拖放到面上就能放置。投影贴花则是另一种实体，它把材质投射到自己盒子内的一切东西上。

## 去平铺 { #detile }
地形图层的一项设置，范围 0 到 1，会随机旋转并偏移纹理的每一次重复，这样大片区域就不会露出明显的网格。它会增加纹理读取的开销，所以在重复看不出来的地方请保持为 0。

## 置换 { #displacement }
一个四边笔刷面，被分成由顶点组成的网格，每个顶点都可以抬高或降低，和 Hammer 里一样。它能在笔刷搭建的关卡中做出起伏不平的地面。大片的室外区域更适合用地形来建。

## 实体定义 { #entity-definition }
FGD 中对一个实体类的描述：它的 classname、键、输入和输出，以及 Godot 为它构建什么，比如节点类和脚本。在 Godot 中它是一个 FuncGodotFGDPointClass 或 FuncGodotFGDSolidClass 资源，列在 FGD 文件的 Entity Definitions 之下。

## 衰减 { #falloff }
绘制用的画笔，比如混合工具的画笔，从中心到边缘如何渐隐。平滑的衰减会得到柔和的边界，恒定的衰减则让整个圆盘以同样的强度绘制。

## FGD { #fgd }
游戏实体类的定义，包含它们的名称、键、输入和输出。这个名字来自 Hammer 的 Forge Game Data 文件。在 Godot 中它是一个 FuncGodotFGDFile 资源，游戏配置会把它转交给编辑器。

## fixup { #fixup }
设在预制体实例上的名称前缀。fixup 为 p1 时，里面名为 door 的实体会变成 p1-door，这样同一个预制体的多份副本就能各自保持连线互不干扰。

## func_detail { #func_detail }
FuncGodot 的一种笔刷实体，用于带碰撞的静态几何体，作为独立的节点构建，和世界笔刷分开。它不添加遮挡体，所以永远不会让它身后的物体停止渲染。

## func_illusionary { #func_illusionary }
FuncGodot 的一种笔刷实体，看得见但没有碰撞，玩家可以穿过去。海岛教程用它来做水面。

## FuncGodot { #funcgodot }
用 Quake 风格的地图文件构建关卡的 Godot 插件。TrenchDot 插件是它的一个分支，所以它的节点叫 FuncGodotMap，它的资源都以 FuncGodot 开头。

## 游戏配置 { #game-config }
Godot 项目根目录中的文件 trenchdot_game.json，由插件写入。它告诉编辑器你的项目使用哪些实体、纹理文件夹和单位比例，插件每次重新写入时，编辑器都会重新加载它。

## 玩法实体包 { #gameplay-entities-pack }
实体参考中的门、按钮、升降机、触发器、逻辑、生成器、道具和特效。它们不属于插件本身。安装这个包会把它们的定义和脚本复制到 res://trenchdot/entities，从那时起它们属于你的项目，你可以随意修改。

## glTF { #gltf }
一种开放的 3D 模型和场景文件格式，Blender、Godot 和大多数 3D 工具都能读取。.glb 文件是它的二进制形式，把几何体和纹理装在同一个文件里。

## Godot 分组 { #godot-group }
Godot 中节点上的一个命名标签，在 Node > Groups 下或通过代码设置，让代码和实体 I/O 能一次找到所有带这个标签的节点。像 @enemies 这样的目标会作用于 enemies 分组中的每个节点。

## Hammer { #hammer }
Valve 为《半条命 2》等 Source 引擎游戏做的关卡编辑器。TrenchDot 借用了它的实体输入输出模型，也能导入它的 .vmf 地图。

## 热重载 { #hot-reload }
每次你在 TrenchDot 中保存，就重新构建已经在运行的游戏的地图，这样你不必重启游戏就能看到改动。游戏中需要有 trenchdot_hot_reload.gd 这个自动加载脚本。

## 热点 { #hotspot }
在饰条图集上标出的一个矩形，存放在该纹理的 .hotspots.json 文件里。热点适配会把所选的面对齐到最匹配它们的矩形，这样一张饰条图集就能快速给一个房间贴好纹理。

## 光照贴图 { #light-map }
一张纹理，记录到达静态几何体每个位置的光，包括反弹光。每个面在其中都有自己的一块区域。

## 光照探针 { #light-probe }
空旷空间中的一个点，存储从各个方向射来的光。移动的物体从周围的探针取得光照，这样它们就能和静态几何体的烘焙光照保持一致。

## LightmapGI { #lightmapgi }
绘制光照贴图及其光照探针的 Godot 节点。由烘焙的 .tdm 构建出的地图会得到一个名为 baked_lighting 的节点。

## 光照预览 { #lit-preview }
编辑器 3D 视图的一种着色模式，用 F3 切换，会显示地图的灯光、太阳阴影、天空和雾。适合在 Godot 中构建之前判断光照，但它只绘制最强的 64 个点光源和聚光灯。

## Live Link { #live-link }
TrenchDot 和 Godot 编辑器之间的连接，是插件在 7842 端口运行的本地服务器。保存时重新构建、实时模式，以及工具栏里的 Godot 状态，都经过它。

## 实时模式 { #live-mode }
在你编辑的同时就把改动推送到 Godot 编辑器中打开的场景，不必先保存，这样你就能在 Godot 自己的渲染器里判断光照和比例。用工具栏里的链接按钮或 Godot > 实时模式 打开。

## 逻辑门 { #logic-gate }
把两个真或假的输入变成一个结果的规则，比如 and（两者都为真）或 xor（恰好一个为真）。logic_gate 实体提供了常用的几种。

## 主场景 { #main-scene }
运行项目时 Godot 播放的场景，在 Project > Project Settings > Application > Run 下设置。在 TrenchDot 中点“运行项目”，或在 Godot 中点播放按钮，都会启动它。

## 地图设置 { #map-settings }
一个 FuncGodotMapSettings 资源，说明纹理、材质和实体定义从哪里来，以及多少个地图单位算一米。FuncGodotMap 可以有自己的设置，否则使用项目默认值。

## MCP { #mcp }
Model Context Protocol，AI 代理和脚本调用程序工具的一种标准方式。编辑器可以运行一个 MCP 服务器，让代理检查和编辑地图。构建关卡并不需要它，这份文档在你打开页眉里的 MCP 开关之前会隐藏 MCP 部分。

## MultiMesh { #multimeshes }
Godot 在一次绘制中画出同一个网格的许多副本的方式。散布出来的树、石头和草都是以 MultiMesh 构建的，这让成千上万个也能便宜地渲染。

## 导航网格 { #navigation-mesh }
AI 代理可以行走的地面的简化轮廓，Godot 用它来寻路。TrenchDotNav 会根据已构建地图的碰撞烘焙出一个。

## 法线贴图 { #normal-map }
一张纹理，存储表面上每个像素朝向哪个方向，让平整的面像有凸起和凹槽一样接住光。它能在不增加几何体的情况下增添细节。

## 操作数 { #operand }
一次计算中，除了接收到的那个数之外所用的数。在加 5 的 math_calc 里，操作数就是 5。

## ORM { #orm }
一张把三张灰度图打包进颜色通道的纹理：环境光遮蔽在红色，粗糙度在绿色，金属度在蓝色。Godot 材质和 TrenchDot 地形图层把它当作一个文件来读取。

## 点实体 { #point-entity }
位于单个位置、形状不来自笔刷的实体，比如灯、声音或出生点。把它从“实体”面板拖进视图就能放置。

## 预制体 { #prefab }
地图中可重复使用的一部分，保存成独立的 .tdm 文件，以实例的形式放进其他地图。编辑预制体文件会更新它的每一个实例。

## res:// { #res }
Godot 书写项目文件夹内路径的方式，不管这个文件夹在磁盘上叫什么。res://maps/room.tdm 就是你的 Godot 项目里 maps 文件夹中的 room.tdm。这也是地图和模型必须保存在项目内、插件才找得到它们的原因。

## 受限模式 { #restricted-mode }
TrenchDot 打开含有代码、且你还没有信任的 Godot 项目的方式。你可以查看和编辑它的地图，但编辑器不会在其上启动 Godot、在 Godot 中构建或发送实时编辑，因为 Godot 打开、运行或构建项目时会执行项目的脚本。点击状态栏中的“受限模式”来信任这个项目。

## 散布集合 { #scatter-set }
用散布工具一起绘制的一组模型，比如一片森林或一块草地，有自己的图层、密度和目标表面。Godot 把每个集合构建为 MultiMesh。

## 屏幕空间反射 { #screen-space-reflections }
Godot 的一种效果，在光亮的表面上映出屏幕上已有的内容，让湿漉漉的街道倒映出路灯。用 worldspawn 的键 ssr 设为 1 来打开。

## 信号 { #signal }
Godot 对节点发出的事件的叫法，比如按钮被按下。每个实体输出都是一个信号，给输出连线就是把这个信号连到目标上的输入方法。

## targetname { #targetname }
你给实体起的名字，让其他实体能找到它，比如 main_door。输出、预制体 fixup，以及 fixture 这样的键，都是靠它来找到实体的。

## 纹素 { #texel }
落在表面上的纹理的一个像素。默认一个纹素覆盖一个地图单位，纹素密度，也就是一块面积里能放下多少纹素，决定了纹理看起来有多清晰。光照贴图也有纹素，它的纹素大小说明一个纹素覆盖多少个地图单位。

## 纹理尺寸 { #texture-size }
纹理的一次重复所覆盖的世界尺寸，在 Godot 材质上以 metadata/texture_size 设置。没有它时一个像素覆盖一个地图单位，会把高分辨率的照片拉伸到一大片区域上。

## 工具纹理 { #tool-textures }
告诉构建过程某个笔刷面的用途、而不是把它画出来的特殊纹理。clip 面只参与碰撞，skip 面什么都不构建，origin 面决定笔刷实体的原点在哪里。special/、tools/ 或 td/ 文件夹中的每张纹理在 Godot 里都不绘制任何东西，nodraw、hint、trigger 和其他工具名称不管放在哪个文件夹里也一样。

## TrenchBroom { #trenchbroom }
一款面向 Quake 风格游戏的免费关卡编辑器。TrenchDot 从它那里汲取了很多灵感，也能导入它的 .map 文件。

## 触发体积 { #trigger-volume }
一个不可见的笔刷实体，当有物体进入或离开时触发输出，比如在玩家走进房间时开始一段过场动画。用体积工具（Shift+E）来画。

## 饰条图集 { #trim-sheet }
一张把边缘、管道和面板等细节条带打包进一张图里的纹理。面通过热点贴合到它的各个部分，所以几张饰条图集就能给整栋建筑贴好纹理。

## 三平面映射 { #triplanar }
把纹理从三个方向投影到表面上的方式，即从上方和两侧投影，再按表面的角度混合。地形图层用它，让悬崖显示出岩石，而不是被拉伸的一团糊。

## UV 锁定 { #uv-lock }
一项默认开启、用 Ctrl+Shift+U 切换的设置，让纹理在你移动笔刷时始终贴在笔刷上。关闭后，纹理会留在世界中原地不动，在移动后的面上滑过。

## UV { #uv }
说明纹理的哪一部分落在面上哪个点的坐标，U 沿着纹理横向，V 沿着纹理纵向。笔刷面通常通过投影得到它们，而网格和某些面会为每个角存储自己的 UV。

## worldspawn { #worldspawn }
地图的根实体，包含世界笔刷。它的键保存整张地图的设置，比如天空、雾、太阳和流式加载，什么都没选中时检查器会显示它。

## 偏航角 { #yaw }
绕垂直轴的旋转，也就是从上方看时某样东西朝向的方向。传送目的地的偏航角决定物体到达后面朝哪边。

## 深度冲突 { #z-fighting }
两个表面落在同一平面或非常接近同一平面的地方出现的闪烁条纹，英文叫 z-fighting。GPU 分不清哪个在前面，于是每个像素时而显示这个，时而显示那个，而且条纹的图案会随着摄像机移动而变化。贴花能避免它，贴在墙上的薄笔刷则不能。
