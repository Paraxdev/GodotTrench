# ターゲット、パラメーター、インプット { #targets-parameters-and-inputs }

接続では、ターゲット、インプット、任意のパラメーターを、ただのテキストで指定します。このページでは、そのテキストがゲームの中でどのノード、メソッド、値になるのかを説明します。

## ターゲット { #targets }

接続のターゲットは、`call_target`のようなキーのターゲットと同じく、どのノードがインプットを受け取るかを決めます。たいていは、別のエンティティに付けたtargetnameです。ほかの書き方では、ノードのまとまりや、マップの外にあるノードにも届きます。

| ターゲット | 届く先 | 使いどころ |
| --- | --- | --- |
| `main_door` | 同じマップ内で、そのtargetnameを持つすべてのエンティティ | ふつうの使い方。名前を付けたエンティティ1つ、または同じ名前を共有する複数のエンティティ |
| `door_*` | `door_`で始まるすべてのtargetname | 一式をまとめて開けるとき。使えるのは末尾の`*`だけです |
| `@enemies` | ツリー内のどこにあっても、Godotグループ`enemies`のすべてのノード | 実行時にスポーンされたものや、ゲームのコードが置いたもの |
| `!player` | `player`グループの最初のノード | チェーンがアクティベーターを失ったときに、プレイヤーへ届かせる |
| `!activator` | チェーンを始めた存在。`!caller`も同じ意味です | トリガーに触れた相手にダメージを与えたり、テレポートさせたりする |
| `!self` | そのアウトプットを持つエンティティ自身 | 自分自身に作用するエンティティ。たとえば、自分を無効にするボタン |
| `/root/Game` | 絶対ノードパス。`/`で始める必要があります | オートロードなど、マップの外にあるゲームのコード |

targetnameは、いちばん近い`FuncGodotMap`の中で探されます。そのため、1つのシーンにある2つのマップは、お互いの名前に届きません。グループ、ノードパス、`!player`はツリー全体で働くので、あるマップから別のマップに話しかけるときに使ってください。

> [!NOTE]
> Sourceでは、`!caller`はアウトプットを起動したエンティティです。ここでは`!activator`と同じ意味になるので、エンティティ自身を指すには`!self`を使ってください。

### 実行時の変更 { #runtime-changes }

targetnameの検索は、速くするためにマップごとにキャッシュされます。実行時に名前つきエンティティをスポーンしたり名前を変えたりしたあとは、そのマップ内の任意のノードで`TrenchDotIO.invalidate(node)`を呼んでください。次の検索で、それらが見つかるようになります。名前を変えるとは`td_targetname`メタを変えることで、ノードの`name`は関係しません。エンティティを倒すときは呼び出しが要りません。キャッシュが解放されたノードを検知します。

スポナーが作ったノードには、targetnameがありません。`@enemies`のように、グループ経由で届かせてください。

## パラメーター { #parameters }

パラメーターは、接続に入力してインプットに渡す値です。たとえば`take_damage`への`25`や、ドアの速度です。テキストは、当てはまる最初の型になります。

| 入力するもの | インプットが受け取るもの |
| --- | --- |
| `25` | 整数の25 |
| `0.5` | 浮動小数点数の0.5 |
| `true`または`false` | bool |
| `0 64 0` | スペースで区切った3つの数から作る`Vector3` |
| `hello` | ほかに当てはまるものがないときの、文字列`"hello"` |

`[10, "$activator"]`のようなJSON配列は、複数の引数に展開されます。引数を2つ以上取るインプット向けです。値は、メソッドが宣言した型に変換されるので、`1234`は`String`引数にテキストとして届きます。メソッドがほかの引数より前にノードを取るときは、`!player`のようなテキストやtargetnameが検索され、そのノードとして渡されます。

パラメーターには、次のプレースホルダーも使えます。インプットが呼ばれるときに埋められます。

| プレースホルダー | 置き換わるもの |
| --- | --- |
| `$activator` | アクティベーター。チェーンを始めたノード |
| `$self`、`$caller` | 受け取るエンティティ自身 |
| `$position` | 受け取るエンティティのグローバル位置 |
| `$caller_name` | 受け取るエンティティのtargetname。なければノード名 |

プレースホルダーは、起動した側ではなく**受け取る**側のエンティティで埋められます。パラメーター全体か、配列の要素全体でなければならず、長いテキストの中では置き換えられません。

## パラメーターなし { #no-parameter }

パラメーターを空にすると、アクティベーターは、オブジェクト型の最初の引数、または型なしで`activator`という名前の引数に入ります。その引数がどこにあっても同じです。`take_damage(amount, source)`でアクティベーターが`source`に入るのは、このためです。アウトプットが運んできたほかの値は、残りの引数に順番に入るので、`set_value`につないだ`changed(value)`は値をそのまま渡します。

`false`も同じように転送されます。そのため、カウンターの`add`につないだ`switched(false)`は、0を加えます。決まった値にしたいときは、パラメーターを設定してください。

## インプットの見つけ方 { #how-an-input-is-found }

接続が起動すると、インプット名は次の順でターゲットと照合されます。

1. その名前のメソッド。またはPascalCaseかcamelCaseの綴り。C#の`AddScore`が`add_score`に応えるのは、このためです。
2. その名前のプロパティ。パラメーター、またはアウトプットが運んだ値が設定されます。パラメーター`4`を付けたインプット`speed`は、ドアの速度を変えます。メソッドを増やす必要はありません。
3. 下に挙げる組み込みのインプットのどれか。どのノードにも通じます。

| インプット | 効果 |
| --- | --- |
| `kill` | ノードを解放して、ゲームから取り除く |
| `show`、`enable` | 見えるようにして、処理を再開させる |
| `hide`、`disable` | 見えなくして、処理を止める |
| `toggle` | 表示だけを切り替える。処理はそのまま |

エンティティ自身のメソッドが優先されるので、トリガーの`disable`は、トリガーを隠さずにオフにします。`show`と`hide`は、エンティティのスクリプトが自前のものを定義していないかぎり、組み込みのものです。それ以外のインプットは、`[TD I/O] <node> has no input '<name>'`と出力されます。
