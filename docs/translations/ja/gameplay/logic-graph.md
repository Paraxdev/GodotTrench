# ロジックグラフ { #the-logic-graph }

**ロジック**パネルは、マップのエンティティI/Oをグラフとして表示します。配線されたエンティティと、ロジックエンティティは、どれもノードになります。接続は、あるノードの右側にある出力ピンから、別のノードの左側にある入力ピンへのワイヤーです。

グラフに出るのは、インスペクターで編集するのと同じ出力です。一方を変えると、もう一方にもすぐ反映されます。グラフを使っても使わなくても、マップ、Godotのビルド、ゲームの動きはまったく同じです。

## 開く { #opening-it }

*表示 > パネル > ロジック*を選びます。

![表示メニューでパネルが開き、ロジックにカーソルが重なっている](../assets/logic-graph/menu-panels-logic.png)

ビューの下にあるマテリアルの隣に開きます。グラフには広さが必要なので、そのドックはウィンドウ中央の半分ほどまで広がります。仕切りかタブをドラッグして変えられます。

![デモマップNight Districtのロジックパネル。ボタンがドア、トリガー、タイマーに配線され、ヘッダーはカテゴリごとに色分けされている。Hall lightsというフレームが、3つのライトを遅延つきで点けるトリガーを囲んでいる](../assets/logic-graph/graph.png)

## グラフの読み方 { #reading-the-graph }

| 見えるもの | 意味 |
| --- | --- |
| ノードのタイトル | エンティティのtargetname。なければ*名前変更*で付けた名前、それもなければクラス名です。その下にカテゴリとクラス名があります |
| タイトルの下のグレーの行 | エンティティの既定値と違う設定です。`max 3`、`wait 2 s`、`once`のようなもので、短い2行に切り詰められます。これがないノードは既定値のままです。インスペクターにはすべてが表示されます |
| ヘッダーの色 | カテゴリです。定義のグループ、なければクラス名の最初の単語で決まるので、`logic_relay`は*logic*になります。[色](#colors)を参照してください |
| ピン | 左が入力、右が出力です。[エンティティ定義](entities/README.md)のものに、そのエンティティでマップがすでに使っている名前を加えたものです。ワイヤーのあるピンは塗りつぶされます。ピンにカーソルを重ねると、型と渡す値が表示されます |
| 黄色のピン名 | その名前が、エンティティの定義にありません。問題パネルでも警告されます |
| ワイヤーのラベル | 遅延、`once`または起動できる回数、パラメーターです。設定してあるものだけが出ます。ワイヤーにカーソルを重ねると、出力、ターゲット、入力、遅延が省略なしで見えます |
| 青のノードとワイヤー | 実行中のゲームだけが解決する[ターゲット](parameters.md#targets)。`!player`、`@enemies`、ノードパス、`door_*`のようなワイルドカードなどです |
| 赤のノードと赤の破線のワイヤー | どのエンティティにもないtargetname。たいていはタイプミスです |

ノードになるのは、配線されたエンティティと、ロジックエンティティ、計算エンティティだけです。それ以外のエンティティも、ビューかアウトライナーで選ぶと表示され、すぐに配線できます。

## 色 { #colors }

色は大きなグラフを見渡すのに役立ちますが、どの色にも名前か形が付いています。また、一般的な色覚の特性でも見分けられるように、パレットは離してあります。

| カテゴリ | 色 |
| --- | --- |
| logic | 青 |
| math | オレンジ |
| trigger | 青緑 |
| func、ドア、ボタン、ムーバー | 朱色 |
| light | 黄 |
| env | ティール |
| game | 空色 |
| prop | ピンク |
| npc | 赤紫 |
| info | グレー |

| ピンの型 | 色 |
| --- | --- |
| pulse、値のないイベント | 白 |
| bool | 朱色 |
| int | 空色 |
| float | 青緑 |
| string | ピンク |
| vector3 | 黄 |
| color | 赤紫 |
| node、アクティベーターなど | 青 |
| variant、任意の値 | グレー |

値を渡すピンは円で、パルスは三角形です。ワイヤーは、始まりの出力と同じ色になります。定義の`group`で付けた独自のカテゴリにも、専用の色が付きます。

## 配線 { #wiring }

出力ピンから入力ピンへドラッグします。ドラッグ中は、ワイヤーが合うピンにリングが付き、終点になるピンが塗りつぶされます。放すと、接続がソースのエンティティの出力に追加されます。

![button_1のreleased出力から、hall_lightのturn_off入力へワイヤーをドラッグしている。合うピンにリングが出ている](../assets/logic-graph/wire-drag.gif)

パルスはどのピンにも合い、値は同じ型のピンに合います。そのため、`activator`ノードは`int`入力に合いません。(intはfloatやboolのピンにも合い、その逆も同じで、variantは何にでも合います。)どのピンでもワイヤーは受け付けられます。エンティティI/Oの名前は、ゲームの実行時にしか確認されないからです。

targetnameのないターゲットには、同じ操作の中で名前が付きます。アウトライナーで*名前変更*で付けた名前があればそれが使われるので、`lamp`と名付けたライトはターゲット`lamp`になります。なければ`door_2`のような空き名になります。ほかのエンティティが使っている名前には、後ろに番号が付きます。

ワイヤーを別の場所に落とすこともできます。

* ノードのタイトルの上なら、そのノードのすべての入力から選ぶか、好きな名前を入力できます。
* 何もない場所なら、そこにロジックエンティティが追加され、ドラッグ元のピンにすでに配線されます。

### ロジックエンティティを追加する { #adding-logic-entities }

何もない場所で右クリックするか、パネルの左上にある**追加**を押すと、ワイヤーなしでロジックエンティティを追加できます。

![追加の一覧。検索フィールドの下にlogicグループがあり、logic_animateが強調表示され、logic_auto、logic_branchなどが続く](../assets/logic-graph/add-menu.png)

検索しないときの一覧はカテゴリ別で、logicとmathが先、そのあとに入力か出力を持つほかのエンティティが並びます。入力するとすべてから検索され、名前がその文字で始まるか、その文字を含むクラスが先に、カテゴリや説明にそれを含むクラスがそのあとに出ます。上下の矢印キーで強調表示が動き、Enterでそのクラスが追加されます。

新しいエンティティはポイントエンティティで、Godotのビルドはそれぞれにノードを作ります。そのため、マップの中に場所が必要です。*Logic*というレイヤーに、配線先のエンティティの隣か、3Dビューのカメラの前に置かれます。それぞれにはすぐ`relay_2`のような空きtargetnameが付き、それがノードのタイトルになります。変更はインスペクターで行ってください。*名前変更*で設定されるのは、アウトライナーの名前だけです。

> [!NOTE]
> ゲームプレイエンティティパックがないと、追加できるロジックエンティティがありません。その場合、追加メニューにインストールの案内が出ます。

### 接続を編集する { #editing-a-connection }

ワイヤーをクリックすると、グラフの右上にあるボックスで、その出力、ターゲット、入力、パラメーター、遅延、回数を編集できます。ボックスの**削除**ボタンか、ポインターがグラフの上にあるときのDeleteキーで、ワイヤーが削除されます。

![button_1からhall_lightへのワイヤーを選択した状態。右上のbutton_1からの接続のボックスに、出力released、ターゲットhall_light、入力turn_off、遅延0.00秒、回数は毎回、削除が表示されている](../assets/logic-graph/connection-box.png)

ラベルの上だけでなく、ワイヤーのどこで右クリックしても、**接続を編集**と**接続を削除**が出ます。どの変更も*履歴*の1ステップになるので、元に戻す操作はほかの場所と同じように使えます。

### ノードのメニュー { #the-node-menu }

ノードを右クリックすると、そのエンティティに対してできることが出ます。

![hall_lightノードの右クリックメニュー。ビューで表示、名前変更、複製、接続先を選択、すべて切断、エンティティを削除、そしてswitched出力のシミュレート](../assets/logic-graph/node-menu.png)

| 項目 | 動作 |
| --- | --- |
| ビューで表示 | そのエンティティを選択して、ビューをそこへ移動します。ダブルクリックと同じです |
| 名前変更 | アウトライナーでエンティティの名前を変えます。ノードのタイトルにはtargetnameがあればそれが使われるので、この名前が出るのは、targetnameのないエンティティだけです |
| 複製 | エンティティをグリッド1つ分ずらしてコピーします。そこから出るワイヤーも含まれます |
| 接続先を選択 | そのノードと、ワイヤーでつながったすべてのノードを選択します |
| すべて切断 | そのノードに出入りするすべてのワイヤーを、1ステップで削除します。エンティティは残ります |
| エンティティを削除 | マップからエンティティを取り除きます。[コピー、貼り付け、削除](#copy-paste-and-delete)を参照してください |
| シミュレート | 出力の1つを、紙の上で起動します。[シミュレート](#simulate)を参照してください |

複数のノードを選択しているとき、選択したノードの1つを右クリックすると、複製と削除は選択したすべてに作用します。

## コピー、貼り付け、削除 { #copy-paste-and-delete }

グラフに表示されるのはマップのエンティティなので、次のキーは、ポインターがグラフの上にあるあいだ、選択したエンティティに(ブラシも含めて)作用します。

| キー | 動作 |
| --- | --- |
| Ctrl+C、Ctrl+V | コピーと貼り付け。ポインターの下に置き先となるビューがないので、コピーはワイヤーごと、元からグリッド1つ分ずれた場所に置かれます。ビューの上にポインターを置いて貼り付けると、そこに置かれます |
| Ctrl+D | 複製。こちらも元からグリッド1つ分ずれます |
| Delete | 選択したワイヤーかフレームを取り除きます。何も選択していないときは、選択した**エンティティをマップから**削除します。ノードだけではありません。ほかのエンティティから削除したエンティティへのワイヤーは赤になります。元に戻すと、すべて戻ります |
| Ctrl+A | 表示されているノードだけでなく、マップのすべてを選択します |

## 動き回る { #moving-around }

| やりたいこと | 操作 |
| --- | --- |
| ズーム | ホイールを回す |
| パン | 中ボタンか右ボタンでドラッグする。動かさない右クリックはメニューを開くので、手が震えるとメニューが出ることがあります。Escapeで閉じます |
| 選択 | ノードをクリックする。ShiftかCtrlを押しながらクリックすると追加され、何もない場所でドラッグすると範囲選択になります。エンティティは、ビューとアウトライナーでも選択され、その逆も同じです |
| ビューで表示 | ノードをダブルクリックする |
| 移動 | ノードをドラッグする。位置はマップに保存されます |
| 整頓 | **整列**は、選択したノードをシグナルの流れに沿って並べます。選択が2つ未満のときは、すべてのノードが自動レイアウトに戻ります |
| 全体を見る | **合わせる**、またはポインターがグラフの上にあるときのHome |
| 選択範囲を見る | ポインターがグラフの上にあるときのFで、選択したノードに合わせます |

誰も動かしていないノードは自動レイアウトに従います。シグナルの流れに沿って左から右に並び、自分でズームやパンをするまで、ビューはパネルに収まるように拡大縮小されます。ノードを動かしたり、グラフで配線したりすると、ほかのノードは今の場所に留まり、新しいノードは、配線先の隣に現れます。青や赤のマーカーノードはエンティティではないので、動かせません。それをターゲットにしているノードの隣に置かれます。

## フレーム { #frames }

フレームは、ノードのまとまりの後ろにあるタイトル付きのボックスで、大きなグラフを整理するためのものです。ひとつの建物のドア、パズル、カットシーンなどに使います。ノードを選んで、グラフの上で**C**を押すか、パネルのツールバーの**フレーム**を押して、タイトルを入力します。冒頭の図にある*Hall lights*のボックスが、フレームです。

| やりたいこと | 操作 |
| --- | --- |
| 中身ごとフレームを動かす | タイトルをドラッグする |
| 大きさを変える | 右下の角をドラッグする |
| 名前を変える | タイトルをダブルクリックするか、選択してF2を押す |
| 色を変える、削除する | タイトルを右クリックする。フレームを削除しても、ノードは残ります |

フレームは、エディターのデータとしてマップに保存されます。Godotのビルドは無視します。

## シミュレート { #simulate }

エンティティを1つ選んで**シミュレート**を押し、その出力の1つを選びます。ノードを右クリックしても同じです。グラフでは、その出力が引き起こすすべてのワイヤーに、黄色で番号が付きます。グラフの下の一覧には、各ステップがノードのタイトルで、届く順に、遅延を足した秒数とともに表示されます。**クリア**でプレビューが終わります。ステップをクリックすると、そのワイヤーが選択されます。

![button_2でシミュレートした状態。garage_doorへのワイヤーと、その先のgarage_beaconへのワイヤーが黄色で、1から3の番号が付いている。グラフの下の一覧に各ステップが並んでいる](../assets/logic-graph/simulate.png)

実行時のルールに従います。ターゲットはtargetnameで見つかり、リレー、タイマー、カウンター、ゲート、ドアなどのよくあるエンティティは、チェーンを先へ渡します。`!player`のような実行時のターゲットは表示されますが、先へはたどりません。

複数の出力のうち1つを起動するエンティティは、起動しうるすべてのワイヤーを表示します。それらのステップと、その先のすべては、一覧では`(maybe)`で終わり、ワイヤーの番号には`?`が付きます。カーソルを重ねると、何を待っているかが表示されます。`add`や`subtract`で動くカウンターは、この形で`hit_max`と`hit_min`に続きます。プレビューは押された回数を数えないからです。ステップはそこにあり、カウンターが`max`や`min`に達すると起きます。`logic_sequence`は、`interval`、`times`、`steps`の各プロパティが決める時刻にステップを起動するので、カットシーンはタイムラインのように読めます。

シミュレートは、Godotなしで、紙の上で働きます。ゲームで実際に起きることは、[配線のデバッグ](debugging.md)で説明します。
