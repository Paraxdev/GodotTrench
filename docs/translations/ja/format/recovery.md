# 壊れたファイル { #damaged-files }

壊れたバイナリマップで失われるのは、壊れたチャンクだけで、それ以外は問題なく開きます。リーダーを書くなら、このページが、それに合わせるためにリーダーがやるべきことです。

リーダーは、バイト12から[チャンク](container.md#chunks)をたどっていきます。有効なチャンクヘッダーには、同期マーカー、一致するヘッダーチェック、1 GiB以下の展開後のサイズ、表示可能なタグがあります。有効なヘッダーがない場所では、リーダーは次の同期マーカーを先へ向かって探し、そこから続けます。

`HEAD`、`NODE`、`END`のチャンクは、ペイロードが解凍できない、チェックサムが合わない、サイズが違う、デコードできない、のいずれかのとき捨てられます。

| 壊れ方 | 結果 |
| --- | --- |
| `NODE`チャンク | そこに入っていたノードが失われる |
| ノードの親が失われた | そのノードは、配下のものすべてと一緒に、マップの末尾にある`Recovered`という名前のレイヤーに移される。このレイヤーには読み込み時に新しいidが付く |
| 60階層より深い入れ子 | これも`Recovered`に移されるので、読み込み中にスタックが足りなくなることはない。これが起きるのは細工したファイルだけ |
| `HEAD`チャンク | worldspawnのプロパティとエディターの状態が失われ、マップのバージョンは`END`から取る |
| `HEAD`と`END`の両方 | ファイルを拒否する |
| `END`チャンクがない | ファイルが途中で切れている。最後の完全なチャンクまでが読み込まれる |
| `END`の数が、読んだ数より多い | 足りないノードの数、またはチャンクの数として報告する |

どのリーダーも、失われたものをすべて報告します。

| リーダー | 報告 |
| --- | --- |
| エディター | 読めたものを開き、失われたものをステータスバーに一覧表示して、マップを未保存にする。壊れたプレハブもステータスバーに報告する |
| Godotアドオン | 読めたものを組み立て、失われたものごとに、`[TDM]`とファイルパスを先頭に付けた警告を出力する |
| `trenchdot --dump` | 読めたものを出力し、失われたものをstderrに書く |

エディターは、保存のたびに、古いファイルを`<map>.tdm.bak`にコピーします。そのため、復旧したマップを保存しても、壊れた元のファイルはその隣に残ります。新しいファイルはまず`<map>.tdm.tmp`に書き、それからマップの上にリネームするので、保存の途中でクラッシュしても、書きかけのマップが残ることはありません。
