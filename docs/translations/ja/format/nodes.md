# ノード { #nodes }

マップの内容は、ノードのツリーです。どのノードも外側の形は同じで、キーは次の順に並びます。

| キー | 型 | 書き込まれる条件 | 意味 |
| --- | --- | --- | --- |
| `id` | integer | 常に | マップ内で一意 |
| `type` | string | 常に | `layer`、`group`、`entity`、`brush`、`mesh`、`terrain`、`scatter`、`instance`のいずれか |
| 型ごとのフィールド | | | そのノードの種類のキー。下と、[ジオメトリ](geometry.md)、[地形と散布](terrain-scatter.md)を参照してください |
| `label` | string | 設定したとき | *名前変更*で付けた名前。下を参照してください |
| `graph` | 数値2つの配列 | 設定したとき | エンティティのノードが[ロジックグラフ](../gameplay/logic-graph.md)のどこにあるか |
| `hidden` | bool | `true`のとき | エディターで非表示 |
| `locked` | bool | `true`のとき | エディターで選択も編集もできない |
| `children` | ノードの配列 | 空でないとき | 子ノードを順に並べたもの |

`hidden`と`locked`はエディターの状態にすぎないので、Godotは非表示のノードも組み立てます。何かをビルドから外したいときは、`omit_from_export`を付けたレイヤーに入れてください。

`label`は、エディターでブラシ、メッシュ、エンティティ、インスタンス、地形に付けた名前で、`brush12`のようなデフォルトの名前の代わりに表示されます。レイヤー、グループ、散布セットには付かず、それらは名前を`name`に持っています。

Godotが`label`を使うのは地形だけで、ノードに`terrain_<id>_<label>`という名前を付けます。ブラシとメッシュはエンティティにまとめられ、エンティティのノード名は`targetname`から取られます。このキーができる前のエディターでも、キーを持つファイルは読めますが、保存するときに捨てます。

`graph`もエディターの状態です。ロジックグラフの中でエンティティのノードがある位置で、単位はグラフのポイントです。誰かが動かしたノードにだけ付きます。Godotは無視し、数値2つでない値は読み込み時に捨てられます。

## id { #ids }

idは正の整数で、保存をまたいでも変わらないので、ほかのデータからノードを指せます。Live Linkは編集をidで送り、散布セットはサーフェスをidで指定し、Godotは生成した各ノードのidを`_td_id`メタデータに保存します。`0`のidや重複したid(手で編集したファイルにしか起きません)には、読み込み時に新しいidが付きます。

プレハブは別の`.tdm`ファイルで、独自のidを持つので、コピーを2つ置くと衝突します。これを避けるために、Godotのビルドは、[インスタンス](#instance)が持ち込むすべてのノードのidに、出現番号の100万倍を足します。1つのプレハブの2つのコピーが、どれだけ深く入れ子になっていても、idを共有することはありません。

## ノードの置き場所 { #where-nodes-go }

| ノード | 許される親 |
| --- | --- |
| レイヤー | トップレベルのみ |
| グループ | レイヤーかグループ |
| ブラシ、メッシュ、地形、散布セット、ポイントエンティティ、インスタンス | レイヤーかグループ |
| ブラシエンティティのブラシかメッシュ | そのエンティティ |

子を持つエンティティはブラシエンティティで、たとえばブラシでできたドアがそうです。どのエンティティにも属さないブラシとメッシュは、worldspawnに属します。

## レイヤー { #layer }

マップのトップレベルの区分で、エディターのアウトライナーに表示されます。

| キー | 型 | デフォルト | 意味 |
| --- | --- | --- | --- |
| `name` | string | 必須 | アウトライナーに表示される名前 |
| `color` | string | 必須 | `#rrggbbaa`。読み込み時は`#rrggbb`も受け付けます |
| `omit_from_export` | bool | `false` | 常に書き込まれます。trueのとき、ビルドはレイヤー全体をスキップします。Godotに渡したくない参考用のジオメトリのためのものです |

## グループ { #group }

まとめて選択、移動できるように集めたノードです。

| キー | 型 | デフォルト | 意味 |
| --- | --- | --- | --- |
| `name` | string | 必須 | アウトライナーに表示される名前 |
| `link_id` | integer | 省略 | リンクidを共有するグループは、*リンクして複製*で作ったリンクコピーです |
| `transform` | 数値16個 | 単位行列、省略 | ほかのコピーに対するこのコピーの配置。列優先の4x4行列です |

グループの内容は、ワールド空間で、すでに配置された状態で保存されています。[リンクコピー](../editor/organizing.md#groups)は、1つのコピーに加えた編集をほかのすべてのコピーで繰り返します。`transform`は、エディターがその編集をコピーからコピーへ運ぶために使うものです。Godotのビルドは`transform`も`link_id`も無視します。

## エンティティ { #entity }

| キー | 型 | デフォルト | 意味 |
| --- | --- | --- | --- |
| `classname` | string | 必須 | ゲーム設定にあるエンティティクラス。たとえば`prop_physics` |
| `origin` | `[x, y, z]` | `[0, 0, 0]` | 常に書き込まれます。ポイントエンティティの位置 |
| `angles` | `[pitch, yaw, roll]` | `[0, 0, 0]` | 常に書き込まれます。度で、`rotation_degrees`と同じYXZ順 |
| `properties` | stringからstringへのobject | 省略 | エンティティのキーを名前順に並べたもの |
| `outputs` | array | 省略 | I/Oの接続。下を参照してください |

プロパティの値は、FGDの型にかかわらず常に文字列です。たとえば`"travel": "0 168 0"`のようになります。

`angles`、`angle`、`mangle`のプロパティはノードの`angles`より優先され、Quake流に読まれます。pitchとrollは符号を反転し、ヨーは180度回します。`light`で始まるクラスでは、`mangle`は代わりにヨー、pitch、rollの順です。`angle`が-1か-2なら、真上か真下を向きます。エディターはエンティティを同じ向きで描画し、そこで回転させると、プロパティはノードの`angles`に移ります。

ブラシエンティティのブラシはすでに正しい位置にあるので、ビルドはその`origin`と`angles`を無視します。

各outputは1つの[I/O接続](../gameplay/io.md)です。このエンティティがシグナルを発したら、ターゲットのメソッドを呼びます。

| キー | 型 | デフォルト | 意味 |
| --- | --- | --- | --- |
| `output` | string | 必須 | 接続を起動する、このエンティティのシグナル |
| `target` | string | 必須 | 呼び出しを受け取る相手。[ターゲット](../gameplay/parameters.md#targets)を参照してください |
| `input` | string | 必須 | ターゲットで呼ぶメソッド |
| `parameter` | string | `""`、省略 | インプットに渡す値 |
| `delay` | number | `0`、省略 | 呼び出すまで待つ秒数 |
| `times` | integer | `-1`、省略 | 発火できる回数。毎回なら`-1` |

## インスタンス { #instance }

別の`.tdm`ファイルへの参照で、位置と回転を付けて配置します。Hammerの`func_instance`と同じ考え方です。プレハブはこうして配置されます。内容は専用のファイルに1つだけあり、すべてのインスタンスがそれを表示します。

| キー | 型 | デフォルト | 意味 |
| --- | --- | --- | --- |
| `path` | string | 必須 | 参照するマップ。参照元のマップからの相対パス、絶対パス、または`res://` |
| `origin` | `[x, y, z]` | 必須 | インスタンスを置く場所 |
| `angles` | `[pitch, yaw, roll]` | 必須 | 度で、YXZ順 |
| `fixup` | string | `""`、省略 | インスタンスの内容に付ける名前の接頭辞。下を参照してください |

ビルドは、参照先のマップでエクスポートから外されていないすべてのレイヤーの子を取り、`origin`と`angles`だけ動かします。テクスチャ投影はジオメトリと一緒に動きます。参照先のマップのworldspawnは使いません。インスタンスは8階層まで入れ子にできます。

Godotのビルドは、参照先の各マップを1回だけ読み、1つのマップのすべてのインスタンスを合わせて、2,097,152個までの値を追加できます。値とは、参照先のマップの配列の要素か辞書のエントリのことで、テキストは8文字ごとに1つ余分に数えます。それを超えると、ビルドは残りのインスタンスを除外してエラーを報告します。普通のマップはこれよりずっと下にとどまり、インスタンスのインスタンスを何重にも掛け合わせたときだけ届きます。

フィックスアップが`p1`なら、`door`は、`targetname`、`target`、`destination`、`call_target`、FGDが`target_source`か`target_destination`と宣言したすべてのプロパティ、およびすべてのoutputの`target`で、`p1-door`になります。`!`、`@`、`/`で始まる値はそのままです。入れ子のフィックスアップは外側から順に足されるので、`a`の中の`b`は`a-b-door`になり、エディターの*インスタンスを分解*でも同じ名前になります。
