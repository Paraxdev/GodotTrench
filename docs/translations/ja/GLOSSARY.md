# 用語集 { #glossary }

## 3Dカーソル { #3d-cursor }
最後にマウスを重ねたビューで、マウスの下にある世界の中の点です。カーソルの位置に置くものはそこに入ります。たとえば、エンティティパネルの「配置」ボタンで置くエンティティや、新しい地形です。

## アクティベーター { #activator }
エンティティI/Oの連鎖を始めたプレイヤーやボディのことで、たいていはボタンを押した人やトリガーに踏み込んだ人です。連鎖の後ろのステップでターゲットに!activatorを指定すると、まさにその一つだけに作用させられます。

## アルベド { #albedo }
マテリアルの基本の色のことで、ライティングや法線マップや発光が加わる前の、素のテクスチャです。Godotでは、マテリアルのカラーテクスチャをアルベドテクスチャと呼びます。

## アルファシザー { #alpha-scissor }
テクスチャをアルファのしきい値でばっさり切り落とす、Godotの透明モードです。どのピクセルも、完全に見えるか完全に消えるかのどちらかになります。格子、葉、エッジのくっきりしたデカールに向いていて、アルファブレンドと違って影も落とします。

## オートロード { #autoload }
Godotが起動時に一度だけ読み込み、ゲーム全体を通して生かし続けるスクリプトやシーンのことです。Project Settings > Globals > Autoloadで設定します。スコア管理やホットリロードのリスナーのような、ゲーム全体で使うコードがここに入ります。

## ベイクしたライティング { #baked-lighting }
フレームごとに計算し直すのではなく、あらかじめ一度だけトレースして保存しておいた光のことです。Godot > ライティングをベイクで、太陽、空、ランプ、光るマテリアルがライトマップにベイクされ、GodotはそれをLightmapGIで描画します。

## ブルーム { #bloom }
明るいランプや光るマテリアルが、周りのピクセルににじませるやわらかい輝きです。worldspawnのキーglow_intensityでオンにします。

## ブール値 { #boolean }
オンかオフか、といった、真か偽のどちらかになる値です。logic_branch、logic_gate、logic_flipflopの各エンティティが、ブール値を保存したり組み合わせたりします。

## ブラシ { #brush }
ボックスやくさびのような凸形の立体で、レベルの基本の部品です。ビューでブラシを描き、CSGで組み合わせると、Godotがそれぞれを、合った当たり判定付きのメッシュに変えます。

## ブラシエンティティ { #brush-entity }
ドア、ボタン、トリガーのように、自分で作ったブラシから形を受け取るエンティティです。先にブラシを描いてからエンティティにします。一点に置くポイントエンティティとは違います。

## 凸形 { #convex }
ボックス、くさび、円柱のように、どこも外側にふくらんでいて、へこみやくぼみがない形のことです。ブラシはすべて凸形でなければならないので、エディターは、ブラシをへこませる頂点の移動を受け付けません。凹んだ形にしたいときは、ブラシをメッシュに変換します。

## コードン { #cordon }
作業中にマップを一つの領域に絞り込むボックスです。コードンを有効にすると、ボックスの外にあるオブジェクトは隠れ、コードンを使ったエクスポートからも外れます。

## CSG { #csg }
Constructive Solid Geometry（構成的ソリッドジオメトリ）の略で、立体を組み合わせて形を作る方法です。たとえば、あるブラシを別のブラシから引いてドア口を切り抜きます。エディターのCSGコマンドは、減算、中空化、凸マージ、交差です。

## デカール { #decal }
しみ、ひび割れ、ポスターのように、面の上に重ねるテクスチャです。TrenchDotではデカールは面の上に乗る薄いメッシュで、ちらつきません。Altを押しながらマテリアルを面にドロップして置きます。投影デカールは、代わりにボックスの中にあるすべてのものにマテリアルを投影するエンティティです。

## タイル解消 { #detile }
0から1の値を取る地形レイヤーの設定で、テクスチャの繰り返しの一つひとつをランダムに回転、移動して、広い地面に目立つ格子模様が出ないようにします。テクスチャの読み込みが増えるので、繰り返しが目立たない場所では0のままにしてください。

## ディスプレイスメント { #displacement }
四角形のブラシの面を頂点の格子に分割して、頂点をそれぞれ上げ下げできるようにしたものです。Hammerにある機能と同じです。ブラシで組んだレベルの中に起伏のある地面を作れます。広い屋外は地形で作るほうが向いています。

## エンティティ定義 { #entity-definition }
FGDの中の、エンティティクラス一つの記述です。classname、キー、インプットとアウトプット、そしてノードクラスやスクリプトなど、Godotがそのために作るものが入っています。GodotではFuncGodotFGDPointClassかFuncGodotFGDSolidClassのリソースで、FGDファイルのEntity Definitionsに並びます。

## フォールオフ { #falloff }
ブレンドツールなどのペイントブラシが、中心から端に向かってどう薄れるかのことです。なめらかなフォールオフだと縁がやわらかくなり、一定にすると円全体が同じ強さで塗られます。

## FGD { #fgd }
ゲームのエンティティクラスの定義で、名前、キー、インプット、アウトプットを持ちます。名前の由来はHammerのForge Game Dataファイルです。GodotではFuncGodotFGDFileリソースで、ゲーム設定がそれをエディターに渡します。

## フィックスアップ { #fixup }
プレハブのインスタンスに付ける名前の接頭辞です。フィックスアップがp1なら、その中のdoorという名前のエンティティはp1-doorになるので、同じプレハブを何個置いても、それぞれの配線が混ざりません。

## func_detail { #func_detail }
当たり判定のある静的ジオメトリのための、FuncGodotのブラシエンティティです。ワールドのブラシとは別の、独立したノードとしてビルドされます。オクルーダーは追加しないので、後ろのオブジェクトを描画から隠すことはありません。

## func_illusionary { #func_illusionary }
見えるけれど当たり判定がないFuncGodotのブラシエンティティで、プレイヤーは通り抜けられます。海の島のチュートリアルでは、水にこれを使っています。

## FuncGodot { #funcgodot }
Quake系のマップファイルからレベルを作るためのGodotプラグインです。TrenchDotのアドオンはこれのフォークなので、ノードの名前がFuncGodotMapで、リソースの名前がFuncGodotで始まります。

## ゲーム設定 { #game-config }
アドオンが書き出す、Godotプロジェクトのルートにあるtrenchdot_game.jsonというファイルです。あなたのプロジェクトが使うエンティティ、テクスチャフォルダ、単位のスケールをエディターに伝えます。アドオンが書き直すたびに、エディターが読み込み直します。

## ゲームプレイエンティティパック { #gameplay-entities-pack }
エンティティリファレンスにある、ドア、ボタン、リフト、トリガー、ロジック、スポナー、プロップ、エフェクトのことです。アドオン本体には含まれません。パックをインストールすると、それらの定義とスクリプトがres://trenchdot/entitiesにコピーされ、あなたのプロジェクトのものになるので、自由に変更できます。

## glTF { #gltf }
Blender、Godot、ほとんどの3Dツールが読める、3Dモデルとシーンのオープンなファイル形式です。.glbファイルはそのバイナリ形式で、ジオメトリとテクスチャを一つのファイルにまとめています。

## Godotグループ { #godot-group }
Godotのノードに付ける名前付きのタグで、Node > Groupsやコードから設定します。コードやエンティティI/Oが、該当するノードをまとめて見つけられます。@enemiesのようなターゲットは、enemiesグループのすべてのノードに届きます。

## Hammer { #hammer }
Half-Life 2のようなSourceエンジンのゲームのための、Valveのレベルエディタです。TrenchDotはエンティティのインプットとアウトプットの考え方を借りていて、.vmfマップをインポートできます。

## ホットリロード { #hot-reload }
TrenchDotで保存するたびに、すでに実行中のゲームのマップを作り直すしくみです。変更を見るためにゲームを再起動する必要がありません。ゲームにtrenchdot_hot_reload.gdのオートロードが必要です。

## ホットスポット { #hotspot }
トリムシートの上に印を付けた矩形で、テクスチャの.hotspots.jsonファイルに保存されます。ホットスポット合わせは、選択した面を、いちばん合う矩形にぴったり合わせるので、トリムシートで部屋を手早くテクスチャリングできます。

## ライトマップ { #light-map }
静的ジオメトリのあらゆる場所に届く光を、跳ね返りも含めて保持するテクスチャです。面ごとに、その中の専用の領域が割り当てられます。

## ライトプローブ { #light-probe }
開けた空間にある一点で、あらゆる方向から届く光を保存します。動くオブジェクトは周りのプローブから光を受け取るので、静的ジオメトリのベイクしたライティングになじみます。

## LightmapGI { #lightmapgi }
ライトマップとライトプローブを描画する、Godotのノードです。ベイクした.tdmから作られたマップには、baked_lightingという名前のものが一つ付きます。

## ライトプレビュー { #lit-preview }
エディターの3Dビューのシェーディングモードで、F3で切り替えます。マップのライト、太陽の影、空、フォグを表示します。Godotでビルドする前にライティングを見極めるのに向いていますが、描画されるのは、いちばん強い64個のポイントライトとスポットライトだけです。

## Live Link { #live-link }
TrenchDotとGodotエディターのつながりで、アドオンがポート7842で動かすローカルサーバーです。保存時の再ビルド、ライブモード、ツールバーのGodotの状態表示は、すべてこれを通ります。

## ライブモード { #live-mode }
編集した内容を、保存する前から、Godotエディターで開いているシーンに反映していきます。Godot自身のレンダラーで、ライティングやスケールを確かめられます。ツールバーのリンクボタンか、Godot > ライブモードでオンにします。

## ロジックゲート { #logic-gate }
真か偽の入力を二つ受け取って、一つの答えにするルールです。and（両方が真）やxor（ちょうど片方が真）などがあります。logic_gateエンティティに、よく使うものが揃っています。

## メインシーン { #main-scene }
プロジェクトを実行したときにGodotが再生するシーンで、Project > Project Settings > Application > Runで設定します。TrenchDotの「プロジェクトを実行」も、Godotの再生ボタンも、これを起動します。

## マップ設定 { #map-settings }
テクスチャ、マテリアル、エンティティ定義の出どころと、1メートルが何マップユニットかを定める、FuncGodotMapSettingsリソースです。FuncGodotMapは自分用のものを持てて、持っていなければプロジェクトの既定のものが使われます。

## MCP { #mcp }
Model Context Protocolの略で、AIエージェントやスクリプトがプログラムのツールを呼び出すための標準的な方法です。エディターはMCPサーバーを動かせて、エージェントがマップを調べたり編集したりできます。レベル作りには必要なく、このドキュメントでは、ヘッダーのMCPスイッチをオンにするまで、MCPに関する部分を隠しています。

## MultiMesh { #multimeshes }
一つのメッシュの多数のコピーを、1回の描画でまとめて描くGodotのしくみです。散布した木、岩、草はMultiMeshとして作られるので、何千個あっても描画が軽く済みます。

## ナビゲーションメッシュ { #navigation-mesh }
AIエージェントが歩ける床を簡略化した輪郭で、Godotが経路探索に使います。TrenchDotNavが、ビルドしたマップの当たり判定からこれをベイクします。

## 法線マップ { #normal-map }
面の各ピクセルがどちらを向いているかを保存するテクスチャで、平らな面が、凹凸や溝があるかのように光を受けます。ジオメトリを増やさずに、細かいディテールを加えられます。

## オペランド { #operand }
計算が、受け取った数のほかに使う数のことです。5を足すmath_calcでは、オペランドは5です。

## ORM { #orm }
三つのグレースケールマップを色チャンネルに詰め込んだテクスチャで、赤にアンビエントオクルージョン、緑にラフネス、青にメタリックが入っています。GodotのマテリアルとTrenchDotの地形レイヤーは、これを一つのファイルとして読みます。

## ポイントエンティティ { #point-entity }
ブラシから形を受け取らず、一点に置かれるエンティティで、ライト、サウンド、スポーン地点などがあります。エンティティパネルからビューにドラッグして置きます。

## プレハブ { #prefab }
独立した.tdmファイルとして保存され、ほかのマップにインスタンスとして置ける、マップの再利用可能な一部分です。プレハブのファイルを編集すると、そのインスタンスがすべて更新されます。

## res:// { #res }
Godotがプロジェクトフォルダの中のパスを書く方法で、そのフォルダがディスク上でどんな名前でも変わりません。res://maps/room.tdmは、あなたのGodotプロジェクトのmapsフォルダにあるroom.tdmのことです。アドオンが見つけられるように、マップとモデルをプロジェクトの中に保存しなければならないのは、このためです。

## 制限モード { #restricted-mode }
コードを含み、まだ信頼していないGodotプロジェクトを、TrenchDotが開くときのモードです。マップの表示と編集はできますが、エディターは、そのプロジェクトでGodotを起動せず、Godotでのビルドもライブ編集の送信もしません。Godotはプロジェクトを開く、再生する、ビルドするときに、そのスクリプトを実行するからです。プロジェクトを信頼するには、ステータスバーの「制限モード」をクリックします。

## 散布セット { #scatter-set }
森や草原のように、散布ツールでまとめてペイントするモデルのグループで、専用のレイヤー、密度、対象の面を持ちます。Godotは各セットをMultiMeshとして作ります。

## スクリーンスペースリフレクション { #screen-space-reflections }
すでに画面に映っているものをつやのある面に映す、Godotのエフェクトで、濡れた道路がランプを映すようになります。worldspawnのキーssrを1にしてオンにします。

## シグナル { #signal }
ボタンが押されたときなど、ノードが知らせるイベントを指すGodotの呼び名です。エンティティのアウトプットはすべてシグナルで、アウトプットを配線すると、そのシグナルが、ターゲットのインプットのメソッドにつながります。

## targetname { #targetname }
main_doorのように、ほかのエンティティから届くようにするために、エンティティに付ける名前です。アウトプット、プレハブのフィックスアップ、fixtureなどのキーが、これでエンティティを見つけます。

## テクセル { #texel }
面に載ったときの、テクスチャの1ピクセルです。既定では1テクセルが1マップユニットを覆い、テクセル密度、つまり一定の面積に入るテクセルの数で、テクスチャの鮮明さが決まります。ライトマップにもテクセルがあり、そのテクセルサイズで、1テクセルが何マップユニットを覆うかが決まります。

## テクスチャサイズ { #texture-size }
テクスチャの1回の繰り返しが覆う、世界での大きさです。Godotのマテリアルにmetadata/texture_sizeとして設定します。ないと1ピクセルが1マップユニットを覆うので、高解像度の写真が広大な範囲に引き伸ばされます。

## ツールテクスチャ { #tool-textures }
面を描画するのではなく、ブラシの面が何のためのものかをビルドに伝える特別なテクスチャです。clipの面は当たり判定だけを持ち、skipの面は何も作らず、originの面はブラシエンティティの原点の位置を決めます。special/、tools/、td/フォルダのテクスチャはどれも、Godotで何も描画せず、どのフォルダにあってもnodraw、hint、triggerなどのツール名のものも同じです。

## TrenchBroom { #trenchbroom }
Quake系のゲームのための、無料のレベルエディタです。TrenchDotは多くの着想をこれから得ていて、その.mapファイルをインポートできます。

## トリガーボリューム { #trigger-volume }
ボディが出入りしたときにアウトプットを発火する、見えないブラシエンティティです。たとえば、プレイヤーが部屋に入ったらカットシーンを始めるのに使います。ボリュームツール（Shift+E）で描きます。

## トリムシート { #trim-sheet }
縁、パイプ、パネルなどのディテールの帯を一枚の画像に詰め込んだテクスチャです。面をホットスポットでその各部分に合わせるので、数枚のトリムシートで建物全体をテクスチャリングできます。

## トリプラナー { #triplanar }
テクスチャを、上と横の二つから、三方向で面に投影し、面の角度に応じてブレンドする方法です。地形レイヤーがこれを使うので、崖が引き伸ばされたにじみではなく、岩として見えます。

## UVロック { #uv-lock }
既定でオンで、Ctrl+Shift+Uで切り替える設定です。ブラシを動かしている間、テクスチャがブラシに貼り付いたままになります。オフにすると、テクスチャは世界に留まり、動かした面の上をすべります。

## UV { #uv }
テクスチャのどの部分が面のどの点に載るかを示す座標で、Uがテクスチャの横方向、Vが縦方向です。ブラシの面は、たいていは投影から得ますが、メッシュや一部の面は、頂点ごとに自分の値を持ちます。

## worldspawn { #worldspawn }
ワールドのブラシを持つ、マップのルートのエンティティです。そのキーには、空、フォグ、太陽、ストリーミングなど、マップ全体の設定が入っていて、何も選択していないときはインスペクターに表示されます。

## ヨー { #yaw }
垂直な軸まわりの回転で、上から見たときにものが向く方向です。テレポートの行き先のヨーが、到着後にボディがどちらを向くかを決めます。

## Zファイティング { #z-fighting }
二つの面が同じ平面か、そのごく近くにあるときに出る、ちらつく縞模様です。GPUはどちらが手前かを判断できないので、ピクセルごとにどちらか一方が表示され、カメラが動くと模様も変わります。デカールならこれを避けられますが、壁に重ねた薄いブラシでは避けられません。
