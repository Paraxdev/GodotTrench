# はじめの一歩 { #getting-started }

ステップ1から3は最初の設定です。すでにTrenchDot用に設定したGodotプロジェクトがあるなら、飛ばして構いません。

ステップ4と5では、TrenchDotで最初の部屋を作り、Godotで見てみます。

## 必要なもの { #what-you-need }

* Godot 4.7以降。C#でエンティティを書きたい場合は.NET版
* 最新の[TrenchDotリリース](https://github.com/Paraxdev/TrenchDot/releases/tag/beta)

## TrenchDotがGodotの実行ファイルを見つけられるようにする { #ensure-trenchdot-can-see-the-godot-executable }

TrenchDotがインストール済みのGodotを見つけられることを確かめましょう。正しく検出されているかは、*ファイル > 環境設定… > Godot実行ファイル*で確認できます。

TrenchDotがGodotを自動で見つけていれば、入力欄の下の行にすでにパスと「使用中」が表示されています。代わりに「見つかりません」と表示されている場合は、ディスク上で実行ファイルを探す必要があります。

入力欄の横の「…」ボタンをクリックして

![Godot実行ファイルの入力欄の横にある…ボタン](assets/getting-started/godot-path-browse.png)

「Godot_v」で始まる実行ファイルを選びます。

正しい実行ファイルを選べていれば、選んだばかりのパスと「使用中」が表示されます。

![入力欄の下の行に、Godot実行ファイルへのパスと使用中の表示が出ている](assets/getting-started/godot-path-using.png)

## 1. Godotでプロジェクトを作る { #1-create-a-project-in-godot }

Godotを開き、左上の「Create」をクリックします。

![Godotのプロジェクトマネージャー。左上にプラスのアイコンが付いたCreateボタン](assets/getting-started/godot-create-project.png)

プロジェクト名を決め（このチュートリアルではTrenchDotTestとします）、必要ならプロジェクトを置くフォルダを選びます。

そして「Create」を押します。

## 2. TrenchDotでプロジェクトを開く { #2-opening-the-project-within-trenchdot }

*Godot > Godotプロジェクトを開く…*を選ぶか

![TrenchDotのGodotメニューで、Godotプロジェクトを開く…が強調されている](assets/getting-started/menu-open-godot-project.png)

ツールバー右上の**Godotプロジェクトを開く…**ボタンを押し

![TrenchDotのツールバー右上にあるGodotプロジェクトを開く…ボタン。プロジェクトを開くとプロジェクト名が表示される](assets/getting-started/toolbar-open-godot-project.png)

プロジェクトのフォルダか、その中の任意のフォルダを選びます。エディターは次の起動時にも、このプロジェクトを開き直します。

## 3. ウェルカム画面 { #3-the-welcome-screen }

新しいGodotプロジェクトだとTrenchDotが判断すると、*このプロジェクトを設定*ウィンドウが表示されます。

![このプロジェクトを設定ウィンドウ。アドオン、ゲームプレイエンティティ、用意済みコンテンツの各セクションがある](assets/getting-started/setup-window.png)

ここでは、Godotがマップをシーンに変換してTrenchDotと通信するために必要なアドオンをダウンロードできます。追加コンテンツも、必要ならここで入れられます。もちろん、何も入れずに始めることもできます。

`info_player_start`や`light`のような最小限のエンティティは、いつでも含まれています。

1. アドオンをインストールする

    上にある「アドオンをインストール」ボタンをクリックすると、FuncGodotのTrenchDot版フォークがプロジェクトにダウンロードされます。TrenchDotには欠かせない手順です。（注：ダウンロードはGitHubのリリースから行います。インターネットに接続できない場合は、先に`func_godot-trenchdot-addon.zip`をダウンロードして、プロジェクトのルートに展開し、手作業でインストールしてください。）

    終わったら「プラグインを有効にする」をクリックして、Godotに読み込ませます。（注：先にGodotを閉じてください。プロジェクトをGodotが開いたままだと、Godotが自分の`project.godot`を書き戻してしまい、プラグインは無効のままになります。）

2. ゲームプレイエンティティをインストールする

    アドオンの下にある**ゲームプレイエンティティをインストール**をクリックします。

    ![このプロジェクトを設定ウィンドウのゲームプレイエンティティのセクションと、ゲームプレイエンティティをインストールボタン](assets/getting-started/setup-gameplay-entities.png)

    ドア、ボタン、リフト、トリガー、プロップ、スポナーは、このパックに入っています。パックがないと、Godotはそれらを当たり判定のない、何も起きない単なる形としてビルドします。ゲームプレイメニューのドアやトリガーのヘルパーは、初めて使うときにパックを自動でインストールしますが、Godotが初めてプロジェクトを開く前にここでインストールしておけば、パックなしでビルドされるシーンは一つもなくなります。

3. （任意）追加コンテンツ

    TrenchDotには、あらかじめ読み込める任意のコンテンツがあります。Poly HavenとambientCGのCC0テクスチャとモデル、それにTrenchDot用に作ったモデルです。ライセンスと、それぞれの出どころの一覧も付いています。

    追加コンテンツが要らなければ「追加なし」を選んでください。最小限のエンティティは含まれたままです。

4. プロジェクトをGodotで一度開く

    プラグインを有効にしたら、プロジェクトをGodotで開きます（ウィンドウに、そのための「Godotエディターでプロジェクトを開く」ボタンがあります）。するとアドオンが、プロジェクトのルートに`trenchdot_game.json`というファイルを作ります。TrenchDotはこのファイルからテクスチャとエンティティを知り、1秒ほどで読み込みます。

    アドオンはファイルが変わるたびに書き直すので、手で編集する必要はありません。このファイルができるまでステータスバーには`trenchdot_game.json`がないと表示され、エディターはコアのエンティティと、インストール済みならゲームプレイエンティティを提供します。

自分のエンティティを追加するには、[GDScriptで作るオリジナルエンティティ](gameplay/custom-entities.md)と[C#のエンティティ](gameplay/csharp.md)をご覧ください。それらを一覧にするリソースは[プロジェクトの設定](godot/project-setup.md)で説明しています。

## 4. 部屋を作る { #4-build-a-room }

エディターには主なビューが4つあります。Godotと同じように飛び回れる3Dビューと、上、前、側面から見る3つのワイヤーフレームビューです。

ブラシや操作はグリッドサイズに左右されます。ツールバーでグリッドサイズを設定できます（小さいほど細かくなります）。

![ツールバーのグリッドサイズ設定。16になっている](assets/getting-started/toolbar-grid-size.png)

空のレベルでは、描き方を説明する短いヒントが表示されます。「ヒントを隠す」で消すか、そのまま描き始めてください。マップに何かが入ると自然に消えます。

![新しいマップ。3Dビューのカードがトップビューをドラッグして最初のボックスを描くよう案内し、トップビューには黄色の「ここをドラッグして最初のボックスを描きましょう」というラベルが出ている](assets/getting-started/empty-map.png)

1. 最初のボックスを描く

    選択ツール（Q）で、どれかのビューの何もない場所をドラッグします。ボックスが描かれていくはずです。左クリックを押したままマウスを動かして、矩形の形を決めます。

    ![4つのビューすべてに最初のボックスが描かれ、トップビューにサイズの512×256が表示されている](assets/getting-started/draw-first-box.png)

2. 高さを足す

    サイドビューで、ボックスの上の辺にマウスを重ねて黄色になるのを待ち、左クリックを押したまま、ボックスの高さが256ユニットになるまでマウスを上に動かします。

    ![サイドビューでボックスの上の辺を引き上げたところ。上と横に256と表示されている](assets/getting-started/side-view-depth.png)

3. 中空にする

    Ctrl+Shift+Kを押すか、ツールバーの中空化ボタンを使います。

    ![中空化ボタンにカーソルを重ねてツールチップが出ているツールバー](assets/getting-started/toolbar-hollow.png)

    ボックスが壁、床、天井に分かれました。小さな部屋や廊下を作るのにぴったりです。続いて、飛行操作（右マウスボタンを押したままWASD）で、中空になったボックスの中に入ります。

4. ドア口を切り抜く

    Escapeで、選択中のブラシの選択を解除できます。何も選択していない状態で、フロントビューのボックスの中に、ドア口の形をした小さな縦長の矩形を描きます。

    ![中空のボックスの中にあるドアのブラシ。フロントビューで幅64、高さ96](assets/getting-started/doorway-brush.png)

    次にサイドビューで、ドアのブラシの片側を伸ばして奥行きを持たせ、壁を貫通させます。

    ![サイドビューでドアのブラシの片側をドラッグして、壁を貫通させている](assets/getting-started/doorway-extend.gif)

    ブラシを選択したまま、Ctrl+Kを押すか、ツールバーの減算ボタンを使います。

    ![CSGの減算ボタンにカーソルを重ねてツールチップが出ているツールバー](assets/getting-started/toolbar-subtract.png)

    ブラシが消えて、壁にドア口が切り抜かれるはずです。

    ![3Dビューの壁に切り抜かれたドア口](assets/getting-started/doorway-cut.png)

5. テクスチャを貼る

    プロトタイプ用のテクスチャが5つ付いているはずです。ドア枠のように一つの面だけにテクスチャを貼るには、マテリアルタブからその面にテクスチャをドラッグします（Shiftを押しながらだとブラシ全体に貼れます）。

    ![マテリアルタブからdev/blueを面にドラッグしているところ。ドロップのプレビューが出ている](assets/getting-started/texture-drop.png)

6. マップを保存する

    変更をGodotで見るには、マップを保存する必要があります。Ctrl+Sを押すか、*ファイル > 保存*を使います。

    保存ダイアログはGodotプロジェクトのフォルダで開きます。プロジェクトの中ならどこに保存しても構いません。プロジェクトのルートに`maps`フォルダを作るとすっきりするので、たとえば`res://maps/room.tdm`にします。（注：フォルダ名は自由ですが、Godotが`res://`パスで読み込めるように、マップはプロジェクトの中に置いてください。）

    保存すると、*ファイル > プロジェクト内のマップ*に表示されます。

    ![ファイルメニューの保存とプロジェクト内のマップ。後者にres://mapsの下のroomが並んでいる](assets/getting-started/file-menu-maps-in-project.png)

## 5. Godotで見てみる { #5-see-it-in-godot }

Godotではレベルはシーンです。シーンはノードのツリーで、`.tscn`ファイルとして保存され、各ノードがメッシュ、ライト、カメラなど一つのものを表します。Godotはプロジェクト内のパスを`res://`で書くので、`res://maps/room.tdm`はプロジェクトフォルダにある`maps/room.tdm`のことです。マップをノードに変換するのは、アドオンのノード`FuncGodotMap`です。

1. Godotエディターで*Scene > New Scene*を選び、左のSceneパネルにある**3D Scene**をクリックします。
2. Ctrl+A（*Add Child Node*）を押して`FuncGodotMap`を検索し、追加します。
3. 追加したノードを選択した状態で、Godot自身のInspector（Godotエディターの右にあるパネル）で*Local Map File*にあなたの`.tdm`を設定します。TrenchDotのインスペクターと同じように使えますが、こちらはGodotのものです。
4. そのInspectorの上にある**Build Map**を押して、Ctrl+Sでシーンを保存します。

ブラシは当たり判定付きのメッシュに、エンティティはスクリプト付きのノードになり、シーンと一緒に保存されます。ノードのほかの設定は[マップのビルド](godot/building.md)で説明しています。エンティティが当たり判定のない素のメッシュになった場合は、TrenchDotのステータスバーに理由が表示されます。[何も起きないエンティティ](godot/entities-troubleshooting.md)をご覧ください。

そのシーンをGodotで開いたままにしておくと、TrenchDotで保存するたびにシーンが再ビルドされます。そのシーンのタブが前面にあればすぐに、そうでなければそのタブに戻ったときに再ビルドされます。結果を残すには、Godotでシーンを保存してください。保存しても再ビルドされない場合は、ステータスバーに理由が出ます。[保存時の再ビルド](godot/live.md#rebuild-on-save)をご覧ください。

> [!WARNING]
> ビルドすると、まず`FuncGodotMap`の子ノードがすべて削除されます。自分のノードはマップノードの隣か、[オーバーレイ](godot/overlays.md)に置いてください。

## デモプロジェクトを試す { #try-the-demo-project }

リポジトリの`godot`フォルダは、リリースでは`trenchdot-demo-project.zip`としても配布されていて、アドオンが入ったプロジェクトです。メインシーンはショーケースのマップを再生します。マップは`godot/demo/maps/showcase`に保存されています。このプロジェクトをエディターで開き、*ファイル > プロジェクト内のマップ*から一つ選ぶと、完成したマップの組み立て方を見られます。

*Godot > プロジェクトにコンテンツを追加…*でデモを選ぶと、同じマップとシーンが自分のプロジェクトに入ります。Godotで`res://demo/demo.tscn`を開き、F6を押すと再生できます。自分のプロジェクトからTrenchDotで開くと、テクスチャなしで表示されます。マップが使っているのは、あなたのプロジェクトのテクスチャではなく、デモのテクスチャフォルダ`res://demo/textures`だからです。デモプロジェクトなら、作られたとおりに見られます。

| キー | 動作 |
| --- | --- |
| WASD、Space、Shift | 歩く、ジャンプ、走る |
| E | ドアやボタンを使う |
| 1から5 | ショーケースのマップを切り替える |
| F3 | I/Oデバッグオーバーレイを表示する。入力と出力が発火するたびのログと、描画されたトリガーボリュームが出る |

## 次へ { #next }

部屋に何かをさせるには、[エンティティI/Oのしくみ](gameplay/io.md)を読んで、[ボタンでドアを開ける](tutorials/button-door.md)を作ってみてください。

自分のプレイヤーには、パックのエンティティのために2つ必要なことがあります。トリガーが反応するのは、物理レイヤー1にあるGodotグループ`player`のボディだけなので、プレイヤーをそこに置いてください。ドアとボタンは、プレイヤーのコードが、見ているものに対して`use()`を呼ぶと動きます。[プレイヤーが押せるようにする](tutorials/button-door.md#let-the-player-press-it)をご覧ください。

## MCP { #mcp }

MCPクライアントが操作しているエディターでは、コンテンツの確認は自動では開きません。`get_state`、`screenshot`、`simulate_input`以外の最初のツール呼び出しで閉じられ、`open_project`で開いたプロジェクトでは確認されません。`project_content`で同じコンテンツを追加できます。[MCP](mcp.md)をご覧ください。
