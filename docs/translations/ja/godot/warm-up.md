# シェーダーのウォームアップ { #shader-warm-up }

Godotはシェーダーを初めて描画するときにコンパイルするので、プレイ開始の最初のフレームがカクつきます。ウォームアップは、その作業をローディング画面の裏で済ませてしまう仕組みです。

ゲームがマップだけなら、何もする必要はありません。どのマップも、実行中のゲームでビルドまたは読み込みが終わると自分でウォームアップを行い、終わったら`warmed_up`を発行します。

ただし、マップ自身のウォームアップが対象にするのはマップだけです。プレイヤー、敵、武器のように、ゲームが独自のコンテンツを追加する場合、それらが初めて登場するときはやはりカクつきます。その場合は、Godotのインスペクターで`FuncGodotMap`の**Warm Up Shaders**のチェックを外し、すべてが揃ってから一度にまとめてウォームアップします。

```gdscript
loading.show()
await build_maps()
spawn_player()
await TrenchDotWarmUp.warm_shaders([get_tree().current_scene, preload("res://enemies/crawler.tscn")]).finished
loading.hide()
```

`warm_shaders`は、ノード、シーン、メッシュ、マテリアルを受け取ります。上の敵のように、まだ生成していないシーンも渡しておくと、登場したときにはもう準備ができています。画面には何も描画せず、それらのスクリプトも実行しません。`progress(done, total)`のシグナルをつなげば、ローディングバーを動かせます。

マップが5つあるテストゲームでは、0.5秒のウォームアップで、プレイ開始の最初のフレームが360msから22msになりました。

> [!TIP]
> エクスポートプリセットで**Shader Baker**もオンにすると、プレイヤーは初回起動時のシェーダーのコンパイルを省けます。
