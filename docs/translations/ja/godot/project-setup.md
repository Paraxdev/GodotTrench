# プロジェクトのセットアップ { #project-setup }

最初のマップなら、アドオンのデフォルトで十分です。自分のエンティティを書くとき、または別のテクスチャフォルダを使いたいときは、プロジェクト専用のリソースを用意してください。アドオンを更新すると、デフォルトは置き換えられるからです。

## アドオンをインストール、更新する { #installing-and-updating-the-addon }

TrenchDotは、プロジェクトを開くたびに、そのアドオンを確認します。`addons/func_godot`がないか、エディターと異なるバージョンのときは、*このプロジェクトを設定*ウィンドウが一度表示され、ステータスバーの右下に黄色の注意書きが残ります。カーソルを重ねると両方のバージョンが表示され、クリックするとウィンドウがもう一度出ます。

![黄色の「アドオン 0.0.9、エディター 0.1.0」の注意書きにカーソルを重ね、そのツールチップが表示されたステータスバー](../assets/project-setup/status-addon-mismatch.png)

*Godot > アドオンをインストールまたは更新…*から、いつでもウィンドウを開けます。

![アドオンをインストールまたは更新…にカーソルを重ねたGodotメニュー](../assets/project-setup/menu-install-update-addon.png)

ウィンドウが提案するのは、プロジェクトが次に必要とする手順だけです。

| プロジェクトの状態 | ウィンドウが提案すること |
| --- | --- |
| アドオンがない | **アドオンをインストール**、続いて**プラグインを有効にする** |
| 古いアドオンがある | エディターのバージョンへ**アドオンを … に更新** |
| 新しいアドオン、またはバージョンのないアドオンがある | エディターのバージョンへ**アドオンを … に置き換え** |
| アドオンはあるが、有効になっていない | **プラグインを有効にする**。`project.godot`の`[editor_plugins]`に追加するだけで、ほかは何も変えません |
| gitのチェックアウトまたはサブモジュールのアドオン | 何もしません。gitで更新してください。エディターが置き換えることはありません |

![アドオン0.0.9がエディターより古いと表示し、アドオンを0.1.0に更新ボタンがある、このプロジェクトを設定ウィンドウ](../assets/project-setup/setup-update-addon.png)

> [!WARNING]
> 更新する前に、Godotを閉じてください。Godotは再起動するまで古いアドオンを実行し続けるので、Live LinkがプロジェクトをGodotが開いているのを検知しているあいだは、ボタンはグレーのままです。プラグインを有効にするときも、Godotを閉じておいてください。そうしないと、Godotが自分の`project.godot`のコピーを書き戻してしまいます。Godotの*Project > Project Settings > Plugins*でチェックを付ける方法でも有効にできます。

古いアドオンは削除されず、プロジェクトの`.trenchdot/addon-backups/func_godot-<version>`に移されます。Godotはドットで始まるフォルダを読み飛ばすので、バックアップをインポートすることも、2つ目のプラグインとして一覧に出すこともありません。新しいアドオンが動いたら、削除してください。(補足：ダウンロードしたものは、先に展開してから入れ替えます。そのため、失敗またはキャンセルされた更新では、古いアドオンがそのまま残ります。)

ダウンロードに失敗したときは、ウィンドウが[リリース](https://github.com/Paraxdev/TrenchDot/releases)と[itch.io](https://paraxdev.itch.io/trenchdot)へのリンクを表示します。どちらにも、同じ`func_godot-trenchdot-addon.zip`があります。`addons/func_godot`ができるようにプロジェクトのフォルダへ展開し、古いフォルダの上に展開するのではなく、置き換えてください。

## コアエンティティとゲームプレイエンティティパック { #core-entities-and-the-gameplay-entities-pack }

どのプロジェクトも、アドオンから小さなコアを受け取ります。worldspawn、`func_detail`、`func_illusionary`、`func_geo`、`light`、`light_spot`、`light_probe`、`env_reflection_probe`、`env_voxel_gi`、`info_player_start`です。

ドア、ボタン、リフト、トレイン、トリガー、ロジック、スポナー、テレポート、パスコーナー、プロップ、エフェクトなど、[エンティティリファレンス](../gameplay/entities/README.md)にあるそのほかのものは、ゲームプレイエンティティパックとして提供されます。必要になったときにインストールすると、`res://trenchdot/entities`にコピーされます。

| パス | 入っているもの |
| --- | --- |
| `gameplay_fgd.tres` | パックのFGDファイル。すべての定義を一覧にしています |
| `definitions/` | エンティティごとにひとつの定義。そのキー、インプット、アウトプット、エディターのギズモ |
| `scripts/` | 各エンティティが実行するGDScript |
| `pack.json` | インストールした内容。更新のときに、あなたの編集と区別するためのものです。そのままにしてください |

コピーはプロジェクトのものです。スクリプトや定義を変える、使わないエンティティを削除する、`gameplay_fgd.tres`に自分の定義を追加する、といったことができます。アドオン自身は、これらのクラス名やスクリプトクラスを定義しないので、そこで何をしてもアドオンと衝突しませんし、アドオンを更新しても元に戻りません。

### パックをインストール、更新する { #installing-and-updating-the-pack }

1. パックをインストールする

    *このプロジェクトを設定*ウィンドウの、アドオンの下にある**ゲームプレイエンティティをインストール**をクリックします。

    ![ゲームプレイエンティティのセクションと、そのゲームプレイエンティティをインストールボタンがある、このプロジェクトを設定ウィンドウ](../assets/project-setup/setup-gameplay-entities.png)

    プロジェクトにコアしかないあいだは、同じボタンがゲームプレイメニューの先頭とエンティティパネルにもあります。

    ![ゲームプレイエンティティをインストールにカーソルを重ね、ツールチップを表示したゲームプレイメニュー](../assets/project-setup/menu-install-gameplay-entities.png)

2. うまくいったか確認する

    ウィンドウに、緑で「res://trenchdot/entitiesにインストール済み」と表示され、新しいエンティティがすぐにエディターで使えるようになるはずです。

    ![インストール後のゲームプレイエンティティのセクション。res://trenchdot/entitiesに86個のファイルを追加したことと、Godotがプロジェクトを開いている場合は再起動することが表示されている](../assets/project-setup/setup-gameplay-installed.png)

    Godotエディターがプロジェクトを開いているときは、TrenchDotがそのエディターに新しいファイルを取り込むよう依頼し、ウィンドウがそれを伝えます。すると、[ライブモード](live.md#when-live-mode-rebuilds-the-whole-map)のシーンは自動で再ビルドされます。ほかの、あなたのマップを使っているシーンは、パックなしでビルドされているので、**Build Map**を押して保存してください。Godotが起動していないとき、または古いアドオンで動いているときは、ウィンドウが、Godotがプロジェクトを開いているなら再起動し、そのあとでそれらのシーンをビルドして保存するよう伝えます。

3. (任意で)あとで更新する

    アドオンの更新で新しいパックが来ると、ウィンドウが**ゲームプレイエンティティを更新**を提案し、ゲームプレイメニューには、変更されたファイルの数が表示されます。クリックするまで、何も更新されません。更新では、新しいファイルが追加され、触っていないファイルは置き換えられます。編集したファイルはそのまま残り、エディターがその名前を伝えます。削除したファイルは、削除されたままです。

エンティティがアドオンから切り離される前に作った古いマップも、引き続き動きます。プロジェクトのマップがパックのエンティティを使っていて、プロジェクト内のどこにもそれが定義されていないときは、エディターがプロジェクトを開いたとき、および更新したアドオンでGodotが起動したときに、パックが自動でインストールされます。どちらの場合も、`.tdm`ファイルはすべてのエンティティを保持します。定義の有無は関係ありません。

> [!NOTE]
> アドオンの中のテンプレート`addons/func_godot/gameplay_pack`には、Godotが読み飛ばすように`.gdignore`ファイルがあります。そのファイルは残してください。そうしないと、パックをインストールしたあとで、Godotがパックのスクリプトクラスをすべて二重に見つけてしまいます。

### どの定義が優先されるか { #which-definition-wins }

コアのFGDである`res://addons/func_godot/fgd/trenchdot/trenchdot_fgd.tres`は、インストールされたパックを自分で読み込みます。そのため、アドオンのデフォルトをもとにしたFGDなら、どれも、一覧に書かなくてもパックを受け取ります。2つの定義が同じクラス名を持つときは、次の順で、あとのものが優先されます。

1. FuncGodotのクラスとアドオンのコア
2. `res://trenchdot/entities`にインストールされたパック
3. 自分のFGDファイルのエンティティ

エンティティを変えるには、パックの中のそのコピーを編集するか、自分のFGDで同じクラス名を定義します。どちらでも動きますが、2回定義したクラス名は忘れやすいので、エディターが教えてくれます。プロジェクトを開いたとき、ステータスバーが優先される定義の名前を表示し、問題パネルが、マップが使う二重定義のクラスごとに警告します。2つのうちどちらかを削除すれば、解決します。

## 自分のリソース { #your-own-resources }

3つのリソースが連携して働きます。FGDファイルは、マップが使えるエンティティを一覧にします。マップ設定は、ビルドに、テクスチャの場所と、読み込むFGDを伝えます。ゲーム設定は、TrenchDotにその両方を伝えるので、編集中に、エディターが同じエンティティとテクスチャを提供できます。

いちばん手早いのは、[`godot/demo`](https://github.com/Paraxdev/TrenchDot/tree/main/godot/demo)から`demo_fgd.tres`、`demo_map_settings.tres`、`demo_game_config.tres`をプロジェクトにコピーして、パスを直す方法です。自分で作るときは、Godotエディターで次のようにします。

1. `FuncGodotFGDFile`を作ります。*Base Fgd Files*を`res://addons/func_godot/fgd/trenchdot_default_fgd.tres`に設定して、コアとインストールしたパックを残し、*Entity Definitions*に自分のエンティティを追加します。このベースがないと、FGDにはそれらがひとつもなく、worldspawnですらコリジョンなしでビルドされます。
2. `FuncGodotMapSettings`を作ります。*Entity Fgd*を手順1のFGDに、*Base Texture Dir*をテクスチャのフォルダ(デフォルトは`res://textures`)に設定します。新しいマップ設定リソースは、`trenchdot_default_fgd.tres`から始まります。これにはコアとパックはありますが、自分のエンティティはありません。
3. `TrenchDotGameConfig`を作ります。*Fgd File*と*Map Settings*を、上の2つのリソースに設定します。(任意で)*Game Name*を設定すると、エディターがツールバーの右上、プロジェクトフォルダの隣に表示します。
4. *Project > Project Settings*で、`func_godot/default_map_settings`を自分のマップ設定に、`trenchdot/game_config`を自分のゲーム設定に向けます。*Map Settings*欄が空のマップノードは、すべてこれに従います。古いアドオンで追加したノードは、その欄にアドオンのデフォルトを保存しているので、そこを空にしてください。

エディターが提供するのはゲーム設定のFGDのエンティティですが、Godotがビルドに使うのはマップ設定のFGDなので、この2つは同じにしてください。違っているときは、ゲーム設定をエクスポートするたびに、GodotがOutputパネルで警告し、TrenchDotの問題パネルが、Godotがビルドに使うFGDにないエンティティをすべて挙げます。

> [!TIP]
> マップ設定の*Entity Name Property*を、デモと同じく`targetname`にしてください。ビルドされたノードがtargetnameで名付けられ、シーンツリーが読みやすくなります。

## ゲーム設定 { #the-game-config }

TrenchDotは、エンティティ、テクスチャフォルダ、単位のスケールを、ゲーム設定が書き出す`res://trenchdot_game.json`から知ります。アドオンは、Godotがファイルの変化に気づくたびに、これをもう一度エクスポートし、エディターは1秒以内に読み込み直します。エクスポートには、デフォルトのマップ設定と、そのFGDが定義するクラスの名前も入っています。これが、Godotなら定義なしでビルドするエンティティについて、エディターが警告できる仕組みです。手動でエクスポートするには、Godotで*Project > Tools > TrenchDot: Export Game Config*を使うか、たとえばCIで、ヘッドレスで実行します。

```sh
godot --headless --path <project> --script res://addons/func_godot/src/trenchdot/export_game_config_cli.gd
```

## プロジェクト設定 { #project-settings }

ほとんどのプロジェクトで変えるのは、1つ目と3つ目だけです。Live Linkに関するものが問題になるのは、ほかのプログラムがすでにそのポートを使っているときです。

| 設定 | デフォルト | 目的 |
| --- | --- | --- |
| `func_godot/default_map_settings` | アドオンのデフォルト | 自分で設定を持たないすべてのマップのマップ設定 |
| `func_godot/default_inverse_scale_factor` | 32 | 1メートルあたりのマップユニット |
| `trenchdot/game_config` | アドオンの設定 | `trenchdot_game.json`を書き出す設定 |
| `trenchdot/auto_export_game_config` | true | ファイルが変わったときに、ゲーム設定をもう一度エクスポートする |
| `trenchdot/live_link_enabled` | true | TrenchDotが通信するLive Linkサーバーを動かす |
| `trenchdot/live_link_port` | 7842 | エディターの環境設定の*Godotライブリンク*と一致している必要があります。変更はすぐに反映されます。1024から65535の範囲で、それ以外の値は警告を出して7842に戻ります |
| `trenchdot/threaded_build` | true | ブラシと地形のチャンクをWorkerThreadPoolで変換し、大きなマップをより速くビルドする |
| `trenchdot/live_chunk_size` | 16.0 | ライブモードでは、worldspawnのジオメトリがこのメートル単位のサイズのチャンクに分割され、編集が自分のチャンクだけを再ビルドする |
| `trenchdot/csharp_entity_dirs` | `res://` | ビルド時にC#のエンティティを探す場所 |
