# 保存、ライブモード、ホットリロード { #saving-live-mode-and-hot-reload }

## 保存時に再ビルドする { #rebuild-on-save }

`FuncGodotMap`を含むシーンをGodotエディターで開いたままにして、TrenchDotでCtrl+Sを押して保存するだけです。Godotは、そのシーンのタブがGodotで表示されていて、マップノードの*Auto Rebuild On Save*がオンになっているかぎり、すぐにそのシーンを再ビルドします。マップを使っている別のタブのシーンは、そのタブに切り替えたときに再ビルドされます。タブを閉じて開き直したり、シーンを読み込み直したりしても、この動作は壊れません。[プレハブ](../editor/prefab-library.md)を保存すると、そのシーンの中で、直接または別のプレハブ経由でそれを使っているマップが再ビルドされます。

Godotが何をしたかは、左下のステータスバーに表示されます。うまくいったときは、こう表示されます。

![ステータスバーに「ライブリンク：Godotが1個のマップノードを再ビルドしました」と表示されている](../assets/live/status-rebuilt.png)

結果を残すには、Godotでシーンを保存してください。ステータスバーに別の表示が出たときは、そのメッセージが理由を教えてくれます。

![ステータスバーに、room.tscnはroom.tdmを使っているがGodotの現在のシーンタブではなく、切り替えると再ビルドされる、と表示されている](../assets/live/status-not-current-tab.png)

| ステータスバーの表示 | 対処 |
| --- | --- |
| シーンがGodotの現在のシーンタブではありません | そのタブに切り替えると、再ビルドされます |
| 現在のシーンタブに、そのマップ用の`FuncGodotMap`がありません | マップをビルドするシーンを開くか、そのマップノードの*Auto Rebuild On Save*をオンにします |
| Godotで開いているシーンがありません | マップのあるシーンをGodotで開きます。すでに開いているなら、続きを読んでください |
| GodotはTrenchDotアドオンなしで動いています | アドオンを有効にして、プロジェクトをGodotエディターで開きます |
| Godotはマップを再ビルドしましたが、マップ設定にいくつかのクラスの定義がないため、通常のノードとしてビルドされます | 定義を追加します。[何も起きないエンティティ](entities-troubleshooting.md)を参照してください |
| Godotは警告つきでマップを再ビルドしました。問題パネルを参照してください | 問題パネルで読みます。「Godot：」で始まっています |

Live Linkのポートを持てるGodotエディターは、ひとつだけです。同じプロジェクトを開いた2つ目のエディターは、Live Linkを待ち受けできなかったとOutputパネルで警告し、TrenchDotはそのまま最初のエディターと通信を続けます。最初のエディターには、開いているシーンがないかもしれません。使わないほうのエディターを閉じると、もう一方が数秒以内にリンクを引き継ぎます。(補足：*Godot > Godotエディターでプロジェクトを開く*は、すでにそのプロジェクトを開いているエディターがあれば、2つ目を起動せずにそれを前面に出します。)

## ライブモード { #live-mode }

ライブモードは、保存する前に、Godotエディターで開いているシーンへ編集を送り込みます。実際のレンダラーで、ライティングやスケールを確かめられます。

1. Godotでシーンを開く

    マップを一度プロジェクトの中に保存しておく必要があります。Godotで開いているシーンには、そのマップを使う`FuncGodotMap`が必要です。

2. オンにする

    ツールバーの右端、Godotのロボットの隣にあるリンクボタンをクリックするか、*Godot > ライブモード*を選びます。ボタンが点灯し、まだ待っているものがあれば、ツールチップがそれを教えてくれます。

    ![ライブモードのリンクボタンがオンになっているツールバー。ツールチップに、編集が保存の前にGodotへ届くと表示されている](../assets/live/toolbar-live-mode-on.png)

3. いつもどおり編集する

    変更はすべて、すぐにGodotに反映されます。

    ![TrenchDotでの編集が、保存する前にGodotエディターに反映されている様子](../screenshots/TrenchDot-demo-live-view.gif)

ライブモードにはGodotのLive Linkが必要で、これはデフォルトでオンです。どちらも*ファイル > 環境設定*にあり、*Godotライブモード*はツールバーのボタンと同じスイッチです。

![環境設定のGodotライブリンク、Godotライブモード、実行中ゲームのホットリロードの行](../assets/live/prefs-live-link.png)

ドラッグ中はノードが動き、ほとんどの編集は触れた部分だけを再ビルドするので、プレビューは遅れずについてきます。レイヤーの*Omit From Export*の切り替えと、プレハブインスタンスの編集は、編集の手を止めたあとにマップ全体を再ビルドします。

プレビューはフルビルドに近いものですが、いつも同じとは限りません。保存すると常にフルビルドになり、保存せずに終了するとGodotは保存済みのファイルに戻るので、保存しないかぎり、ライブモードで試したことは何も残りません。

### ライブモードがマップ全体を再ビルドするとき { #when-live-mode-rebuilds-the-whole-map }

シーンがフルビルドの結果と合わなくなったとき、Godotはマップ全体を自分で再ビルドします。ライブモードがシーンに対して始まるときはすぐに、それ以外は編集の手を止めたあとに行われます。

| いつ | なぜ |
| --- | --- |
| ライブモードが、別のエンティティ定義でビルドされたシーンに対して始まるとき | そのシーンは、ゲームプレイエンティティパックをインストールしたり定義を追加したりする前にビルドされていて、一部のエンティティが通常のノードになっています |
| ライブモードが、以前のライブ編集で変更されたシーンに対して始まるとき | そのシーンに、保存しなかった以前のセッションのライブ編集が残っています |
| ライブモードの実行中にエンティティ定義が変わったとき | GodotのインスペクターでFGDや定義を保存した、スクリプトクラスが変わった、インストールしたパックのように新しいファイルが届いた、のいずれかです |
| マップが使うプレハブを保存したとき | そのシーンは、まだ以前のプレハブの姿のままです |

ライブモードの外で開いているシーンは、ビルドされたときのエンティティのままです。そのうちのどれかが別のエンティティ定義でビルドされていると、GodotのOutputパネルが警告します。その中の**Build Map**を押して、保存してください。

### 定義のないエンティティ { #entities-without-a-definition }

Godotに定義がないクラスのエンティティをライブモードがビルドすると、ステータスバーにそのクラスと、追加先のFGDが表示されます。

![ステータスバーに、Godotにはcrypt_lampの定義がなく通常のノードとして表示されている、res://crypt_settings.tresのFGDにそのクラスを追加する、と表示されている](../assets/live/status-no-definition.png)

マップがそのクラスを使っているあいだは、ライブモードボタンのツールチップにも同じ注意書きが残ります。

![オンになったライブモードボタン。ツールチップに、編集が保存の前にGodotへ届くことと、Godotにcrypt_lampの定義がないことが表示されている](../assets/live/toolbar-live-mode-no-definition.png)

定義を追加して保存すると、Godotがマップを自分で再ビルドします。次に保存すると、注意書きは消えます。定義を置く場所は、[何も起きないエンティティ](entities-troubleshooting.md)を参照してください。

## 実行中のゲームでのホットリロード { #hot-reload-in-a-running-game }

すでに実行中のゲームで、保存した内容を確かめるには次のようにします。

1. オートロードを追加する

    Godotで*Project > Project Settings > Globals > Autoload*を開き、次のスクリプトを追加します。

    ```
    res://addons/func_godot/src/trenchdot/runtime/trenchdot_hot_reload.gd
    ```

2. Godotエディターからゲームを実行する

    オートロードが待ち受けるのは、Godotエディターから起動したゲームだけです。`enabled_in_exported_builds`をtrueにした場合は別です。

3. TrenchDotで保存する

    ゲームは、保存したファイルを使うマップを再ビルドして、`map_reloaded(map)`を発行します。このシグナルを使って、プレイヤーをスポーン地点に戻したり、ゲームの状態をリセットしたりできます。ステータスバーは、最後が「実行中のゲームが1個のマップを再読み込みしました」で終わるはずです。

ポート7843で待ち受けます。これはエディターの環境設定の*実行中ゲームのホットリロード*と一致している必要があります。TrenchDotが保存を送るのは、Live Linkがオンのときだけです。
