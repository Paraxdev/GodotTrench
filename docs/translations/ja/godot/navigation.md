# ナビゲーション { #navigation }

`TrenchDotNav`は、ビルドしたマップからナビゲーションメッシュをベイクして、敵やNPCがマップの中で道を見つけられるようにします。

```gdscript
map.build()
var region := await TrenchDotNav.bake_region(map)
```

`bake_region`はワーカースレッドでベイクし、マップの下に`navigation`という名前の`NavigationRegion3D`を追加して、そこを通る経路が使えるようになった時点で戻ります。複数のマップを持つノードを渡すと、すべてをひとつのメッシュにまとめてベイクします。再ビルドするとリージョンは解放されるので、そのあとでもう一度ベイクしてください。

## 対象になるもの { #what-counts }

ベイクが読むのはマップのコリジョンで、メッシュではありません。プレイヤーがぶつかるものが、そのままエージェントが避けて歩くものになります。

| マップ内のもの | ナビゲーションメッシュ内 |
| --- | --- |
| ワールドブラシ、`func_detail`、地形とプロップのコリジョン | 含まれる |
| クリップブラシ | 含まれる。壁と同じように遮る |
| イリュージョナリーブラシ、トリガー、物理プロップ | 含まれない |
| ドア、ボタン、プラットフォーム、トレイン | 含まれないので、閉じたドアが出入口をふさぐことはない |
| `navigation_ignore`グループのボディ | 含まれない |

つまり、経路は閉じたドアを通り抜けます。エージェントは、ぶつかったドアを自分で開ける必要があります。

## エージェントのサイズ { #agent-size }

`TrenchDotNav.profile(radius, height, max_climb, max_slope)`は、エージェント1種類のサイズ分の設定を返します。radiusは経路を壁から遠ざけ、heightは低い天井を除外し、*max_climb*はエージェントが登れる段差の最大の高さ、*max_slope*は登れるスロープの最大の傾きです。サイズの単位はメートル、傾きの単位は度です。

| 引数 | デフォルト |
| --- | --- |
| `radius` | 0.3 |
| `height` | 1.8 |
| `max_climb` | 0.3 |
| `max_slope` | 45 |

メッシュのセルは0.1mで、サイズはそのセルに合わせて丸められます。たとえば幅が広くて背の低い生き物なら、プロファイルを2番目の引数として渡します。

```gdscript
var region := await TrenchDotNav.bake_region(map, TrenchDotNav.profile(0.5, 1.2))
```

(`bake_region`は、ナビゲーションマップのセルサイズをベイクのセルサイズに設定します。そのマップ上の他のリージョンも、同じセルサイズにする必要があります。)

## キャッシュ { #caching }

大きなマップを初めてベイクするときは、数秒かかります。結果は`user://trenchdot_navigation`にキャッシュされ、キーはコリジョンと設定です。同じマップで次に起動したときは、ほんの一瞬で読み込まれます。3番目の引数に`false`を渡すと、キャッシュを使わずにベイクします。

## マップを確認する { #checking-a-map }

`TrenchDotNav.bake(map)`は、呼び出したスレッドでベイクして`NavigationMesh`を返します。ツールやテストに便利です。`TrenchDotNav.islands(nav)`は、つながっていない部分をポリゴンのインデックスで、大きい順に一覧にします。

行けるはずの部屋が独立した島になっているなら、たいていは出入口を低い何かがふさいでいるか、段差が`max_climb`より高くなっています。壁の上面や、厚い壁の中の床も、小さな島として現れます。

> [!WARNING]
> Godotは4096ポリゴンで経路探索を打ち切り、そこまでの経路を返します。大きなマップでは、これが到達できない地点のように見えます。`TrenchDotNav.path(node, from, to)`には上限がありません。エージェントでは、`NavigationAgent3D`の`path_search_max_polygons`を0にしてください。

## TrenchDotで確認する { #seeing-it-in-trenchdot }

ゲームを実行しなくても、エージェントがどこを歩くかをTrenchDotの中でそのまま確認できます。

1. Godotでシーンを開く

    マップをプロジェクトの中に保存し、そのマップをビルドする`FuncGodotMap`を含むシーンで、プロジェクトをGodotエディターで開きます。

2. 歩行可能エリアをオンにする

    *表示 > 歩行可能エリア > 歩行可能エリアを表示*を選びます。そのすぐ下にエージェントのサイズがあり、いちばん下の行には、歩ける範囲の広さと、切り離された島の数が表示されます。

    ![歩行可能エリアのサブメニューを開いた表示メニュー。歩行可能エリアを表示、続いて半径0.30m、高さ1.80m、最大登坂0.30m、最大傾斜45.00度、まだベイクされていません、が並んでいる](../assets/navigation/menu-walkable-area.png)

Godotが[Live Link](live-link.md)を通してシーンをベイクし、TrenchDotがその結果を3Dビューと2Dビューに描きます。(ベイクできない場合は、たとえばマップを先にプロジェクトへ保存する必要があるなど、理由がステータスバーに表示されます。)

色の意味は次のとおりです。

| 色 | 意味 |
| --- | --- |
| 青緑 | つながっている最大の領域。ほとんどのエージェントはここにいる |
| 朱色 | 緑の領域にいるエージェントが行けない島。*最大登坂*より高い段差、*半径*の2倍より狭い隙間、*最大傾斜*より急な坂を探してください |

オーバーレイは、編集のたびに少し待ってからもう一度ベイクされます。[ライブモード](live.md)を使っていないときは、Godotがまず表示されているとおりにマップをビルドします。*Godotでビルド*と同じです。

> [!TIP]
> 壁や屋根の上面は、小さな朱色の島として現れます。緑の床の隣にある朱色の床を探してください。
