# オーバーレイ { #overlays }

ビルドのたびに、マップが生成したものは置き換えられるので、マップノードの下に手で追加したものは、次の保存で消えます。オーバーレイは、マップに属していて、再ビルドのたびに残さなければならないGodotのコンテンツを置く場所です。たとえば、独自のスクリプトを持つ自動販売機、Godotで調整したパーティクルエフェクト、AnimationPlayerを持つランプです。

![夜の街区の中庭。ストリングライト、ホタル、看板はオーバーレイから、ランプはマップから](../assets/overlays/night-district-courtyard.jpg)

## 追加する { #adding-one }

1. オーバーレイノードを追加する

    Godotで、`FuncGodotMap`の直接の子として`TrenchDotOverlay`ノードを追加します。

2. その下にノードを置く

    ビルド、ライブモード、ホットリロードはそれに一切触れないので、その下のノードは状態とシグナルの接続を保ち、シーンと一緒に保存されます。

(ノードがひとつだけなら、オーバーレイは省けます。マップの直接の子で、`trenchdot_keep`グループに入れたノードも、ビルドを越えて残ります。シーンの別の場所にあるオーバーレイは、代わりに*Map Path*でマップを指せます。その場合は、マップのトランスフォームに追従します。)

オーバーレイのコンテンツは、メートル単位のマップのローカル空間を使います。1メートルが32ユニットなので、`(2, 0, -3)`にある子は、TrenchDotで`(64, 0, -96)`と表示される場所にあります。

## 独自のシーンにしたオーバーレイ { #an-overlay-in-its-own-scene }

オーバーレイは、独立したシーンにもできます。同じマップを複数のシーンが使っていてオーバーレイを共有したいとき、レベルのシーンを担当する人とオーバーレイを担当する人が別のとき、デモのようにスクリプトがレベルのシーンを生成するときに役立ちます。

1. ルートが`TrenchDotOverlay`のシーンを作ります。
2. その`.tscn`を`FuncGodotMap`ノードにドラッグして、マップの直接の子としてインスタンス化します。

Godotは、インスタンス化したシーンを、展開する矢印のないひとつのノードとして表示します。中身にアクセスするには、次のようにします。

| やりたいこと | 方法 |
| --- | --- |
| 使われているすべての場所でオーバーレイを編集する | シーンドックでノードの隣にある*Open in Editor*アイコンをクリックするか、ファイルシステムドックで`.tscn`をダブルクリックします |
| このシーンの中だけでノードを見る、または変更する | ノードを右クリックして、*Editable Children*をオンにします |

オーバーレイのシーンを単独で開くと、マップの下にないため、ルートに警告が表示されます。これは想定どおりです。TrenchDotの破線のボックスは、マップのあるシーンが次にビルドまたは保存されたときに追いつきます。オーバーレイが自分のマップを知るのは、そこだけだからです。

## オーバーレイをつなぐ { #wiring-overlays }

オーバーレイのノードとマップのエンティティは、マップのエンティティ同士が使うのと同じアウトプットとインプットで、互いにトリガーできます。

| やりたいこと | 方法 |
| --- | --- |
| マップのアウトプットをオーバーレイのノードに届ける | ノードに`TrenchDotOverlayIO`の子を付けて、その*Targetname*を設定します |
| オーバーレイのノードからマップのエンティティを動かす | `TrenchDotOutput`の子を追加し、*Output*でシグナルを選んで、ターゲット、インプット、パラメーターを入力します |
| 動くエンティティにコンテンツを乗せる | `TrenchDotAnchor`の下に置き、*Target*にそのエンティティのtargetnameを設定します |

`TrenchDotOverlayIO`に送られたインプットは、同じ名前のノードのメソッドを呼ぶか、同じ名前のプロパティを設定するか、`show`、`hide`、`toggle`を実行します。そのため、スクリプトのないノードでも使えます。インプット`emitting`にパラメーター`true`を渡すと、`GPUParticles3D`が始まります。どのインプットも、`input_received(input, parameter, activator)`も発行します。

`TrenchDotOutput`は、親のあらゆるシグナルを待ち受けるので、`Area3D`はコードなしで`body_entered`で発火します。独自のイベントには、親のスクリプトにシグナルを追加して、それを選びます。

```gdscript
extends StaticBody3D

signal flipped_on(activator: Node)
signal flipped_off(activator: Node)

var on := false

func use(activator: Node = null) -> void:
	on = not on
	if on:
		flipped_on.emit(activator)
	else:
		flipped_off.emit(activator)
```

アンカーは、置いたときのオフセットを保ち、再ビルド、ライブ編集、移動を通してエンティティに追従します。そのため、警告の看板は、ローラードアと一緒に上がります。

> [!WARNING]
> つなぎ方は再ビルドを越えて残りますが、状態は残りません。マップのエンティティは、開始時の状態に戻ります。そこで、オーバーレイの`map_rebuilt(map)`シグナルに接続して、状態を戻してください。たとえば、ランプをもう一度つけます。

## デモで見る { #see-it-in-the-demo }

デモプロジェクトの夜の街区には、これがすべて入っています。そのシーン`res://demo/showcase/night_district.scn`は、スクリプトがショーケースのシーンを再ビルドするため、マップの下にオーバーレイのシーン`res://demo/overlays/night_district_overlay.tscn`をインスタンス化しています。オーバーレイのシーンを開くと、中庭のランプを切り替えるブレーカーボックス、マップのトリガーでつくストリングライト、ガレージのローラードアに乗る看板が見つかります。
