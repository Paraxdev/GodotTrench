# GodotTrenchプロジェクトを更新する { #updating-a-godottrench-project }

TrenchDotはかつてGodotTrenchという名前で、ベータ版の一時期はLevelBenchと呼ばれていました。その頃にプロジェクトをセットアップしたり、マップを保存したりしていても、そのまま使い続けられます。アドオンの更新は一度だけです。

## 手順 { #steps }

1. 新しいエディターを起動します。初回の起動時に、古い設定フォルダから、環境設定、信頼したプロジェクト、最近使ったファイルがコピーされます。古いフォルダはそのまま残るので、古いエディターも引き続き使えます。
2. Godotプロジェクトを開きます。セットアップのウィンドウが開き、プロジェクトのアドオンがエディターより古いと表示されます。バージョン番号が同じでも表示されます。先にGodotを閉じてから、バージョンが続く**アドオンを … に更新**ボタンを押します。
3. プロジェクトをGodotで一度開きます。アドオンがプロジェクト設定を`godottrench/`から`trenchdot/`へ移し、`godottrench_game.json`の代わりに`trenchdot_game.json`を書き出します。

## 引き継がれるもの { #what-carries-over }

| 以前あったもの | どうなるか |
| --- | --- |
| `.gtm`のマップ | そのまま開きます。ステータス行には「room.gtmをGodotTrench形式から更新しました。保存すると反映されます」と表示されます。保存しても`.gtm`の名前は変わらないので、シーンはそのままマップを見つけられます。新しいマップは`.tdm`で保存されます。 |
| `GODOTTRENCH_`の環境変数 | 引き続き使えます。両方の名前が設定されているときは、`TRENCHDOT_`のほうが優先されます。 |
| `res://godottrench/entities`にあるゲームプレイパック | 引き続き動作し、そのクラスを継承する自作のスクリプトも、そのままコンパイルできます。新しいパックもインストールした場合は、両方が定義しているエンティティでは新しいほうが優先されます。シーンがまだ使っているあいだは、古いフォルダをそのまま残してください。 |
| `res://godottrench/`にあるネイチャーパックとモデル | それらを配置したマップは引き続き動作します。スキャッタープリセットは`res://trenchdot/nature`を探すので、新しくスキャッターをペイントするには、ネイチャーパックをもう一度追加してください。 |
| 古いアドオンでビルドしたシーン | 読み込めます。Godotが、移動したアドオンのスクリプトをuidで見つけるためです。マップをもう一度ビルドすると更新されます。 |

## MCPクライアント { #mcp-clients }

MCPサーバーの名前は、現在は`trenchdot`です。クライアントの設定で名前を変えてください。トークンの変数は`TRENCHDOT_MCP_TOKEN`で、古い`GODOTTRENCH_MCP_TOKEN`も引き続き使えます。
