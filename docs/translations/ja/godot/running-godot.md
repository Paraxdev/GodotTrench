# エディターからGodotを実行する { #running-godot-from-the-editor }

保存、ビルド、ライブモードは、Live Linkを通してアドオンとやり取りするので、そのプロジェクトを開いているGodotエディターであれば、どれでも動きます。TrenchDotがGodotの実行ファイルを見つける必要があるのは、*Godot > Godotエディターでプロジェクトを開く*、ツールバーのGodotロボット、Godotエディターがプロジェクトを開いていないときの*Godot > プロジェクトを実行*(F5)だけです。これらは、自分でGodotを起動するからです。

![プロジェクトを実行にカーソルを重ねたGodotメニュー。右にF5のショートカット、下にGodotエディターでプロジェクトを開くが並んでいる](../assets/running-godot/menu-run-project.png)

## プロジェクトを実行 { #run-project }

Godotエディターがプロジェクトを開いているあいだは、*プロジェクトを実行*が、そのエディターに、開いているシーンを保存してメインシーンを再生するよう依頼します。GodotでPlayを押したときと同じです。ゲームには、ライブ編集も含めて、Godotがビルドしたものがすべて入ります。ステータスバーには、「Godotが開いているシーンを保存し、メインシーンを実行します」と表示されるはずです。プロジェクトにメインシーンがないときは、そう表示されます。Godotの*Project > Project Settings > Application > Run*で設定してください。

Godotエディターがないときは、*プロジェクトを実行*は、Godotの実行ファイルでゲームを起動します。その場合は、Godotで最後に保存されたとおりにシーンが動きます。古いアドオンでも同じで、ステータスバーに、ゲームに最新のマップの変更が入っていない場合があると追記されます。Godotで保存するか、そちらでPlayを押してください。

## 実行ファイルを探す { #finding-the-executable }

*ファイル > 環境設定*を開き、*Godot実行ファイル*を見ます。TrenchDotが見つけたときは、入力欄の下に「使用中」という言葉とパスが表示されます。

![環境設定のGodot実行ファイル欄。その下に「使用中」の行とパスが表示されている](../assets/running-godot/prefs-godot-using.png)

黄色で「見つかりません」と表示されているときは、欄の隣の「…」ボタンをクリックして、ディスク上のGodotの実行ファイル(`Godot_v`で始まるもの)を選びます。見つかったGodotが違うものだったときも、同じようにします。見つかるまでは、Godotエディターでプロジェクトを開くはグレーのままで、Godotエディターがプロジェクトを開いていないあいだは、プロジェクトを実行もグレーのままです。

![空のGodot実行ファイル欄、…ボタン、黄色の見つかりませんの行](../assets/running-godot/prefs-godot-not-found.png)

環境設定に使えるパスがないときは、エディターは次のうち、最初に見つかったものを使います。

1. `GODOT`環境変数。
2. `PATH`にある`godot`または`godot4`。次に、`Godot_v4.7.2-stable_win64.exe`のようなダウンロードしたビルドが、新しい順に続きます。プロジェクトフォルダに`.csproj`があるときは、C#のプロジェクトにはMonoビルドが必要なので、Monoビルドが優先されます。コンソールビルドは除外されます。
3. 一般的なインストール先のフォルダ。Windowsでは、WinGet、Scoop、Steam、`Programs/Godot`。Linuxでは、`~/.local/bin`とSteam。macOSでは、`/Applications/Godot.app`。

## Godotボタン { #the-godot-button }

ツールバーの右端にあるGodotロボットは、接続の状態を表します。カーソルを重ねると、クリックしたときに何が起きるかが表示されます。

グレーは、プロジェクトが開かれていないか、Godotが見つからないことを意味し、クリックしても何も起きません。

![カーソルを重ねたグレーのGodotロボット。ツールチップにGodotが見つからないと表示されている](../assets/running-godot/toolbar-godot-not-found.png)

通常の色は、Godotが見つかったことを意味します。クリックすると、プロジェクトがGodotエディターで開きます。

![カーソルを重ねた通常の色のGodotロボット。ツールチップにGodotエディターでプロジェクトを開くと表示されている](../assets/running-godot/toolbar-godot-found.png)

シアンは、Godotエディターがこのプロジェクトを開いていることを意味します。クリックすると、そのエディターが前面に出ます。

![カーソルを重ねたシアンのGodotロボット。ツールチップにGodot 4.7.2-stable (official)がこのプロジェクトを開いている、クリックで表示すると表示されている](../assets/running-godot/toolbar-godot-open.png)

Godotがビルド中は、その隣にスピナーが表示されます。ツールチップに、実行中のGodotのアドオンが古いと表示されたときは、*Godot > アドオンをインストールまたは更新…*で更新すると、ライブモードが使えるようになります。

## プロジェクトの信頼 { #project-trust }

Godotは、プロジェクトを開く、再生する、ビルドするとすぐに、そのスクリプトを実行します。ダウンロードしたプロジェクトやマップパックには、独自のスクリプトが入っていることもあります。そのため、TrenchDotがまだ知らないプロジェクトで、コードを含んでいるものを開くときは、まずTrenchDotが確認します。

TrenchDotは、最初にプロジェクトの中にコードがないか調べます。そのあいだ、ステータスバーには*コードを検索中*と表示され、Godotではそのプロジェクトに対して何も起動されません。そのため、大きなプロジェクトでは、確認が出る、または開くまでに少し時間がかかります。

![「このプロジェクトのファイルの作者を信頼しますか？」という確認。プロジェクトのフォルダ、制限モードがブロックするもの、親フォルダのチェックボックス、プロジェクトを信頼と制限モードで開くのボタンが並んでいる](../assets/running-godot/trust-prompt.png)

自分のプロジェクトや、信頼できる人のプロジェクトでは、**プロジェクトを信頼**をクリックします。先に*親フォルダ '…' 内のすべてのファイルの作者を信頼する*にチェックを付けると、そのフォルダにあるすべてのプロジェクト、たとえばゲームをすべて入れているフォルダを信頼します。チェックを付けないと、信頼するのはそのプロジェクトひとつだけです。その中に展開したプロジェクト、たとえば独自の`project.godot`を持つマップパックは、一緒には信頼されません。

よく分からないときは、**制限モードで開く**をクリックします。マップを見たり編集したりはできますが、TrenchDotはそのプロジェクトに対してGodotを起動せず、Godotでのビルドも、ライブ編集の送信も行いません。すると、ステータスバーの右側に*制限モード*が黄色で表示されます。クリックすると、もう一度確認が出ます。

![ステータスバーの黄色い制限モードのチップ。ツールチップに、信頼するまでTrenchDotはこのプロジェクトをGodotで実行しないと表示されている](../assets/running-godot/restricted-mode-chip.png)

制限モードでは、*プロジェクトを実行*、Godotロボット、*Godotでビルド*、ライブモードのオンが、「実行するとスクリプトも動きます。信頼して続けますか？」と確認し、**プロジェクトを信頼**をクリックすると先へ進みます。

まだ信頼していない別のプロジェクトに属するマップを開いたときは、開いているプロジェクトが維持され、確認のボタンに**現在のプロジェクトを維持**が加わります。開いているプロジェクトのフォルダの中にある`project.godot`は、Godotが無視するのと同じように無視されます。開いているプロジェクトの外にあるマップが独自のGDScriptを実行するときは、ステータス行がそう伝え、問題パネルがその場所を示します。

TrenchDotが信頼を尋ねるようになる前からあった*最近のプロジェクト*のプロジェクトは、信頼したものとして扱われます。`--project`でエディターを起動したプロジェクトも、そのセッションのあいだは同じです。

> [!NOTE]
> 制限モードが対象にするのは、TrenchDotが起動するものだけです。自分でプロジェクトをGodotで開けば、スクリプトはいつもどおり実行されます。

### コードのないプロジェクト { #projects-without-code }

コードを含まないプロジェクトは、確認なしで開きます。Godotが実行するものがないからです。空のフォルダ、作ったばかりのプロジェクト、TrenchDotのアドオンと、それがインストールしたゲームプレイエンティティパックだけのプロジェクトがこれにあたります。ここでいうコードとは、スクリプト、C#プロジェクト、ネイティブライブラリ、スクリプトを含むシーンとリソース、オートロード、エディタープラグイン、`logic_script`にGDScriptが入っているマップのことです。アドオンとパックがTrenchDot自身のものとして扱われるのは、その中のすべてのファイルが、このバージョンがインストールするものと一致しているあいだだけです。そのため、編集されたものや古いコピーはコードとして数えられ、手早く調べきれないほど大きなプロジェクトも同じです。

TrenchDotは、プロジェクトを開くたびにもう一度調べ、何も記憶しないので、プロジェクトにスクリプトが増えると確認が出ます。自分のプロジェクトを信頼したままにするには、コードがないうちに、*ファイル > 保存*でマップをその中に保存します。それ以降はTrenchDotが信頼し、Godotでスクリプトを追加したあとも同じです。制限モードでプロジェクトにマップを保存しても、何も信頼されません。

### 信頼したプロジェクト { #trusted-projects }

*ファイル > 環境設定…*を開いて、いちばん下の*信頼したプロジェクト*を見ると、信頼しているプロジェクトとフォルダがすべて分かります。ひとつの隣の**削除**をクリックすると、その信頼を取り消します。それが開いているプロジェクトなら、すぐに制限モードになり、ステータスバーに黄色のチップが表示されます。ただし、そのプロジェクトにコードがない場合は別です。

![環境設定の信頼したプロジェクト。2つのプロジェクトと、その中のすべてのプロジェクトを含むフォルダが並び、それぞれに削除ボタンがある。ひとつのツールチップに、ここのスクリプトをGodotが実行する前に、TrenchDotがもう一度確認すると表示されている](../assets/running-godot/trusted-projects.png)

## MCP { #mcp }

エージェントの前に確認が出ることはありません。`open_project`と`get_state`は`restricted`を返し、Godotにプロジェクトを実行またはビルドさせるツールは、チップで信頼するまでエラーで失敗します。`map_file`の`open`は、信頼していないプロジェクトのマップに対しては、開いているプロジェクトを維持し、そのプロジェクトを`other_project`として返します。

どちらの結果にも入っている`trust`は、プロジェクトが制限モードではない理由を伝えます。`stored`、`--project`による`session`、`no_code`のいずれかです。エージェントが`map_file`、`run_action`、または`run_script`の中で行う保存は、決して信頼を記録しません。そのため、エージェントがコードのない状態で作業しているプロジェクトは、スクリプトが増えたときにもう一度確認されます。
