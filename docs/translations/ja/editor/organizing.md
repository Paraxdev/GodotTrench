# マップを整理する { #organizing-a-map }

マップが大きくなってくると、パーツごとに分けたり、物をまた見つけられるようにしたり、再利用する部品を一か所にまとめたりしたくなります。その多くは、左にあるパネル、アウトライナーから始まります。

## レイヤー { #layers }

アウトライナーは、マップをレイヤー、グループ、オブジェクトのツリーとして表示します。レイヤーを使うと、たとえば1棟の建物を1枚のレイヤーにするというように、マップをパーツに分けられるので、残りの作業中にその部分を隠したりロックしたりできます。

アウトライナーの上部にある**レイヤーを追加**をクリックすると新しいレイヤーができ、すぐにカレントレイヤーになります。新しいオブジェクトは*(現在)*と表示されているカレントレイヤーに入り、レイヤーをクリックするとそれがカレントになります。行の前にある目で隠し、鍵で選択や編集をできなくします。

行にカーソルを合わせると、マテリアル、サイズ、境界が表示されます。オブジェクトはすべてのビューで同時にアウトラインが表示されるので、`brush7`がどの壁なのかが分かります。

![Houseレイヤーが開いてbrush7の行にカーソルがあるアウトライナー。ツールチップにマテリアル、サイズ、境界が表示され、3Dビューと正面ビューでは奥の壁にアウトラインが付いている](../assets/organizing/outliner-hover.png)

ブラシとメッシュは、`brush12`や`mesh40`のように種類とIDで一覧になるので、中空化や減算で残った壁を見分けられます。IDはオブジェクトを動かしても、保存し直しても変わりません。

### 名前を付ける { #naming-things }

オブジェクトを選んでF2を押すか、アウトライナーかビューで右クリックして*名前変更*を選びます。行がテキストフィールドになります。Enterで名前が確定し、Escapeでキャンセルされ、空の名前にするとデフォルトの名前に戻ります。

![アウトライナーのブラシの行がテキストフィールドになり、「front wall」と入力されている](../assets/organizing/outliner-rename.png)

名前はマップと一緒に保存されます。エンティティの`targetname`はこの名前とは別に保たれるので、名前を変えてもアウトプットの届く先は変わりません。クリップ、CSG操作、変換で残った破片は名前を引き継ぎ、リンクされたグループの中のオブジェクトに名前を付けると、すべてのコピーにその名前が付きます。

（レイヤー、グループ、散布セットは常に名前を持つので、それらでは空の名前にしても何も変わりません。散布セットの名前を変えると、散布ツールがそのために作ったレイヤーの名前も変わります。）

### アウトライナーでオブジェクトを選ぶ { #picking-objects-in-the-outliner }

行をCtrl+クリックすると、選択に加えたり外したりできます。Shift+クリックは、最後にクリックした行とこの行のあいだのすべての行を選択し、Ctrl+Shift+クリックは、その範囲をすでに選択しているものに追加します。ビューでは他のオブジェクトの陰に隠れるオブジェクトも、アウトライナーなら選びやすいことがよくあります。

### レイヤーをGodotに出さない { #keeping-a-layer-out-of-godot }

ゲームに決して届けたくない参考用のジオメトリは、そのレイヤーを右クリックして*書き出しから除外を切替*を選びます。するとそのレイヤーの名前のあとに*[除外]*と表示されます。隠すだけでは足りません。Godotは非表示のオブジェクトも構築するからです。

![Blockout参考レイヤーの右クリックメニュー。書き出しから除外を切替にカーソルがある](../assets/organizing/layer-menu-omit.png)

## グループ { #groups }

グループは、テーブルのブラシのように、オブジェクトをひとまとめにして、一つとして選択したり動かしたりできるようにします。グループに関することはすべて*編集 > グループ*にあります。

![グループを開いてリンクして複製にカーソルを合わせた編集メニュー](../assets/organizing/menu-groups.png)

| 入力 | 結果 |
| --- | --- |
| Ctrl+G、Ctrl+Shift+G | 選択をグループ化する、グループ解除する |
| クリック | グループ内のオブジェクトを選択する |
| ダブルクリック | グループ全体を選択する |

**リンクして複製**（Ctrl+Shift+D）は、元と同期し続けるコピーを作るので、窓枠を1つ直せばすべてが直ります。リンクされたコピーはアウトライナーに*(リンク)*と表示され、コピー同士は一つとして編集されるため、どれかをクリックするとグループ全体が選択されます。1つのコピーだけ違うものにしたいときは、*編集 > グループ > グループのリンク解除*でリンクを切ります。

## プレハブ { #prefabs }

複数のマップで再利用する部品は、選択してから*編集 > プレハブ > 選択から作成…*を選びます。選択が専用の`.tdm`として保存され、その場所にインスタンスが置かれます。プレハブのファイルが変わると、すべてのインスタンスが更新されます。

![プレハブを開いて選択から作成にカーソルを合わせた編集メニュー](../assets/organizing/menu-prefabs.png)

> [!NOTE]
> プレハブを作る前に、マップを一度保存してください。プレハブのパスはマップからの相対パスで保存されるので、マップにファイルがないうちは、エディターが拒否します。

一度貼り付けてから自由に形を整えたい部品には、代わりに[プレハブライブラリ](prefab-library.md)を使います。

プレハブを2回置くと、2つのエンティティが同じtargetnameを持ちます。インスタンスのフィックスアップがそれを解決します。フィックスアップが`p1`なら、中のすべての名前にその接頭辞が付き、`door`は`p1-door`になって、各コピーの配線が別々に保たれます。マップファイルとGodotのビルドはフィックスアップを理解しますが、エディターにはまだそれを設定する欄がありません。

## コードン { #cordon }

コードンは、エディターを大きなマップの一部分に絞り込みます。

1. 作業したいものを選びます。
2. *表示 > コードン > 選択からコードンを設定*を選ぶか、インスペクターの**コードン**をクリックします。

    ![コードンを開いて選択からコードンを設定にカーソルを合わせた表示メニュー](../assets/organizing/menu-cordon.png)

3. 選択のまわりの黄色いボックスに触れていないものはすべて隠れ、選択できなくなり、ステータスバーに*コードン*と表示されます。

    ![前：家、芝生、庭の壁、柱、背の高い参考ブロックがあるマップ全体。後：黄色いボックスの中の家と、それに触れている芝生だけ](../assets/organizing/cordon-before-after.png)

*表示 > コードン > コードン有効*でオフとオンを切り替え、*コードンを消去*で取り除きます。コードンはマップと一緒に保存されます。

変わるのはエディターの表示だけで、Godotはマップ全体を構築します。1つのエリアを別のツールに渡すには、*ファイル > エクスポート > .map、コードンのみ…*が、その中のオブジェクトだけを書き出します。

## 問題 { #issues }

問題パネルは、アウトライナーと履歴の隣のタブで、作業中にマップをチェックします。体積のないブラシ、マテリアルのない面、存在しないtargetnameを宛先にしたアウトプットなど、Godotで壊れたり見た目がおかしくなったりする問題を一覧にします。

![存在しないターゲットのエラー、重複したブラシ、定義のないエンティティ、Zファイティングする2つの面についての3件の警告、空のグループについての情報の行がある問題パネル。ほとんどに修正ボタンがある](../assets/organizing/issues-panel.png)

問題をクリックすると、そのオブジェクトが選択されてフレームに収まります。多くには**修正**ボタンがあり、ヘッダーの**全て修正**は、修正できるものをすべて修正します。

面が同じ平面上にある別のブラシの面と重なっているという警告は、Godotで2つの面がちらつくという意味です。片方の面を平面から離すか、重なりをトリムしてください。

モデルが存在しないという警告は、プロップの`model`が存在しないファイルを指していて、プロップがメッシュなしで構築されるという意味です。同じ名前で拡張子が違うファイルがあるとき、たとえば`chair.glb`に対して`chair.gltf`があれば、警告にその名前が表示されます。

マップがGDScriptを実行するという警告は、マップが独自のコードを持っていて、シーンがGodotで再生されると同時にそれが動くという意味です。`source`または`expression`を持つ`logic_script`ごと、コードを渡せるアウトプットや`logic_call`ごと(たとえば`source`をそれに送るアウトプット)、これらのいずれかを含むプレハブごとに1件表示されます。他の人が作ったマップを再生する前に、必ず読んでください。

「Godot」で始まる警告は、保存のあと、または*Godotでビルド*のあとに行われた、Godotでの直近のビルドから来ます。定義なしで構築されたクラスと、そのビルドの他の警告です。[何も起きないエンティティ](../godot/entities-troubleshooting.md)を参照してください。

## 履歴 { #history }

履歴パネルはすべての編集を、新しいものを上にして一覧にします。古い項目をクリックすると、その項目も含めてそこまで元に戻ります。元に戻した編集は*現在*の上に薄く表示されたままで、その1つをクリックすると、そこまでやり直せます。

![現在のマーカーの上に名前変更とグループ化が薄く表示され、中空化の項目にカーソルがある履歴パネル](../assets/organizing/history-panel.png)

## MCP { #mcp }

[MCPサーバー](../mcp.md)からエディターを操作するエージェントやスクリプトは、`validate_map`ツールで問題パネルと同じチェックを実行できます。このツールはチェックを`coplanar_faces`や`missing_model`のようなコードで呼びます。`run_action`のアクション`insert_prefab`は`fixup`を受け取るので、エージェントはインスタンスを置くときにフィックスアップを指定できます。
