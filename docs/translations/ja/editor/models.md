# モデル { #models }

モデルは、BlenderやBlockbenchのような別のプログラムで作った3Dファイルです。TrenchDotは、glTF、OBJ、Blockbench、STL、MD2、MD3のファイルを読み込めます。

モデルは、画面下部にあるマテリアルやプレハブの隣の**モデル**タブで見つかります。`res://models`の中身すべてと、インストールしてあれば`res://trenchdot/nature`にある自然物のモデルが一覧に並びます。

![モデルタブ。検索欄、フォルダとソースのフィルター、並べ替え、スラッグ、サムネイルサイズのスライダー、合わせる、サイズの倍率、再スキャンボタン、インポート…が並び、その下に自然物モデルのサムネイルがグリッドで並んでいる](../assets/models/models-panel.png)

新しいプロジェクトにはモデルがありません。*Godot > プロジェクトにコンテンツを追加…*で自然物のモデルが追加され、デモを選ぶと`res://models/polyhaven`にあるPoly Havenのプロップも入ります。自分のファイルを`res://models`にコピーして、⟳ボタンで再スキャンしてもかまいません。

## モデルを置く { #placing-a-model }

モデルをマップに入れる方法は2つあります。エディターで形を変えたいかどうかで選んでください。

| 置き方 | マップへの保存内容 | 向いている用途 |
| --- | --- | --- |
| 編集可能なメッシュ | ジオメトリのコピー。以後はファイルに追従しません | [メッシュツール](meshes.md)で編集したい形 |
| `prop_model`エンティティ | `res://`のパスだけ。Godotがファイルを読み込みます | そのまま使うプロップ。ファイルを変えると、すべてのコピーが追従します |

### 編集可能なメッシュとして { #as-an-editable-mesh }

1. （任意）サイズを設定する

    モデルツールバーの合わせるは、初期状態でチェックが入っています。いちばん長い辺が4分の1メートル未満、または256メートルを超えるモデルを2メートルに拡大縮小するので、極端に小さいファイルや大きいファイルでも使える状態で入ってきます。隣の×欄は、その上にさらに倍率をかけます。どちらも配置するときに効くので、ドラッグする前に設定しておいてください。

2. ビューにドラッグする

    モデルタブからサムネイルをどれかのビューにドラッグします。ポインターの下の面に置かれます。

    ![モデルタブから3Dビューにドラッグしたワイン樽。床の上に編集可能なメッシュとして置かれる](../assets/models/drag-model-into-view.gif)

ディスク上のどこにあるファイルでも、モデルツールバーの末尾にある**インポート…**を使えます。

### プロップとして { #as-a-prop }

1. ファイルを選ぶ

    *ファイル > インポート > モデルプロップ (.bbmodel, .glb)…*に進み、モデルを選びます。

    ![ファイルメニューでインポートが開き、モデルプロップ (.bbmodel, .glb)…にカーソルが合っている](../assets/models/file-import-model-prop.png)

2. インスペクターを確認する

    モデルは3Dカーソルの位置に`prop_model`エンティティとして置かれ、`model`キーに`res://`のパスが入ります。

    ![prop_modelエンティティのインスペクター。modelキーにres://models/polyhavenのパスが入っている](../assets/models/inspector-prop-model.png)

プロップは、Godotが読み込めるファイルを指している必要があります。プロジェクトの外のファイルを選ぶと、エディターが先に`res://models`へコピーするか尋ねます。

Blockbenchのモデルには、さらに2つの取り込み方があります。*ファイル > インポート > Blockbenchモデルをメッシュで…*と*Blockbenchモデルをブラシで…*です。ブラシとして取り込むと、すべてのキューブが1つのブラシになり、ファイル名のグループにまとめられます。

## 置いたメッシュのテクスチャ { #textures-of-a-placed-mesh }

編集可能なメッシュは、モデルの見た目を保ちます。テクスチャは、プロジェクトのテクスチャフォルダの`models/<name>`にコピーされます。`<name>`は、モデルタブでのモデルのパス、またはほかの場所から持ってきたモデルならファイル名です。メッシュを選ぶと、インスペクターに描画に使うマテリアルの一覧が表示されます。

![置いたメッシュのインスペクター。頂点は5966、マテリアルはmodels/polyhaven/containers/wine_barrel_01/tex0](../assets/models/inspector-mesh-materials.png)

ただの画像ではモデルと同じように描画されない場合は、Godotのマテリアルもプロジェクトのマテリアルフォルダに入ります。そのおかげで、切り抜きの葉、ピクセルアート、光る部分（glTFモデルのエミッションカラーとエミッションマップも含みます）が、Godotでもここと同じように描画されます。マテリアルを入れ替えるには、メッシュを選んだままマテリアルタブでマテリアルをクリックします。*編集 > 元に戻す*で元に戻せます。

配置でファイルが上書きされることはありません。同じモデルをもう一度置くと、テクスチャは再利用され、Godotで調整したマテリアルもそのまま残ります。別のモデルのテクスチャがすでにそのフォルダにある場合、たとえば`rock.glb`の隣にある`rock.bbmodel`のものなどは、新しいほうが`models/rock_2`のような番号付きフォルダに入ります。元に戻してもファイルはそのまま残ります。読み取り専用のプロジェクトなどでテクスチャを書き込めない場合は、メッシュはテクスチャなしで入ってきて、ステータスバーに理由が表示されます。

テクスチャはピクセルが同じかどうかで同一とみなされるので、別のプログラムで保存し直しただけのものも再利用されます。上から描き込んだ場合はどうなるでしょう。以前に置いたメッシュはあなたの版を保ち、次に置いたものは番号付きフォルダに新しいコピーと新しいマテリアルを得ます。以後の配置にもあなたの変更を反映させたいときは、マテリアルタブから自分のマテリアルをそれらに適用してください。

> [!NOTE]
> FuncGodotは、同じ名前のマテリアルファイルがないときにだけ、プロジェクトの`default_material`から面のマテリアルを作ります。置いたモデルの面にマテリアルファイルができている場合は、そのファイルで描画されるため、`default_material`に設定したカスタムシェーダーは届きません。変えたいときはGodotでそのファイルを編集してください。マテリアルの拡張子が`tres`でないプロジェクトにはマテリアルファイルができず、デフォルトマテリアルが使われます。

## サムネイルの詳細メニュー { #more-on-a-thumbnail }

サムネイルを右クリックすると、カーソル位置への配置、パスのコピー、ディスク上のファイルの表示ができます。パックにURLがあれば、*パックのページを開く*も出ます。

![wine_barrel_01のサムネイルの右クリックメニュー。カーソル位置に配置にカーソルが合っていて、続いてパスをコピー、ファイルマネージャーで表示、パックのページを開くが並ぶ](../assets/models/thumbnail-menu.png)

## パックのクレジット { #pack-credits }

無料のモデルパックは、たいていクレジット表記を求めます。モデルのフォルダ、またはその上のどのフォルダでも、`pack.json`を置いておくと（いちばん近いものが優先されます）、パネルがそのモデルのパック、作者、ライセンスを把握します。サムネイルにカーソルを合わせると確認できます。

![wine_barrel_01のサムネイルのツールチップ。パス、Pack: Poly Haven、作者、License: CC0、パックのURL、モデルのクレジットが表示されている](../assets/models/thumbnail-credit-tooltip.png)

```json
{
  "name": "Nature Kit",
  "short": "Nature",
  "author": "Some Artist",
  "license": "CC0",
  "url": "https://example.com/nature-kit",
  "credits": [{ "asset": "pine", "author": "Other Artist" }]
}
```

`short`は、スラッグにチェックが入っている間に各サムネイルに表示されるラベルで、なければ`name`が使われます。`credits`は、拡張子を除いたファイル名で対応づけて、個別のモデルの作者、ライセンス、URLを上書きします。`pack.json`のないフォルダは、いちばん上のフォルダの名前で一覧に並びます。
