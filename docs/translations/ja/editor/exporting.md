# Blenderなどの3Dツールにエクスポートする { #exporting-to-blender-and-other-3d-tools }

マップの見た目を、1つの3Dモデルファイルとして保存できます。ブラシ、メッシュ、地形、モデルが、テクスチャごと入ります。Blenderでレベルをレンダリングしたり、トレーラー用のショットを用意したり、ブロックアウトをアーティストに渡して、その上に最終的なメッシュを作ってもらったりするのに便利です。

> [!WARNING]
> エクスポートされるのはジオメトリとマテリアルだけです。エンティティのロジック、I/Oの配線、トリガー、スクリプト、ゲームプレイの動作は含まれず、このファイルをTrenchDotでマップとして開き直すことはできません。マップはあくまで`.tdm`なので、編集はそちらで続けてください。

## 手順 { #steps }

1. エクスポートを開く

    *ファイル > エクスポート > glTF Binary (.glb)、Blenderなど3Dツール用…*を選ぶか、コマンドパレット（Ctrl+Shift+PまたはF1）に「glTF」と入力します。

    ![エクスポートを開いてglTF Binary (.glb)、Blenderなど3Dツール用…にカーソルを合わせたファイルメニュー](../assets/exporting/menu-export.png)

2. 入れるものを選ぶ

    *3Dツール向けにエクスポート*ウィンドウが開きます。入れたいものにチェックを付けます。下の[オプション](#options)を参照してください。*プロップモデル*と*散布インスタンス*の横の数字は、それぞれがオブジェクトをいくつ追加するかを示します。上部で形式をOBJに切り替えることもできます。

    ![glTF Binaryを選び、マップ全体とプロップモデル（5）にチェックがあり、散布インスタンス（4081）にチェックがない、3Dツール向けにエクスポートウィンドウ](../assets/exporting/export-dialog.png)

3. 保存する

    **エクスポート…**をクリックして、ファイルの保存先を選びます。エクスポートは進行状況のウィンドウとともにバックグラウンドで動くので、編集を続けられます。**キャンセル**を押すと、何も書き込まずに止まります。終わると、ステータスバーに、出力したオブジェクト、マテリアル、三角形の数が表示されます。

4. Blenderで開く

    *File > Import > glTF 2.0 (.glb/.gltf)*を使って、ファイルを選びます。デフォルトのままで大丈夫で、インポーターがモデルを自動でZ上向きにします。

ファイルには、**エクスポート…**をクリックした時点のマップが入ります。未保存の変更は先に自動保存されます。ただし、*ファイル > 環境設定*で自動保存がオフのときは保存されません。プロジェクトに画像がないマテリアルの名前がステータスバーに表示された場合、そのマテリアルはテクスチャなしで出力されます。

## オプション { #options }

| オプション | 働き |
| --- | --- |
| マップ全体、選択のみ | すべてか、選択したオブジェクトだけです。どちらもレイヤーとグループの中に入ったままです |
| 非表示のレイヤーとオブジェクト | ビューで隠れているものも書き出します。オフなら、見えているものが出ます |
| プロップモデル | プロップなどのポイントエンティティが表示するモデルを、その位置、回転、スケールで書き出します |
| 散布インスタンス | [散布セット](scatter.md)のすべての木、岩、草の茂みを、それぞれ個別のオブジェクトにします。数千個で大きく開くのが遅いファイルになるので、デフォルトではオフです |
| ポイントエンティティを空のマーカーとして | モデルのない各ポイントエンティティの位置に、そのエンティティと同じ名前の空のオブジェクトを置きます。Blenderでライトやカメラを配置するときに便利です |
| 名前のないブラシを結合 | 名前を変えていないブラシを、レイヤー、グループ、エンティティごとに1つのオブジェクトにまとめるので、Blenderのアウトライナーが短く保たれます。名前を付けたブラシは別々のままです |

## エクスポートされるもの { #what-is-exported }

| マップ内 | ファイル内 |
| --- | --- |
| レイヤーとグループ | 同じ名前の空の親オブジェクトなので、アウトライナーの構成が引き継がれます |
| ブラシ | 1つずつのオブジェクトで、アウトライナーと同じ`brush12`か、付けた名前になります |
| ドアやリフトのようなブラシエンティティ | エンティティの名前が付いた親オブジェクトで、そのブラシをエディターで置かれている位置に持ちます |
| メッシュ、デカール | 1つずつのオブジェクト。デカールにはブレンドされた両面マテリアルが付きます |
| 地形 | 1つのオブジェクト。各三角形は、最も強くペイントされたレイヤーのテクスチャを取るので、ペイントしたブレンドは段になって見えます |
| プレハブのインスタンス | プレハブの中身が所定の位置に移され、インスタンスの名前が付いたオブジェクトの下に入ります |
| マテリアル | マテリアルごとに1つで、アルベドテクスチャと、あれば法線、ラフネス、メタリック、アンビエントオクルージョン、発光のマップが付きます。切り抜きや透けて見えるマテリアルはアルファを保ち、ピクセルアートはシャープなままです。組み込みのdev用の色は、グリッドのテクスチャとして出力されます |

Godotのビルドが描画しないものは、ファイルにも入りません。ツールテクスチャ（クリップ、スキップ、オリジン、スカイ、トリガー、nodraw、ヒント）の面、別のブラシに隠れた面、トリガーなどのボリュームエンティティ、*書き出しから除外*に設定されたレイヤーです。ライト、サウンド、スポーンポイント、スカイ、フォグもエクスポートされません。

互いの面を隠し合うのは、ファイルに入るオブジェクトだけです。そのため、*選択のみ*でエクスポートした柱は、床に接している底の面を保ちますし、*書き出しから除外*に設定したレイヤーが、隣のオブジェクトに穴を残すこともありません。

## 単位と軸 { #units-and-axes }

Godotの1メートルは、Blenderの1メートルです。マップの単位は、プロジェクトの1メートルあたりの単位数で割られます。マップの設定で変えていなければ32です。ファイルはGodotと同じY上向きで、glTFが想定する向きです。ブラシ、メッシュ、地形はそれぞれ、境界の中心に原点があり、モデルはモデルファイルの原点を保ちます。

## OBJを使うとき { #when-to-use-obj }

*ファイル > エクスポート > Wavefront OBJ（.obj）…*は、glTFを読めないツール向けです。3つのものを並べて書き出します。たとえば`level.obj`、マテリアルを入れた`level.mtl`、テクスチャのコピーを入れた`level_textures`フォルダです。移動するときはまとめておいてください。Blenderでは、*File > Import > Wavefront (.obj)*を使います。

OBJには親オブジェクトも、1つのメッシュをコピー同士で共有する方法もないので、すべてのオブジェクトがワールド空間でフラットに書き出され、散布インスタンスはそれぞれ完全なコピーになります。散布インスタンスにチェックを付けていると、合計が100万個の三角形になった時点でウィンドウが一度警告し、ファイルがどれだけ大きくなるかを表示します。OBJのエクスポートは、1000万個を超える三角形、つまり1ギガバイトを超えるファイルは受け付けません。マテリアルは、アルベド、法線、ラフネス、発光のテクスチャを保ちます。相手のツールが読めるなら、glTFのほうをおすすめします。

`.glb`ファイルには最大4GBまで入ります。glTFは、散布インスタンスがいくつそのモデルを表示していても、モデルを1回だけ書き出すので、そこに達するのはとても巨大なマップだけで、その場合は壊れたファイルを書かずに、エクスポートがそう伝えます。

## コマンドライン { #command-line }

`trenchdot --export-glb <map> <out.glb>`と`--export-obj <map> <out.obj>`は、ウィンドウを開かずにデフォルトのオプションでエクスポートします。マップのGodotプロジェクトは、そのフォルダから見つけられます。[コマンドライン](../command-line.md)を参照してください。

## MCP { #mcp }

`map_file {op: export_glb, path}`は`.glb`を書き出し、`map_file {op: export_obj, path}`は`.mtl`とテクスチャフォルダ付きの`.obj`を書き出します。どちらも、開いているマップを、保存済みかどうかにかかわらずそのまま使います。オプションはフラグで、`selection_only`、`hidden`、`scatter`、`models`（設定しなければtrue）、`markers`、`merge_brushes`です。結果には`objects`、`meshes`、`materials`、`images`、`triangles`、`bytes`、`missing_textures`が並びます。`run_action`は`export_glb`と`export_obj`を拒否します。メニューの項目がファイルダイアログを開くためです。
