# ライティングのベイク { #baking-lighting }

ベイクは、太陽、空、ランプ、光るマテリアルの光を、バウンスも含めて一度だけ計算し、ライトマップとしてマップの中に保存します。Godotは、その光を毎フレーム計算する代わりに、保存された光を描きます。やわらかいバウンス光、ランプからにじむ色、暗めの隅が、実行時のコストはほとんどなしで手に入ります。切り替えたり動かしたりしたいライトは、ベイクの隣でリアルタイムのままです。

![左はライトプレビューの部屋で、のっぺりしたグレーの中に、窓の下に縁のくっきりした日なたがある。右は同じ部屋をベイクしたあとで、暖かいランプの光、暗めの隅、やわらかい日なたがある](../assets/light-baking/lit-preview-and-baked.png)

ベイクの対象は静的なジオメトリで、ワールドブラシ、メッシュ、地形、ディスプレースメント、動かないブラシエンティティです。ドアやプラットフォームのように動くブラシエンティティ、トリガーボリューム、デカール、ツールテクスチャ、エクスポートから外したレイヤーは、ベイクで照らされることも、ベイクした影を落とすこともありません。

## マップをベイクする { #baking-a-map }

1. ライティングをベイクのウィンドウを開く

    *Godot > ライティングをベイク…*を選びます。

    ![Godotメニューで、ライティングをベイクにカーソルを重ね、ツールチップが出ているところ](../assets/light-baking/menu-bake-lighting.png)

2. 何が入るかを確かめる

    一番上の行が内容をまとめていて、たとえば「太陽、ライト1個、空、光るマテリアルを102個のサーフェスにベイクします」のように表示され、どのライトがリアルタイムのままかも書かれています。

    ![ライティングをベイクのウィンドウ。品質が中、テクセルサイズが16.0 u、影の柔らかさが0.30、CPUで実行](../assets/light-baking/bake-dialog.png)

3. 品質とテクセルサイズを選ぶ

    下の[オプション](#dialog-options)を参照してください。最初に見てみるだけなら、デフォルトで十分です。

4. **ベイク**をクリックする

    進行状況のウィンドウに段階が表示され、そのあいだも編集を続けられます。ベイク中に加えた変更は、ベイクには含まれません。**キャンセル**で止まり、マップは元のライティングのままです。

5. 結果を見る

    終わると3Dビューが**ベイクしたライティング**のシェーディングに切り替わり、ステータスバーに、かかった時間とライトマップの大きさが表示されます。

ベイクは`.tdm`の中に保存され、ベイクは1回のアンドゥで元に戻せます。同じウィンドウの**ベイクを削除**で捨てられ、Godotはマップをまたリアルタイムで照らします。

## ダイアログのオプション { #dialog-options }

| オプション | 働き |
| --- | --- |
| 品質 | トレーサーが使うレイとバウンスの数です。下の表を参照してください |
| テクセルサイズ | ライトマップの1テクセルが覆うマップユニットで、2から128、デフォルトは16（50cm）です。小さいほど鮮明で、時間がかかります |
| 影の柔らかさ | 0から1です。自前の`light_size`を持たないライトを広げて、影の縁をやわらかくします。0なら硬いままです |
| 実行環境 | CPU、GPU、CPU + GPUです。下を参照してください |

| 品質 | テクセルあたりのレイ | バウンス | ライトあたりのシャドウレイ | 使いどころ |
| --- | --- | --- | --- | --- |
| プレビュー | 32 | 1 | 4 | ライトの配置用です。ノイズは多いですが速いです |
| 中 | 96 | 2 | 8 | 普段の作業用で、デフォルトです |
| 高 | 192 | 3 | 12 | きれいな結果がほしいときです |
| 最終 | 384 | 4 | 16 | 出荷するビルド用です。大きなマップでは時間がかかります |

ライトマップは1辺が最大4096テクセルです。頼んだテクセルサイズではマップが収まらないときは、もっと粗いサイズでベイクされ、ステータスバーにそう表示されます。マップは、最後にベイクしたときのオプションを覚えています。

### CPU、GPU、またはその両方 { #cpu-gpu-or-both }

| 実行環境 | 選ぶとき |
| --- | --- |
| CPU | どのコアでも、いつでも動きます。安全なデフォルトです |
| GPU | マシンに専用のグラフィックスカードがあるときで、たいていはずっと速くなります |
| CPU + GPU | どちらも強いときです。カードとすべてのコアが1つのキューから仕事を取り、それぞれ追いつける分だけ取ります |

GPUが使えないとき、たとえば搭載されていない、ソフトウェアレンダラーである、マップがバッファに収まらないほど大きい、といった場合は、CPUがマップをベイクし、ステータスバーに理由が表示されます。GPUが途中で失敗したときは、残りをCPUが引き継ぎます。

## ベイクを見る { #looking-at-the-bake }

*表示 > シェーディング > ベイクしたライティング*でベイクを表示でき、マップにベイクがあれば、F4でシェーディングを切り替えるときにも含まれます。*表示 > シェーディング > ベイクビュー*で、何を表示するかを選びます。

![表示 > シェーディング > ベイクビューを開き、ベイクしたライト付きテクスチャにチェックが入り、ライトマップのみにカーソルが重なっている](../assets/light-baking/menu-baked-view.png)

| ベイクビュー | 表示するもの |
| --- | --- |
| ベイクしたライト付きテクスチャ | ライトマップで照らされたテクスチャで、Godotの表示に近いものです |
| ライトマップのみ | テクスチャなしの光だけで、バウンスやノイズを見極めるのに使います |
| 太陽シャドウマスク | 各場所に太陽がどれだけ届くかで、日なたは白です |
| アンビエントオクルージョン | 隅や物の下の暗さで、確認用だけです。Godotでは使われません |

![同じ部屋を4つのベイクビューで見たところ。左上がベイクしたライト付きテクスチャ、右上がライトマップのみ、左下が太陽シャドウマスク、右下がアンビエントオクルージョン](../assets/light-baking/baked-views.png)

## ライトのキー { #light-keys }

`light`と`light_spot`にはすべて`bake_mode`キーがあり、worldspawnには太陽用の`sun_bake_mode`があります。

| 値 | ベイクでの扱い | Godotでの扱い |
| --- | --- | --- |
| `auto` | `baked`と同じですが、`targetname`を持つライトや`start_on`が0のライトは、I/Oで切り替えられるのでリアルタイムのままです。太陽はいつもベイクされます | Static、またはDisabled |
| `baked` | 直接光とバウンス光、その影 | Staticで、ライトマップが担います |
| `bounce` | バウンス光だけ | Dynamicで、Godotが直接光とその影をリアルタイムで描きます |
| `realtime` | 除外されます | Disabledで、完全にリアルタイムです |

ランプの影を動くオブジェクトに合わせたいけれど、バウンスはそのまま部屋を満たしてほしいときは、`bounce`を使ってください。Godot自身の名前の`static`、`dynamic`、`disabled`も使えます。リアルタイムのライトは、[ライトプローブ](../godot/baked-lighting.md#light-probes)を通して動くオブジェクトも照らします。

`light_size`はランプの半径で、メートルです。ランプが大きいほど影がやわらかくなり、0ならウィンドウの影の柔らかさが代わりに使われます。`light_indirect_energy`はバウンス光を拡大縮小し、`omni_attenuation`、`spot_attenuation`、`spot_angle_attenuation`はフォールオフの形を決めます。Godotのライトには、すべて同じ名前のプロパティとして渡されるので、リアルタイムのライトはベイクと一致します。

## ベイクが古くなるとき { #when-a-bake-goes-out-of-date }

ベイクは、作られたときのジオメトリとライトを覚えています。静的なジオメトリを動かす、形を変える、追加する、削除する、あるいはライト、ライトプローブ、worldspawnの太陽と空のキー、使っているテクスチャやその設定を変えると、古くなります。すると、ライティングをベイクのウィンドウが、前回のベイク以降にマップが変更されたと警告します。

![ライティングをベイクのウィンドウ。黄色の行に「前回のベイク以降にマップが変更されました。ライティングを更新するには、もう一度ベイクしてください。」と出て、ベイクとベイクを削除のボタンがある](../assets/light-baking/bake-dialog-out-of-date.png)

もう一度ベイクするまで、変わった面は、エディターではライトプレビューを、Godotではマップの平均の光を表示し、そのほかの面はベイクした光のままです。ここでは、ベイクのあとで柱を動かしました。柱はライトプレビューで表示され、古い影が床に残っています。出荷する前に、もう一度ベイクしてください。

![柱を動かしたあとのベイク済みの部屋。柱は均一に照らされ、古いベイクの影が元あった場所に残っている](../assets/light-baking/bake-out-of-date.png)

## テクスチャ設定 { #texture-settings }

面を選んで、インスペクターの**テクスチャ設定**を開くと、そのテクスチャを使うすべての面の扱いを、マップ全体で設定できます。設定はマップと一緒に保存されます。

![面を1つ選び、テクスチャ設定を開いたインスペクター。ライトをベイクする、ベイクした影を落とす、ライトマップの精細度、繰り返し間隔、投影が並んでいる](../assets/light-baking/texture-settings.png)

| 設定 | 働き | 使いどころ |
| --- | --- | --- |
| ライトをベイクする | オフにすると、その面をライトマップから外し、Godotはマップの平均の光をその面に与えます | 空、水、近くで見る人がいない面 |
| ベイクした影を落とす | オフにすると、ベイクのときに光がその面を通り抜けます | ガラス、格子、薄いデカール |
| ライトマップの精細度 | これらの面のテクセルサイズに掛けます。1より小さいと鮮明に、1より大きいと容量の節約になります | 床ではくっきりした影、遠い天井ではぼやけた影 |
| 繰り返し間隔 | テクスチャのピクセルサイズの代わりに、1回の繰り返しが覆うマップユニットです | どこでもテクスチャを同じスケールにする |
| 投影 | ワールドにすると、各面のオフセット、スケール、回転を無視して、テクスチャが切れ目なくつながります | 壁紙、タイル、コンクリート |

> [!TIP]
> バックルーム風のマップなら、壁紙をワールド投影にして、繰り返しのサイズを一度だけ設定すれば、それで描いたどの壁も、テクスチャツールに触れなくてもそろいます。

2つのベイクのオプションがどちらもオフの面は、ベイクから完全に外れます。繰り返しのサイズと投影は、Godotでも適用されます。

## MCP { #mcp }

`bake_lighting`ツールは、ウィンドウと同じオプションの`quality`、`texel_size`、`softness`、`backend`（`cpu`、`gpu`、`hybrid`）でベイクし、`view`でベイクビューを切り替えます。ベイクが終わるまで待ち、ライトマップのサイズ、各種の数、使ったGPUまたは使えなかった理由、`out_of_date`を返します。`texture`ツールの`settings`オペレーションは、`material`、`bake`、`casts`、`texel_scale`、`size`（`null`でクリア）、`projection`（`face`か`world`）で、テクスチャ設定を読み書きします。[MCPサーバー](../mcp.md)を参照してください。

</div>
