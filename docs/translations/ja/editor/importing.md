# HammerとTrenchBroomのマップをインポートする { #importing-hammer-and-trenchbroom-maps }

HammerやTrenchBroomで作ったレベルがありますか。作り直さずに、そのまま持ってきましょう。*ファイル > インポート*は、Hammerの`.vmf`、またはTrenchBroom、Quake、Qodotの`.map`を、保存されていない新しいマップとして開きます（開いているマップに未保存の変更があるときは新しいタブで開きます）。それを`.tdm`として保存すれば、Godotは他のマップと同じように構築します。

## 手順 { #steps }

1. 先にGodotプロジェクトを開く

    変換されたテクスチャはプロジェクトのテクスチャフォルダに入るので、マップの対象プロジェクトを*Godot > Godotプロジェクトを開く…*で開きます。

2. マップをインポートする

    *ファイル > インポート*から*.vmf（Hammer）…*または*.map（TrenchBroom, Quake）…*を選び、続けてファイルを選びます。

    ![インポートを開いて.vmf（Hammer）…にカーソルを合わせたファイルメニュー。その下にテクスチャを変換とモデルのインポートが並んでいる](../assets/importing/file-import-menu.png)

3. テクスチャを変換する

    マップのテクスチャがマップの近くにあるときは、プロジェクトにないものについて、エディターが「マップのテクスチャを変換しますか？」と尋ねます。はいと答えてください。[テクスチャを変換する](importing-textures.md)を参照してください。

4. 問題タブを確認する

    左上の、アウトライナーと履歴の隣にある問題タブを開きます。プロジェクトにまだないマテリアルはすべて警告として表示され、そのマテリアルの面はチェッカー模様で描かれます。

    ![警告が2件ある問題タブ。マテリアル'castle/brick_wall'がプロジェクトにありません（12面）が表示され、3Dビューではその壁と階段が灰色のチェッカー模様で描かれている](../assets/importing/issues-missing-materials.png)

    面にはマテリアル名が残っているので、あとでテクスチャを追加すれば直ります。すべてのテクスチャがそろえば、その警告は消えます。

    ![テクスチャを変換したあとの同じマップ。問題タブには問題は見つかりませんと表示され、壁にはレンガのテクスチャが表示されている](../assets/importing/textures-converted.png)

5. 保存する

    *ファイル > 別名で保存…*を使って、プロジェクト内に`.tdm`として保存します。

> [!NOTE]
> 単位はそのまま保たれます。Sourceのマップは1メートルあたり約40ユニット、Quakeのマップは約32ユニットで作られているので、プロジェクトが別のスケールを使っていない限り、Sourceのマップはゲーム内より少し大きくなります。

## インポートで引き継がれるもの { #what-the-import-keeps }

| Hammer | TrenchDotでは |
| --- | --- |
| ツールマテリアル（`tools/toolsnodraw`、`toolsclip`、`toolsplayerclip`、`toolstrigger`、`toolsorigin`、...） | プロジェクトのスキップ、クリップ、オリジンのテクスチャと`special/trigger` |
| スカイの面 | プロジェクトのスカイテクスチャ。デフォルトは`special/sky` |
| ディスプレイスメント | 高さとブレンドアルファを持つディスプレイスメント |
| `func_instance` | インスタンスの中身を収めたグループで、所定の位置に移動されます。中の名前にはインスタンスのフィックスアップが適用され、`$`と`#`の置換が埋められ、`instance:name;Input`を宛先とするアウトプットは実際のエンティティにつながれます |
| ビジグループ | レイヤー |
| 非表示のオブジェクト | 非表示のノード |
| エンティティのキーとアウトプット | エンティティのプロパティとアウトプット |

TrenchBroomのレイヤーとグループはレイヤーとグループのままで、Quakeのツールテクスチャも同じ方法でプロジェクトのツールテクスチャになります。

必要なのが数個のブラシだけですか。TrenchBroomでコピーしてTrenchDotでCtrl+Vを押すと、同じように変換されて入ってきます。[プレハブライブラリ](prefab-library.md#pasting-from-trenchbroom)を参照してください。

スカイの面はGodotでは衝突しますが、何も描画しません。worldspawnのキー`sky_source`には元のテクスチャが残り、テクスチャを変換するとそれがプロシージャルなスカイに変わります。[テクスチャを変換する](importing-textures.md#skies)を参照してください。

## 既知の制限 { #known-limitations }

| 制限 | 対処 |
| --- | --- |
| `.vpk`や`.pak`アーカイブの中のテクスチャは読み込まれません | 先に展開してください。たとえばVPKEditが使えます |
| インスタンスは、マップの隣とその上のフォルダから探されます | ゲームの`maps`フォルダの構成を保ってください。見つからないインスタンスは`func_instance`エンティティのままになります |
| ValveとQuakeのエンティティクラスは新しいプロジェクトに定義がないので、エディターはそのキーを知りません | FGDに追加するか、自分のクラスに置き換えてください。問題タブに一覧が表示されます |
| Sourceのマテリアル機能の一部は省かれます。`$basetexture2`のブレンド、ディテールテクスチャ、環境マップ、プロキシです | Godotで設定してください |
| Quake 3のパッチ（曲面）とブラシプリミティブはスキップされます。ステータスバーに数が表示されます | メッシュとして作り直してください |
| 頂点が上下だけでなく横にも動いているディスプレイスメントは、ブレンドアルファのないメッシュになります | メッシュとして編集してください |
